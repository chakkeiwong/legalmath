# Expose the bounded procedure as a reusable product command

Execute after the frozen G0–G3 comparison closes; develop in isolation while its
live jobs run. The current procedure is a reusable Python component, but the
accepted run scripts bind specific development cases. A product user needs an
ordinary command accepting a source packet, declared question, facts and
qualifications, and producing the same reviewable hypotheses and uncertainty.

## Evidence contract and skeptical audit

Question: can the tested bounded interpretation procedure run on another supplied
interface without editing a development script? Comparator: `MethodRun` and the
fixed round-nine runner. This adds an entry point, not a new interpretation
method or evidence of legal accuracy. Preserve its two-reading request limit,
four-target critic batches, twenty-four-call task budget, complete source,
unknown/non-executable handling and retained criticisms.

Pass criteria: the command validates the supplied interface before any paid
dispatch, accepts only an existing explicitly named allowance, fixes a cumulative
reservation ceiling, retains success/failure and source hashes, and permits
resume only with identical inputs, method, provider route and code. Successful
resume spends no new call. Interrupted work requires an explicit recovery action;
no automatic replay of an uncertain dispatch. Elapsed-time and call accounting
must survive failures. The result retains uncertainty and cannot issue a release.

Vetoes: altered source/interface, method or route, changed allowance history,
missing task evidence, concurrent writing, unvalidated response or a Java/Python
mismatch. These block the affected operation. A model concern or non-executable
reading is a valid unresolved result and must not stop evidence collection or
become a fabricated answer. No hidden reference expression or expected scenario
is part of the product command's input.

The declared factual vocabulary is an explicit limitation: this command does not
prove that the vocabulary is complete, and the broader source inventory remains
a separate stage. The product already supports source acquisition and inventories;
do not silently pretend that selecting a clause automatically resolves all
external authorities or the bank's fact definitions.

## Implementation and checks

Add `legalmath assurance-interpret-issue` with a public-input file, output
directory, JDK path, existing allowance and method selection. Add an explicit
resume flag and recovery operation. Lock the run directory, bind all relevant
identities, preserve the first allowance checkpoint and use fixed per-run
ceilings. Public source data may contain quoted instructions; it is never shell
code or permission to execute commands.

Use a synthetic counted provider to exercise a complete invocation, byte-for-byte
resume, stale-input rejection, concurrency, interrupted dispatch and call-budget
preservation. Test ordinary CLI argument wiring. Then run the command on the
retained family-office clause whose negation and qualification were investigated
in round eight. This live invocation receives the public source and declared
issue, without earlier proposals, criticisms or reference expressions. Its
maximum is 24 calls from the existing 500-call grant. The question is whether the
ordinary command executes the complete method and retains outstanding uncertainty;
the run does not estimate legal accuracy or compare models. Full regression is
required after the shared discrepancy repair. Record exact commands and evidence.

No new provider allowance or production deployment is requested. A bank staging
adapter still needs the institution's real host interface, input evidence
contract, control registry and release roles. Those unavailable inputs are a
genuine boundary for institution deployment, not a reason to postpone this
locally implementable command.


## Isolated audit findings before installation

The first completed-resume implementation checked only the starting ledger
checkpoint. A targeted test changed a consumed call's timestamp and demonstrated
that this was insufficient when the start checkpoint was empty. The repair binds
the final allowance checkpoint, rechecks the retained method manifest and
revalidates every successful task receipt before returning a completed result.
No live provider calls were used for this diagnostic. The synthetic regression
also preserves the first failure, stale public input/code refusal, exclusive run
locking and explicit interruption recovery without a refunded reservation.

The subsequent source audit found two additional control defects. A question
stored on an individual executable reading did not necessarily enter the merged
concerns. Two incompatible programs could both receive supporting criticisms
without triggering reconsideration. Add candidate-level questions to the retained
concerns and use executed behavior groups when deciding whether another semantic
cycle is required. Where no executed comparison is supplied, distinct expressions
remain a conservative reason for reconsideration. Equivalent expressions may be
cleared as a behavioral disagreement only by the executed comparison; their
source questions remain independent reasons to retain uncertainty.

These changes amend the shared method and therefore require a new method version,
focused adverse tests and a full regression after installation. Preserve the
round-nine implementation before changing it, and report that study under its
actual frozen method. Test the missing-question and incompatible-reading cases
against that baseline first, then show that the repaired procedure actually
executes its reconsideration tasks even when every critic says supported. This
repair improves discrepancy propagation; it does not establish that a reading
matches the intended legal meaning.

The baseline diagnostic also exposed an incorrect acceptance expectation in a
paraphrase test: its authored reference retained two unresolved source questions.
The repaired scorer must abstain on that fixture. A separate, explicitly
question-free synthetic variant verifies the narrower paraphrase acceptance
behavior. Keep the authored reference unchanged. Validate timestamps, packet
structure, unique source-unit identifiers and the Java toolchain before any paid
call; malformed input or a missing toolchain should not consume the grant.

The reusable-method audit also found that rejected generation proposals were
retained only after its semantic cycle. A structurally repaired response could
change the proposed formula, leaving the earlier possible reading outside the
next reconsideration request. Retention alone is insufficient for this path.
Before deciding on semantic reconsideration, collect the rejected generation
history, make it a trigger, and supply its unchanged proposals and validation
errors to the reviser. Keep that history after revision. A targeted counted
provider test must demonstrate the old missed branch and the repaired execution;
neither the supervisor nor the validator may silently supply a different formula.

Check elapsed time again after the last local verification before marking a run
complete. A Java subprocess has its own bounded timeout and may finish after the
issue deadline, but its late result must not be accepted within that expired
budget. A simulated-clock test distinguishes deadline enforcement from model
quality without spending a live call.

## Executable phases and limits

H0 installs and tests the reviewed entry point and discrepancy repairs. H1 runs
the public clause through that entry point, capped at 24 further calls and one
hour, and checks its receipts and executed distinctions. H2 runs the full
regression under a 900-second command deadline and verifies preserved evidence.
The fixed supervisor refreshes the next phase after success. A failed phase
requires a recorded executed repair, fresh plan and current-source review before
retry; at most three phase attempts are allowed. A timed-out paid invocation is
recovered explicitly without restoring consumed calls. Successful run reuse must
use identical inputs and the command's authenticated resume path.

completed resume because only Python files entered the implementation hash. No
repository source or live evidence was changed during this test; it used a
controlled temporary package identity and a counted synthetic provider.

No interpretation method, provider request or Java computation changes, so this
repair needs focused boundary regression rather than another paid live run or
another full-suite repetition. Preserve the full H2 result under its actual
pre-H3 implementation and report H3 separately with its exact test count.
