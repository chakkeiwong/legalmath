This is a next-phase specification. The executed work is recorded separately in
`interpretation-round16/execution-result.md`. Start by verifying round 16's
delivery, preserving its external bound files and retaining the unchanged live

tested fixtures. The remaining central question is how to obtain supported
judgments and operational evidence for the bank's actual decisions, and measure
the error of those judgments without calling agreement truth.

## Audit and limits

S1 is locally executable without a larger allowance. S2 requires new authorized
calls or independently supplied judgments; elapsed time and this plan do not
authorize them. S3 and S5 can first inspect the already retained sources, but
must not manufacture missing authority. S4 can demonstrate a synthetic Java host
without claiming actual bank integration. S6 needs independently justified
reference evidence and a genuinely separate method/family; its absence is not
a reason to buy a comprehensive legal consultancy automatically.

The baseline comparator remains the unmodified prior behavior on the same
question and inputs. A lower number of NOT_ESTABLISHED labels, more agreements
or more test cases is explanatory, not the primary correctness criterion.
Three attempts per phase, immutable evidence and a fixed deadline remain the
repair discipline. A rejected interpretation triggers the next discriminating
repair; only corrupted evidence, invalid assumptions or an exhausted resource
required for that action stops the dependent work.
