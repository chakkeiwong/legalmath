## Implementation

Use pinned LlamaIndex Core 0.14.25 for splitting, context restoration and
hierarchical synthesis. Use a real local BM25 implementation, avoiding a new
embedding service. Isolate dependencies in `.venv-context`; record exact
versions. Keep custom code focused on source binding, legal coverage,
dependency selection, validation and finite dispatch.

1. Build an immutable source/requirement store from the actual product envelope.
   Preserve occurrence IDs for repeated text. Split with token-based overlap and
   exact character offsets, retaining the complete chunk population.
2. Prepare two complete reading passes over every source chunk. Keep each of
   the 46 obligations and 35 readings separately identifiable. Top-k retrieval
   cannot stand in for complete reading.
3. Retrieve small pieces and restore surrounding context using LlamaIndex's
   metadata-replacement operation. Materialize original text and locators.
   Compare against the same retrieval without expansion.
4. Add explicit source-reference/quotation bridges. Missing, ambiguous or
   oversized dependencies remain visible and block only affected conclusions.
   Test a remote exception, a remote definition and boundary-crossing text.
   Similarity alone cannot establish that every semantic dependency was found.
5. Expose the optional route through `scripts/legal_product_completion.py`.
   Validate per-piece model responses for coverage and quotation identity before
   later consumption. Independent requests continue after a failed piece.
6. Exercise LlamaIndex hierarchical synthesis with a bounded provider adapter.
   Retain source/obligation coverage separately from summaries, enforce progress
   and finite calls, and reject expansion that recreates the all-context input.
   A scripted hierarchy run establishes plumbing, not legal interpretation.
7. Prepare original-source qualification requests and conservative call, time
   and output limits. Actual findings must undergo source-backed interaction
   review before the route can be promoted or feed legal/tool-effect claims.

LangChain parent retrieval is an alternative, not another prerequisite.
RAPTOR/GraphRAG are later candidates if the simpler method misses distant
relationships. OpenAI File Search is an optional managed alternative requiring
an API/provider integration; the present tools-disabled wrapper does not expose
it. No cloud store or paid call is created by this package.

API inspection distinguish these explanations.
