## Evidence contract and intended product

Question: can an installed legalmath module capture an explicit supported file
inventory, verify its identity/currentness, run actual prospectus source and
downstream stages, and refuse stale or incomplete profiles without fallback?
Add legalmath.prospectus.native_profile, runnable with python -m, without editing
successor modules or extraction defaults. Expose capture, check, source,
construct, finish and verify commands. Every stage writes exclusive start/result
records, requires real predecessor products, has a120second deadline, and never
reuses failed or ambiguous output. No automatic rebind of supplied legal reading
or correction approvals: stale parent bindings continue to refuse.

Capture receives a reviewed explicit file/directory map. It copies regular
files using the existing snapshot API, retaining provenance, fixed environment,
file digests, supported runtime/method identities and a caller-pinned profile
digest. It never traverses host directories to guess dependency closure.
Validate all blob identities, source/method/runtime bindings and source request
requirements before source launch. Source selection uses SourceRuntime for every
native call and retains full streams/receipts; downstream stages call the real
service APIs. Verify checks actual answer, phase parents, delivered receipts and
profile identity. Restart requires a new explicit output location; no hidden
retry, cache reuse, source correction or automatic fallback.

Baseline comparators: native-binding006 ordinary2010 default/fresh/retained
products and accepted008 source-bound controls. New installed matrix:2010 fresh
and retained routes, each from original source through P1–P5 and actual answer,
complete equality with ordinary baseline including all36176 units and parent

Use a fresh offline virtual environment and wheel built from copied current src
plus pyproject. Confirm installed module paths are inside that environment and
exact source hashes match the wheel/source records.

Primary pass criterion: full installed product/answer and native receipt
preservation; profile missing/changed blob, wrong profile/manifest, changed
method, wrong request, unknown stage, duplicate stage, failed predecessor and
forged answer controls all refuse. Capture/check and actual source must use the
installed module. Unit checks are engineering controls, not promotion alone.
Missing installed-import proof, stale input, unchecked fallback or semantic
mismatch veto promotion. A failed candidate triggers specific attribution and
one reviewed changed repair; no unchanged run or reset campaign is authorized.
Corrupt original evidence, unresolved process state or exceeded bounds stops
dependent execution; continue independent authorized work.
