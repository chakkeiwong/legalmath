# Bounded recovery of answer and graph interfaces

This is the declared failure-guided recovery of the focused answer/tool trial,
not a new product direction. The first live trial reproduced exact-case-copy,
answer-quote and tool-key output failures. It also produced an invalid argument
graph: all eleven attacks violate the signed-proposition relation, two quotations
are invalid, and one conclusion's sign contradicts its explanation. Independent
eligible arms must finish before this recovery is admitted; old results, ledgers,
code and program versions remain unchanged.

The question is whether an explicit output interface and one diagnostic-guided
graph repair can produce source-reviewed matched answers with actual installed
tool feedback. The comparator is a fresh baseline using the same retained full
source, exact questions, five cases, four generated prose readings and reviewed
graph as every tool arm. The failed predecessor baseline is a regression control,
not this comparison's baseline. The original seven source obligations remain the
primary answer acceptance criteria.

## Repairs and dependencies

| Item | Needs success | Needs completion | Independent work and result |
|---|---|---|---|
| Interface repair and adversarial checks | None | Predecessor failures observed | Declare exact case strings and actual tool keys as schema enums; explain quote locations; reject missing, extra or mismatched rows |
| Graph repair design | None | Actual graph failure | Bind all original graph diagnostics and source; request corrected signed propositions, valid targets and source warrants; no mechanical invention of legal edges |
| Admission and resource review | Interface tests, reviewed runner | Predecessor trial and assessment | Register versioned recovery, exact rules and a ledger copying the final predecessor prefix |
| One graph repair | Admission | None | One counted fresh model response; explicit rejection does not block baseline or retrieval |
| Executor input review | None | Graph attempt | Validate source warrants, conclusion signs, P11/UT distinction and any proposed attacks; retain unformalized readings |
| Baseline, BM25, LegalRuleML, Logical English | Admission, retained readings | Executor input review | Four separate answer attempts; unsupported formalization is an explicit tool outcome |
| PyArg, Carneades, clingo | Valid reviewed graph | Executor input review | Three separate engine and answer attempts; one failure never cancels another |
| Combined arm | Valid reviewed graph and successful/unsupported computations | Executor input review | Separate candidate; it cannot erase any single-tool failure |
| Source review of each answer | That answer validates | None | One fresh review per answer; semantic rejection affects that answer only |
| Assessment and closeout | None | All arms attempted or blocked | Executor checks source reasoning, actual delivery and consideration, scope, ledger, and exact remaining blockers |

The graph is repaired once from the actual failed model graph and its complete
diagnostics, with the full source and retained readings. The model must not
connect two different propositions merely because their readings differ. A
rebuttal requires one signed proposition and its opposite; an undercut requires
the negative applicability of the targeted inference. The repair must distinguish
what the source says from what applies to a hypothetical client, and P11 from UT
Code 6.8. An empty or fully blocked graph may be valid but establishes no useful
argument-tool contribution. No invented Boolean formalization is required to
make LegalRuleML or Logical English run. Their target limitation is a result.

For answers, the provider schema enumerates the supplied case IDs and exact fact
strings, the seven obligation IDs and the actual delivered tool-check keys. With
no tool context, tool_account has maximum length zero. Instructions explicitly
require copied facts, a quote from main answer or case prose, and exactly one
account for each actual tool check. Validators still independently enforce pair
identity, coverage, quotes and conditional P11 applicability. A schema constraint
does not establish semantic preservation; the source review remains required.

## Evidence and resource contract

Primary pass criterion: actual answers preserve all seven source obligations and
five case distinctions under executor source inspection, with traceable treatment
of each actual tool result. Hard answer vetoes remain invented applicability,
missing P14 alternatives, wholesale incorporation, invented ownership facts,
trigger substituted for fulfillment and solver agreement treated as legal truth.
Only shared source corruption, invalid authority, changed bound inputs, exhausted
global limits or the original deadline veto continuation of independent work.

One graph response plus eight answers and eight reviews gives at most **17 new
calls**, with no automatic retry. Copy the exact final predecessor ledger prefix;
do not refund failed calls or reuse unused predecessor stages. The original 400
global ceiling and 12 October 2026 04:28:01 UTC deadline still apply. Each call
uses the same configured GPT-6.1 Sol route, 300-second limit, 200,000 input bytes
and 80,000 output bytes; devices are intentionally CPU only. Preflight checks the
actual repair request and the remaining worst-case clock before dispatch.

The four retained readings are a reviewed development input, not a complete
population. The two failed reader outputs remain excluded. All arms share those
limitations. Byte fit, output validation, engine agreement and latency are
explanatory diagnostics. With one stochastic response per arm, differences are
descriptive only; no ranking, default change, complete English interpretation,
P14/Gatecoin closure or client-compliance conclusion follows.

Results will be retained under artifacts/legal-mission-control/2026-10-12/
answer-tools-repair/ and the corresponding mission result note. The manifest
must bind code, plan, review, inputs, predecessor ledger and exact commands.
Install only narrow enumerated action rules; host installation and execution
remain separate actions. All local edits and offline verification are already
authorized by the user's standing permission.

## Skeptical review before implementation

PASS for a bounded implementation and offline verification. The wrong historical
baseline is excluded; copied-case fidelity is treated as engineering validity,
not legal quality. The new schema exposes constraints the predecessor imposed
only after generation. Complete graph diagnostics address the actual failed
interface, while executor review prevents a syntactic repair from laundering
incorrect legal reasoning. The matched arms share the same source, readings and
graph; unsupported or rejected inputs remain visible. The strongest alternative
explanation is general unreliability of this output model, not missing prompt
detail. One bounded recovery tests that explanation without indefinite repairs.
Passing tests is insufficient for live admission: review the concrete runner,
finished predecessor result, clock, command rules and immutable bindings first.
