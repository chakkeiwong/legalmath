# Assurance round 15: executable closure and retained uncertainty

This program implements the round-14 successor specification in
`docs/plans/assurance-after-round14.md`. The baseline is the accepted round-14
phase journal and delivery manifest. Its 765 passing tests and eleven source
reference scenarios establish engineering checks, not correct English.

The question is whether we can expose and narrow remaining source and execution
errors while preserving every unresolved alternative. The comparator is the
frozen round-14 source packet, eight original unencoded parents, 232 restored
claim/reading pairs, and the two generated 23EC52 policies. More agreement or
fewer open rows is not a promotion criterion.

## Evidence contract and assumptions

The required result is an exact disposition for every restored pair; actual
backend checks on the encoded children; retrieved, hashed public dependencies;
inspectable page regions for every PDF dispute; and counterexamples that detect
specified semantic mutations and rounding errors. The final report must
separate executed checks, rejected proposals, unavailable evidence, and pending
work. No automatic legal release is permitted.

The relevant failure modes are an omitted qualification hidden by routing, a
wrong extracted claim, a compiling child that loses its parent condition, a
missing incorporated document, an altered PDF number or exception, and an
incorrect boundary or asset classification reaching Java. Any invalid identity,
stale source, changed immutable result, or backend disagreement vetoes the
dependent result. Source disagreement triggers the remaining issue queue;
it does not invalidate the investigation method. A transport failure stops
further live calls, while independent deterministic work continues.

|---|---|---|---|
| 24 pairs per request | Bounded serialization to fit the actual remaining allowance | Oversized or malformed response; measure input bytes and require exact pair coverage | Convenience hypothesis |
| Every restored executable pair is scheduled | Round-14 exclusion challenge and successor S1 | Reusing historical CONTEXT labels would hide 48 rows; scheduling changes no source text or legal judgment | Required comparison universe |

Engineering conformance, source interpretation, and empirical accuracy remain
separate. Labels, counts, timings and mutation results are explanatory diagnostics.
No superiority, population error bound, independence, completeness of readings,
or review-cost saving follows from this run.

The rational extension represents intended exposure as n/d basis points. The
adapter parses an exact decimal percentage p, forms 100p as a Fraction, and
returns its integer numerator n and positive denominator d. Since d>0,
n/d >= 1000 if and only if n >= 1000d. The transformed RuleIR uses exact
integer scaling by 1000, avoiding division or rounding. This establishes the
representation identity under the existing supplied VA classification; it does
not establish that classification or that the historical circular governs a
current transaction.

## Resource and repair controls

The allowance had 487 reservations at the final pre-dispatch audit. Reservations
467–487 were already present; their outputs were not located in this round's
journal and receive no evidentiary credit here. The initial assertion that they
were another authorized execution was not verified. Their consumption is retained.
The full 487-call prefix is frozen; it cannot be edited or refunded. The user's
existing authorization is 500 total reservations. This program may therefore
use at most thirteen new reservations, including malformed outputs and failed
transports. A concurrently appended reservation reduces what remains.

The original proposal to leave four calls unused is dropped: it was an arbitrary
convenience, not a user restriction. The reviewed absolute ceiling remains 500.
Ten first-pass 24-pair batches leave at most three calls for repairs. A failure
may therefore leave an explicit pending queue; it may never shrink the universe.
Each structured request gets at most one serialization/evidence repair. A batch
still invalid may split once while capacity remains. A transport or resource
failure stops live dispatch immediately; the provider wrapper has no hidden
transport retry. The phase journal allows at most three attempts per phase,
twenty-one total, within six hours. No attempt is refunded or erased.

Before each phase, the master refreshes `next-phase-plan.json` from actual
predecessor results. After it, `repair-review.json` records dependent repairs.
`repair` reruns the same verified master, reusing completed immutable actions and
retrying failed actions only within the fixed limits. Completed live evidence
is cached by exact request/schema/settings and never described as a new vote.
A code change changes the phase binding; it cannot masquerade as a tested result.
A changed source requires a new investigation.

## Skeptical review verdict

Proceed after the focused fault tests. The review repaired a stale budget,
incorrect cross-packet batching, suppression of restored CONTEXT rows, missing
code bindings, a nonresumable allowance check, a repair command that merely
wrote a note, unconditional completion despite pending work, and reuse of
hard-coded phase-directory numbers. It also replaced queue-only PDF/source
work with actual inspectable packets and bounded public acquisition.

The plan could still pass while all readers share an overlooked condition.
The source-to-rule correspondence and the completeness of possible readings
remain its weakest evidence. That is why the next common-error study needs
separately justified references and another model family; the present run cannot
supply those by relabelling development fixtures. Missing external evidence
blocks that accuracy claim, not the deterministic repairs above.
