# Source-bound and larger-domain solver corpus

Revision 221 repaired an overbroad acceptance route: a finite-only certificate
cannot close the original G07/PACKAGE-05 larger-domain solver requirement.
This next same-task package asks whether the installed Z3 path computes the
declared Boolean consequences and carries them through actual construction,
clause and law products. Original source meaning and explanation minimality
remain separate open requirements.

## Evidence contract and research intent

Compare the current explicit Z3 route with an independent enumerator written
without importing production names/evaluate or the existing finite oracle.
Use every 24-by-3-by-4 retained BASF conditional formula/scenario pair, plus
predeclared synthetic formulas with 3, 12, 13 and 16 variables. The latter
sizes cross the actual finite-engine limit and require a working larger-domain
solver rather than a fallback that only reports DOMAIN_LIMIT. Include all/any,
contradiction/tautology, constrained equality/opposition, partial facts, missing
facts, explicit conflicts and inconsistent premises.

The primary criteria are exact status/decision agreement, valid complete
witnesses satisfying the formula, observations and every constraint, and
genuinely inconsistent named cores. A core need not be minimal: check its
members and independently establish that its represented premises have no
compatible world. Named-constraint anchors must validate against retained
source bytes. A small constrained comparison must also agree with production
finite evaluation when no constraints are present.

Exercise actual P1-P5 and final consumers on an explicitly synthetic source
for true, false, unknown, conflicting, correlated and inconsistent 13-variable
cases. Check all emitted solver evidence, not only the final status. Include
13-variable construction tautology and contradiction, law timing exclusion,
finite DOMAIN_LIMIT, stale source, tampered product and wrong-namespace controls.
Separately injected solver-unknown behavior proves the interface response only;
it is not evidence that a real timeout occurred. Check the 256/257-variable
boundary using declared expected outcomes without enumerating 2^256 worlds.

Repeat the same corpus using the already accepted exact installed wheel,
isolated imports and the existing read-only runtime. Verify all loaded
production paths and the complete package inventory. Preserve complete records
and require exact source/installed equality, except that no timing field enters
the compared evidence. Both environments must identify the actual Z3 version.

Wrong answers or witnesses, an invalid unsatisfiable core, missed corruption,
missing solver, wrong imports, source/method drift or resource overrun vetoes
the candidate. A semantic counterexample triggers a reviewed local-versus-package
diagnosis and repair. A failed candidate does not reject the research direction.
Test totals, latency and number of cases are explanatory only. Passing does
not prove legal interpretation, exhaustive alternatives, minimal explanations,
unbounded solver correctness, new default readiness or whole-build completion.

## Assumption audit and pre-mortem

The 24 BASF scenarios are exposed development readings; their formulas remain
conditional and no candidate is selected. Synthetic Boolean problems establish
software behavior, not legal facts. Source-bound use checks anchor preservation,
not the authenticity or sufficiency of a legal interpretation. The direct
oracle has a 16-variable exhaustive ceiling, chosen to make complete enumeration
tractable; larger boundary controls are explicitly a different evidence class.

The installed runtime already contains Z3 4.16.0.0. Reuse is a same-host
convenience with explicit import/version hashes, not a portability test. The
production timeout remains 1000 ms per check and random_seed=0; no performance
ranking or general timeout success is claimed. Core identity may vary between
solver versions, so validity is the substantive criterion. This exact same
version run additionally compares full retained records to detect packaging drift.

The run could pass misleadingly if the oracle copied the solver's implementation,
only the 12-variable branch ran, or the installed runtime imported the checkout.
Separate recursive evaluation, explicit 13/16-variable receipts, altered-answer
controls, package identity and loaded-module checks address those risks. A
deliberately wrong status/witness/core and permissive verifier must fail the
checker before the evidence is considered.

Audit verdict: PASS for this partial engineering/package evaluation. The
baseline and supported question are explicit, comparison uses identical inputs,
proxy metrics cannot promote, and later repairs remain available only through
a new reviewed same-task revision. Do not edit shared production for this
corpus. Preserve the 450-file wheel and five current installed component criteria.

and runner. Preparation is bounded to 60 seconds and 2 MiB. Propose one sixth
