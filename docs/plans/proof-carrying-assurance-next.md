# Next evidence after the executed dossier integration

This is a successor specification, not authority to spend a new model allowance
or deploy a rule. Start from the accepted manifests named by
`artifacts/proof-carrying-assurance/verified-execution-v3/final-report.json`.
Do not promote the preserved v1 attempts or an interrupted suite. The current
500-call ledger is exhausted; no further provider invocation is authorized by
this document.

## Question and baseline

The next question is whether source-driven investigation finds consequential
alternatives in sources not used to construct the integration fixtures, and
whether a small formal checker can validate declared translation obligations.
The baseline is the current source/search/criticism pipeline plus the new
file-bound dossier. Five archived readings and agreement between compiled
backends are not a legal reference answer.

Maintain three ledgers: engineering behavior; formal propositions under stated
semantics; and interpretation support from authoritative sources. A new source
edition, fact meaning or legal priority must create new identities. Never patch
an accepted historical dossier to make its question disappear.

## Ordered work and acceptance

1. **Close available source dependencies first.** Inspect the existing authority
   catalog and retained FAQ/Code editions from later rounds. The old replay's
   missing-FAQ finding is about its packet, not a claim that the whole project
   lacks an FAQ. Assemble a new packet with applicable edition evidence,
   explicit missing-reference dispositions and exact source anchors. Reaudit
   extraction and retain a side-by-side packet difference. Acceptance is source
   integrity/closure accounting; it is not settlement of the legal question.

2. **Register a narrow proof-certificate profile.** Specify the exact shared
   interpretation/RuleIR semantics, including unknown, conflict, out-of-scope,
   exact arithmetic and time. Choose one proposition such as preservation of a
   supported Boolean lowering. Implement certificate production and a bounded
   independent checker; test false statements, omitted premises, different
   input hashes, unsupported constructs and checker failure. PROVED remains
   rejected until the registered checker succeeds on the exact target. A Lean
   theorem about an abstract interpreter does not by itself prove compiled Java
   behavior; that correspondence needs its own formal statement/evidence.

3. **Prepare prospective source tasks before seeing model answers.** Freeze
   source/date selection, questions, output meanings, method budgets and expected
   unsupported-language paths. Use new publications as they arrive, or label an
   earlier unseen set as retrospective held-out evidence. Do not select only
   circulars already expressible in the grammar. Retain every failed or
   unencoded task in the denominator.

4. **Execute fresh breadth and bounded investigation after renewed authorization.**
   Use the existing source-first normative, controlled-language and adversarial
   roles in separate contexts; retain all meaning-changing alternatives before
   search prioritization. Reevaluate criticism, pair comparability and concrete
   witnesses through the dossier. A possible first budget is four questions,
   three initial roles and at most fifteen further calls per question: at most
   72 provider invocations in total, including repairs. This is a proposed
   ceiling, not current permission. A timeout consumes an invocation; retries
   cannot reset the shared ledger. Required breadth missing at the ceiling
   yields an incomplete report, not consensus.

5. **Measure consequential omissions with an independent reference.** Begin with
   the source's own worked examples and applicable official FAQ answers. For
   disputes those do not settle, obtain narrowly scoped in-house policy/legal
   answers to the actual separating cases. External consultancy is a last
   resort for remaining material questions, not a default review of every
   output. Reference creators must not merely approve the model's answer list.
   Compare single-reader and ensemble paths at equal budgets; record unknown
   reference answers separately. With few circulars, report case evidence and
   intervals where justified, without claiming statistical superiority.

6. **Re-run after a later source or method change.** New facts, source text,
   applicability and checker versions invalidate the corresponding accepted
   result. Demonstrate that a formerly clean case becomes unresolved when a new
   exception or authority appears. The generated Java must remain associated
   with its own old source version; no silent update of historical decisions.

Every phase needs its own exact manifest, fixed commands, acceptance criteria,
repair ceiling and refreshed successor. The next agent should review this
specification against the then-current merged repository before implementing
it. Stop only for invalid evidence, an unsafe execution boundary, fixed budget
exhaustion or a material decision requiring the bank; preserve candidate failure
as evidence for the next repair when those vetoes have not fired.

## Evidence limits

The strongest alternative explanation for a clean ensemble remains a common
missed source qualification. Better source coverage, explicit adversarial
alternatives and independent formal execution reduce particular failure modes;
they do not establish universal legal correctness. A false clean result on an
independently resolved, consequential case vetoes promotion. Method counts,
search scores and old-regression accuracy cannot override it.
