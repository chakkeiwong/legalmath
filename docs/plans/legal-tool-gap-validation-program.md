## Question and evidence contract

Do selected external tools help the actual interpretation workflow identify,
preserve, or resolve the missing premises behind the original 46 obligations?
An engine returning a result is an engineering observation. A legal gap closes
only when the exact original question has a source-supported answer, its factual
and applicability premises are established, and rival interpretations and
contrary sources have received substantive review.

Freeze all 46 original obligation identities and their existing missing premises,
all 35 retained readings (including the 32 unformalized ones), the four original
development questions, the 60-unit retained corpus, the previous final report,
and the current dirty product implementation. A candidate must not inherit a
different source set, hidden legal answer, model route, or question.

| Role | Criterion |
|---|---|
| Primary engineering criterion | Actual external-tool calls are integrated with retained product inputs/outputs; reference identity, alternatives, uncertainty and source links survive; adversarial corruptions are detected. |
| Primary applicability criterion | A tool's contribution is traced to a named original missing premise, with input, output, limitation and next required evidence. Distinguish detecting an error, organizing evidence, conditional computation and resolving the premise. |
| Closure criterion | Source-supported resolution of the original obligation plus established applicability/factual premises and substantive review. No closure through a shorter or different question. |
| Promotion veto | Unsupported source span, missing alternative, silent priority, invented fact/standard, unknown treated as false, duty trigger treated as fulfillment, graph acceptance treated as legal truth, or missing required product evidence. |
| Continuation veto | Changed frozen inputs/method without a recorded revision, corrupted journal, unbounded command, unauthorized scope, exhausted budget, or a harness incapable of producing interpretable evidence. |
| Repair trigger | Reproducible transport, adapter, schema, or product integration defect. Preserve the failure and its cause; record the repair before retrying. |
| Explanatory only | Rank, timing, test count, number of arguments, XML validity, model agreement, and observed answer differences. |
| Nonconclusions | General English understanding, a legal accuracy rate, current-law completeness, client compliance, stochastic superiority, or production-default readiness. |

Failure of a tool blocks that tool's promotion. A provider outage blocks live
comparisons but does not stop independent offline tests. A valid refusal to
resolve missing client facts is an appropriate boundary, not a tool failure.

## Concrete phases and refresh

G0 freezes the preceding inputs and maps every obligation and reading to its
gap type, applicable tools, test, and closure requirements. No record may silently
drop out. The manifest records the Git commit and hashes of uncommitted source.

G1 runs all locally available applicable engines on product-derived records:

- PyArg and Carneades: compare actual retained argument graphs with the local
  declared semantics; remove/add attacks and retain contrary/unknown premises.
  Judge graph preservation separately from source-to-argument construction.
- LegalRuleML: encode the supported finite rule profile with native rule/source
  elements, validate using the official schema, decode and compare relations,
  conditions and sources. Test deleted/swapped conditions and source links.
  Preserve unsupported readings explicitly; opaque JSON inside XML is not a
  semantic roundtrip.
- Logical English: reproduce the failing control, compare with the pinned
  author's example, inspect the declaration parser, and make at most a scoped
  local-copy adapter/runtime repair. Positive, malformed and changed-trigger
  controls must pass before use; source-language equivalence remains separate.
- BM25: compare lexical overlap and retained whole-unit baselines with passage
  retrieval over the identical corpus. Preserve character offsets. Evaluate
  decisive passages from the predeclared source review and report omissions;
  these are development annotations, not held-out legal labels.
  Because retained sources normalize newlines, use exact contiguous windows of
  at most 1,000 characters with 250-character overlap adjusted to whitespace.
  This convenience choice is a hypothesis, not a tuned default. Targets are
  actual decisive clauses reviewed before freezing, never document headers.
- eyecite: reproduce HK/UK/US controls and record target coverage and explicit
  unresolved citations. An extraction miss cannot become a resolved authority.
- Case factors: use the existing sourced Gatecoin distinctions through the
  product's precedent functions; test absent consent, changed terms, different
  relationships and unverified later treatment. This is conceptual reuse of
  HYPO/CATO/AGATHA, not an original-engine deployment.
- SARA-IE, CLERC, MAPIE, Tweety/s(CASP), KeY and LangGraph: reassess the precise
  prerequisite or overlap against a named gap. Record a reasoned non-use where
  no qualified target protocol, licence, calibration data or distinct question
  exists. Do not install an unrelated tool to inflate integration counts.

G2 tests the inherited provider route with a tiny structured response, a small
source question, and a product-size structured request. Each reservation counts,
including a failure. A failed large request with successful smaller controls
triggers bounded transport/input investigation. Two failed tiny probes stop
further live dispatch on that route. Provider failure never fabricates an answer.

G3 compares four arms on each original development question: unchanged source
baseline, retrieval only, structured tool context only, and combined context.
All arms receive the same original source and substantive candidate material;
tool arms add only transformations and explicit computation. Two repetitions,
reversed order on the second, give 32 direct calls. No statistical ranking is
claimed from this small development matrix. Apply source-span checks and inspect
answers substantively; automated string checks alone cannot establish entailment.

Run actual CompleteInvestigation baseline and combined-tool arms, capped at 24
reservations per arm. Preserve every stage reached, rejected output and dossier.
Tools process the live product records where supported, with diagnostics returned
to the next model stage and a final source/alternative-preservation check. Replay
retained records is an integration control, never a substitute for these live
arms. If any planned test is unavailable, label it untested and keep the program's
overall objective incomplete.

G4 produces a tool-by-gap evidence matrix for all 46 obligations and 35 readings,
explicitly separating checked integration, failed controls, untested benefit,
detected defects, conditional results and source-supported closures. Review every
candidate closure and critical source claim. Record engineering decisions,
inference status, strongest alternative explanation and next discriminating work.
The final status is COMPLETE only when the declared coverage and product criteria
are met; an exhausted run is INCOMPLETE_WITH_EVIDENCE. No automatic successor.

Before each phase, write its predecessor hashes, actual findings, remaining
budget, reviewed action, and any prerequisite failures. A failed attempt stays
immutable. A repaired method receives a new method hash and repair record.
Restart uses cached accepted results and never repeats a counted model request
without an explicit retained retry decision.

## Defaults, budgets and assumptions

| Choice and provenance | Justification/status | Failure mode and early check |
|---|---|---|
| Prior 60-unit corpus and original questions | Continuity baseline | Missing decisive source; preserve source references and review omissions. |
| Current dirty product code | Actual local product under test | Git hash alone cannot reproduce it; freeze content hashes and copies before use. |
| Existing configured provider/model | Same-route comparison baseline | Authentication/transport/model failure; tiny structured probe before large requests. |
| Two direct repetitions | Bounded descriptive diagnostic | Correlated outputs and small sample; no superiority claim or default promotion. |
| BM25 defaults and top eight | Existing baseline, not tuned optimum | Mixed text lengths; exact-source relevance controls and passage ablation. |
| Explicit grounded/preferred semantics | Prior matched computational target | Authored premises may be wrong; attack/source mutation tests and legal review. |
| Limited rule/controlled-language profile | Optional integration hypothesis | Lossy encoding; reject unsupported constructs and compare decoded terms. |
| Synthetic fact perturbations | Boundary tests only | Artificial facts mistaken for client facts; labelled fixtures, no actual closure. |

12 reserved repairs); 12 recorded implementation/transport repairs; 24 hours

All runs are CPU only with CUDA_VISIBLE_DEVICES=-1. No GPU, training, system
package installation or production default change. Existing pinned local tools
are reused; no new tool download is planned. No model/provider substitution.
