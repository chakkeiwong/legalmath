## Question and evidence contract

Can a supported OCR/annotation worker sequence recover after missing or
changed inputs with the same result as a clean recomputation, while an
undeclared native read is denied, explicitly observed and bound, or continues
to veto reuse?

The exact comparators are the retained scan/scan_de inputs, the current authored
annotation control, the existing executor recovery suite and the already
reproduced undeclared-read test. Preserve their bytes and actual old limits.
Use only newly created isolated copies for mutations and deletions.

| Role | Criterion |
|---|---|
| Primary recovery pass | Actual worker/controller results after each declared mutation match a separate clean recomputation, including exact errors and restoration |
| Primary read-boundary pass | A deliberately undeclared input affects no certified reusable result; denial or tracing is evidenced on actual subprocess/child-process reads |
| Promotion veto | Stale output reused, changed/missing model accepted, lost page, lost authored relation, incomplete trace treated as complete, or a source escape admitted |
| Continuation veto | Corrupted comparator, unknown imported runtime, unexplained nondeterminism, changed bound method, missing required diagnostic or exhausted resource bound |
| Repair trigger | A reproduced local dependency, adapter or recovery failure; retain one bounded attempt and review its smallest repair |
| Explanatory | Runtime, text length, file counts, trace counts and number of completed tests |

Passing this work does not establish OCR quality on real multilingual tables,
legal correctness of an annotation, cross-host portability, host security or
general confinement of arbitrary applications. No package limitation follows
from a sandbox-only failure. Existing historical sources and receipts remain
unchanged.
