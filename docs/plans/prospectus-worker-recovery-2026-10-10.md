## Reproduced baseline and code findings

The existing R6 test `test_native_unrecorded_read_prohibits_reuse` launches a
real Python subprocess that reads a file omitted from `inputs`. The read
succeeds, `ReadContext.current` checks only declared records, and
`ReadContext.reusable` refuses reuse for every native invocation. This is an
explicit conservative boundary; it is not OS confinement. The earlier
controller correctly calls `reusable`, while the closure phase receipts
describe declared-method assurance. Do not weaken either statement merely
because a worker succeeds.

`test_real_executor_sequences_match_clean_recomputation` already mutates
source, holdings, calendar and receipts through the actual closure executor.
It uses synthetic full-term calculations. It does not yet exercise real OCR
model deletion, worker failure, corrected extraction or annotation recovery.
The OCR worker binds its PyMuPDF distribution, interpreter, worker and language
model hashes but declares that native reads remain unconfined. The scan path
runs OCR again for current assessment; frozen replay retains historical inputs.

Code inspection also identifies a concrete admission question: `scan` bounds
the tessdata directory once, then opens `<language>.traineddata` beneath it.
A model-file symlink can potentially resolve outside that directory. This is
not yet reproduced here. A targeted isolated fixture must establish its actual
behavior before any repair or claim about it. `bound_path` and all existing
root restrictions remain mandatory.

Both `strace` and `bwrap` are available on this host. Availability is not proof
that nested namespaces or tracing are permitted, nor that these tools cover
the supported workers. A minimal fixture must test the actual environment.
If sandbox restrictions prevent that fixture, use the required trusted-command
approval mechanism; do not infer a host/package defect or switch tools to
bypass the restriction.

## Question and evidence contract

Can a supported OCR/annotation worker sequence recover after missing or
changed inputs with the same result as a clean recomputation, while an
undeclared native read is denied, explicitly observed and bound, or continues
to veto reuse?

The exact comparators are the retained scan/scan_de inputs, the current authored
annotation control, the existing executor recovery suite and the already
reproduced undeclared-read test. Preserve their bytes and actual old limits.
Use only newly created isolated copies for mutations and deletions.

| Role | Criterion |
|---|---|
| Primary recovery pass | Actual worker/controller results after each declared mutation match a separate clean recomputation, including exact errors and restoration |
| Primary read-boundary pass | A deliberately undeclared input affects no certified reusable result; denial or tracing is evidenced on actual subprocess/child-process reads |
| Promotion veto | Stale output reused, changed/missing model accepted, lost page, lost authored relation, incomplete trace treated as complete, or a source escape admitted |
| Continuation veto | Corrupted comparator, unknown imported runtime, unexplained nondeterminism, changed bound method, missing required diagnostic or exhausted resource bound |
| Repair trigger | A reproduced local dependency, adapter or recovery failure; retain one bounded attempt and review its smallest repair |
| Explanatory | Runtime, text length, file counts, trace counts and number of completed tests |

Passing this work does not establish OCR quality on real multilingual tables,
legal correctness of an annotation, cross-host portability, host security or
general confinement of arbitrary applications. No package limitation follows
from a sandbox-only failure. Existing historical sources and receipts remain
unchanged.

   A runtime import check intentionally hides GPU devices before imports.

   Check expected success/rejection before launching OCR. If a source escape is

   Record complete page inventory, words, image identities, runtime and product

   path, corrupt only the copied extraction/annotation, and restore from the
   protected copies. Use fresh result directories for every step. Compare
   against clean recomputation after each supported change; full products and
   source identities are primary, phrase recognition alone is insufficient.
4. Extend the actual executor sequence to extraction and annotation inputs.
   A changed model, missing resource, stale correction map or changed relation
   must invalidate affected results. A restored resource may permit a newly
   recorded attempt; it must not conceal the earlier failure. Keep a finite
   deterministic sequence before any generated sequences.
5. Exercise the supported native-read mechanism on a deliberately tiny worker:
   declared read, undeclared read, child-process read, symlink and changed-file
   case. Prefer a fixed worker wrapper with explicit paths and no network.
   A trace that omits children, failed lookup dependencies or runtime reads
   cannot justify reuse. If complete binding is not shown, retain the current
   reuse veto and record the exact residual; do not replace it with a claim.
6. Apply the demonstrated mechanism to one real supported OCR/annotation worker
   before claiming integration. Retain actual command, host/tool versions,
   filesystem assumptions, observed/denied reads and downstream result. Update
   R6 attribution and run affected phase/remaining regression checks with exact
   coverage. A second host remains an explicit external requirement.

## Defaults, budgets and review

Use the currently pinned CPU runtime and retained model bytes; do not install
packages or silently alter environment versions. Existing scan settings are
300 DPI, two declared pages and explicit English/German profiles. These are
recovery baselines, not an OCR-quality recommendation. Their earliest failure
checks are exact import identities, model hashes and full page inventory.

Allow 30 seconds for the path/permission probe, 300 seconds for a single OCR
worker invocation and 900 seconds for the first finite recovery sequence,
subject to reviewing a measured successful baseline first. Cap new retained
evidence at 100 MB with an explicit metadata reserve. Trace output has its own
10-MB cap; overflow vetoes trace completeness. Subsequent expanded runs require
measured scheduling review, not an inherited limit. No live browser/model API
calls or GPU work are planned.

Pre-mortem: two cached or identically broken results might agree. Record actual
fresh worker launches, isolate restored and clean computations, inspect page
inventory and critical authored relations, and keep a known adverse control.
A trace may appear complete while missing a native child; use a child read
whose omission must be detected. A restricted sandbox may masquerade as a
package failure; recheck the minimal authorized command in the trusted context.

Skeptical design audit: PASS with execution admission pending. This sequence
uses already reproduced gaps, separates a new path hypothesis from evidence,
and requires actual worker effects rather than count-based completion. It
preserves the conservative native reuse veto unless a stronger boundary is
demonstrated. Missing a second host blocks portability claims, not the local
recovery and admission checks. The next task is the smallest admitted path
diagnostic, following completion of the coupon repair.
