# Rebuild phase products from explicit inputs

## Problem and research intent

The current consume command accepts pinned conditional profiles. The fresh
assess command builds P1-P5 in one call, omits separately retained interpretation,
law and financial inputs, and has no way to checkpoint their construction.
For BASF the original request lacks the later governing, incorporation,
statutory and definition inputs retained in P3. Simply passing the old profiles
to assess would neither preserve their baseline nor establish fresh support.

The engineering question is whether a pinned input recipe can reconstruct
P1-P5 from the original PDFs and supplied phase inputs through public commands,
with one bounded phase per invocation. A successful exact reconstruction permits
reuse of existing profile pins. Changed products require new reviewed profiles;
this program must never rewrite profile hashes to conceal a changed premise.

## Proposed sequence

1. Finish and record coverage054. Prepare a recipe referencing the exact
   original request, interpretation input, law input/cases and financial
   input/cases. Keep supplied inputs distinct from regenerated products.
2. Add a public prepare command for P1-P5. Require the recipe byte hash, pinned
   parent manifest for every later stage, exact prior stages and a new output
   directory. Every stage uses the existing source, construction, interpretation,
   law or financial implementation. No extraction is replaced by saved P1.
3. Test an actual small source through all five stages and the installed CLI,
   including phase input forwarding, changed recipe, source, parents and missing
   stages. Refuse path escape and overwriting evidence.
4. Run BASF regeneration in separate source, construction, interpretation and
   downstream calls. Compare each full product with CLI311 before promoting
   reuse. Source drift stops reuse; retain the actual difference for a reviewed
   source-specific repair. Test totals cannot substitute for those comparisons.
5. Retain the recipe, command evidence and output identities, then record and
   refresh the original authority. Only if complete products match may the
   current pinned profiles be used unchanged. Novel-source profile preparation
   and automatic interpretation remain separate unfinished work.

## Skeptical audit and assumptions

Audit of the initial idea found two flaws: the original request does not contain
all later phase inputs, and a monolithic run would exceed the existing per-stage
bound. The revised design exposes the existing phase boundaries, forwards each
input explicitly and retains the original request identity. It does not add a
second work-selection controller. Existing source_product and phase functions
are the baseline, not a new implementation of interpretation.

Exact reproducibility is a hypothesis about retained source bytes and the
installed extraction runtime. The earliest discriminating check is complete P1
equality after real extraction. Native executable metadata and source occurrence
identity are included; a text-only match cannot promote a different graph.
The proposed recipe and product size caps must be justified from measured input
sizes before admission. Input hashes prove integrity, not legal correctness.
All current client/adviser/CDM/portability decisions remain in force.

Primary criterion: real phase command outputs equal direct public functions on
a small source, followed by complete original-source BASF equality. Vetoes:
lost phase input, copied derivative passed off as extraction, silent rehashing,
changed source extent, baseline drift, output overwrite or installed mismatch.
Explanatory diagnostics: runtime, file sizes and test counts. No claims of source
recall, legal completeness or arbitrary new-prospectus profile support follow.

Before admission, record the forecast using coverage054 actual cumulative costs.
Existing cumulative bounds must not be silently reset. Any necessary increase
requires an explicit reviewed revision with the same prior costs and scope.
Keep per-stage limits and one-second command yields. A candidate failure is
recorded and may trigger one changed repair; it does not authorize unchanged
retries or abandoning independent source work.

## Reviewed implementation choices

Measured CLI311 JSON sizes are 17.8 MB for the original request, 3.1 MB for
separate interpretation inputs, and 65.8/34.0/52.9 MB for P1/P2/P3. Use a 64-MiB
phase-input cap, 128-MiB product cap and 64-KiB recipe/manifest cap. These are
explicit implementation bounds for this trial, not legal scope criteria. Tests
exercise refusal at the bound using a reduced test cap; larger future inputs
need a reviewed size revision rather than silent truncation.

The command accepts all five named recipe inputs, including explicit null law
and financial inputs with their case lists. Later stages require every earlier
stage and verify complete parent seals and links. Source bytes are checked again
at each stage. Refuse existing output directories; any failed stage leaves its
own incomplete directory as evidence and is resumed only through a new reviewed
attempt. Exact inputs and output manifests are relative to the declared root.
This is ordinary evidence integrity, not a host sandbox or a security boundary.

Tests compare every small-source product with the existing direct functions,
exercise changed sources/recipes/parent links and preserve old CLI parsing.
The isolated installed package then prepares the real BASF P1-P5 sequentially
from the retained original PDFs and explicit inputs. Each complete product must
equal its previous CLI311 product. Finally the installed consume command uses
that regenerated manifest and all existing profiles without changing any pin;
its full answer must equal coverage054. This is a substantive reproducibility
check, not a new default or proof for arbitrary unseen prospectuses.

Forecast at most 1100 new measured seconds and 350 MiB, including a retained
17.8-MB request, 3.1-MB interpretation input, approximately153-MB regenerated
products and isolated package. Retain coverage054's actual cumulative costs and
explicitly revise the cumulative026 ceiling from10800 to12600 seconds and from
1536 to2048 MiB, with the same4-MiB reserve. This expansion pays for retained real
regeneration rather than repeating saved-answer tests. Keep every prior attempt
and unknown manual time; same-task admission54 becomes55. Installed preparation
calls remain separate and bounded; no network, adviser, GPU or source download.
