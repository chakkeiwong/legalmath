# Tool and literature adoption survey

Date: 7 October 2026. Baseline: `a05e18bbd`, branch
`feature/prospectus-evidence-master`. This survey addresses the engineering and
evidence gaps recorded in the ordered repair's `RESULT.md`.

## Question and evidence contract

Which existing components can close a specified gap with less implementation
and validation risk than extending the current service? Compare each candidate
with the current pinned code, existing ResearchAssistant/OCR tools, and the
smallest local implementation. Do not compare a manually reviewed candidate
with an automatic baseline and attribute the difference to software.

A recommendation requires an inspected mechanism, an explicit integration
boundary, known input/semantic limitations, and a local acceptance experiment.
Inspect technical methods, evaluation/limitations and relevant appendices of
papers used for decisions; inspect official implementation where available.
Public metadata nominates reading and does not establish accuracy, maturity or
legal applicability. Store acquired sources, exact URLs, hashes and reading
anchors locally. Reuse previous retained technical reading where appropriate.

Promotion vetoes: lost source characters/geometry, silent legal defaults,
incorrect supported answers, semantics incompatible with UNKNOWN/CONFLICT,
unreviewed mandatory conventions, or a dependency whose operating requirements
cannot be met. Continuation vetoes: invalid source identity, corrupted inputs,
unbounded retrieval or unexpected paid/model execution. A failed tool candidate
does not invalidate the prospectus program.

Explanatory diagnostics: document/parser throughput, downloads, citations,
repository activity, installed modules, benchmark scores on unrelated domains.
No tool is promoted to the production default by this survey. No model training,
GPU execution, bulk installation, paid API, or external reviewer messaging is
part of this task. Human legal adjudication and actual event facts stay external
evidence requirements.

## Coverage and working assumptions

| Gap | Candidates and comparator | Earliest discriminating evidence |
|---|---|---|
| Document structure and OCR alignment | Existing PyMuPDF/Poppler/Tesseract; Docling; document parsing benchmarks; alternative OCR systems | Exact characters, page/box alignment, margin attachment and language order on retained pages |
| Choices, exclusions, references and amendments | Current AST plus Z3 constraints; Akoma Ntoso; Web Annotation and provenance standards | Every selected/excluded occurrence accounted for; indirect references and competing editions remain visible |
| Conditions, negation, exceptions and priority | Existing partial semantics/RuleIR/Catala; ContractNLI; statutory IE; argumentation/contract checkers | Truth-table and contradictory/unknown premise cases; reviewed and automatic input arms |
| Dated law and events | Existing bitemporal facts; structured legal identifiers and authority portals | Effective, known and observed times; applicability versus actual exercise |
| Financial schedules and settlement | Exact local kernels; QuantLib; ACTUS; FINOS CDM | Source-explicit conventions, event traces and independently derived boundary amounts |
| Controller dependencies and reproducibility | Current DAG; Build Systems à la Carte; hermetic build principles; property/mutation tests | Undeclared reads fail; relevant changes invalidate exactly the needed descendants |
| Review and finite acceptance | Existing review packets/UI; INCEpTION/brat; legal benchmark annotation methodology | Independent blinded labels, source-grounded disagreements and adjudication, heldout families |

Assumptions: retained cases are development evidence, not a heldout population;
paper/code versions are separate identities; local availability means discovery
or import only unless execution is separately recorded. Financial and legal
defaults are hypotheses until tied to the selected source. Parser/model ranking
requires a later predeclared paired evaluation, not this source survey.

## Execution and stopping rule

1. Inspect local environment and current code at the relevant interfaces.
2. Use ResearchAssistant for bounded public metadata discovery and PDF parsing.
   Retrieve official/author primary papers, specifications and selected source
   files; preserve unsuccessful routes and version limitations.
3. Read mechanisms and relevant evaluation/appendix material, trace proposed
   adapters into the current code, and record adopt/trial/defer decisions.
4. Write the survey, source/reading manifest and concrete experiment sequence;
   red-team each recommendation for hidden defaults and stronger unsupported
   conclusions. Check links, retained hashes and working tree changes.

Stop when every gap has an inspected mechanism or a named unresolved source,
each proposed adoption has an integration/acceptance specification, and the
most important alternatives have a disposition. This is an engineering-focused
survey, not a claim of exhaustive literature saturation. Use at most 120 bounded
logical public retrieval attempts in this separate survey; preserve provider failures.
Redirects can generate more wire requests than logical attempts; the transport
receipts retain redirect counts where available.
The old prospectus-corpus request ledger remains unchanged.

Artifacts: `SURVEY.md`, `source-manifest.json`, `reading-ledger.json`, environment
inventory and discovery responses under the new research directory. Commands
use the current worktree; external tools remain read-only. CPU-only checks set
`CUDA_VISIBLE_DEVICES=-1` before any possible scientific-library import.
