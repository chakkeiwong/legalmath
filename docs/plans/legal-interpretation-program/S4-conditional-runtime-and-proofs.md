## Thorough plan review

The broad plan has two material underspecifications. First, S3's admission test
requires positive support and no negative support. It is not monotone under
recursive addition of evidence: a later contrary could invalidate an already
derived conclusion. A naive accumulating forward loop would be wrong relative
to that semantics. Second, the existing Boolean lowering theorem proves equality
of two parsed Boolean trees. It does not prove S3's standard computation or a
recursive theory. Reusing its certificate would prove the wrong target.

Revision: fix extensional evidence before inference. Add a separate finite positive
Horn profile with only positive intensional heads and positive derived parents.
It admits cycles without manufacturing support from an unseeded cycle. Extensional
true/false/unknown/conflict states remain distinct; only positive-only support
admits a fact premise. Negative heads, dynamic contrary generation, defeasible
priorities and recursive argument trees are explicitly outside this new profile.
The existing eight-argument preferred profile remains unchanged.

S3's 35 retained readings include 32 without formalization. Inventory every
reading individually, preserving exact original hashes and uncertainty; no
Boolean formula will be invented to claim their English interpretation solved.
The new compiler lowers S3's explicitly declared conditional standards, including
their authority and inference premises, to a separate executable representation.

## Mathematical specification and evidence contract

Question: for a bounded declared theory and fixed evidence, does the actual
decoded Java result equal exactly its least set of derivable positive heads?

Comparator: verified S3 sufficient implications (no recursive dependencies) and
an independent closed-set enumeration oracle on small recursive theories.
There is no comparison against legal answer labels, model votes or weak proxies.

Represent support by independent positive and negative bits. The wire codes are
0 = neither, 1 = positive only, 2 = negative only, 3 = both. The admissibility
function is g(c) = (c = 1). Each rule r has a head h(r), a list F(r) of fixed
fact indices, and a list P(r) of positive parent-head indices. For a set X:
T(X) = X union {h(r): every f in F(r) has g(code[f]), and P(r) is a subset of X}.
Start X0 empty and iterate. Because only membership in X can enable a parent,
X subset Y implies T(X) subset T(Y). Each strict change adds a head; with H
heads, at most H strict changes occur. A final closure check is still required.

Derivability is inductively generated by a rule whose fixed facts are admitted
and whose parents are derivable. Soundness is preserved when adding such a head.
By induction on a derivation, every closed set contains every derivable head.
Thus a sound closed set is exactly the least derivable set. Unseeded cycles add
nothing; a seeded cycle can derive only through its seed. Failure to derive a
head is absence from this conditional closure, never its legal negation.

The Lean prelude will prove this generic leastness argument and admission facts.
For each checked invocation, reconstruct the typed numeric program from the
actual Java-decoded payload, verify its identity against the requested program,
construct ordered derivation witnesses and kernel-check that the actual returned
set is sound and closed. Do not execute proof text or command paths supplied by
a receipt. Rebuild proof code from validated integers and fixed templates.

Primary criteria: generic theorem accepted by pinned Lean; each retained backend
result has a kernel-checked soundness/closure witness for its exact numeric input;
codec rejection and roundtrip correspondence checks pass; source-bound lowering
reproduces every S3 rule status; the v4 actual dossier invokes and verifies the
new runtime. Independent finite enumeration challenges recursive implementation.
Counts, speed and model/reviewer agreement are explanatory only.

Promotion vetoes: lost four-state support, false support from cycles, omitted
premises, changed modalities/objects/attachments, stale evidence, missing kernel
checking, or unsupported English claims. Continuation vetoes: corrupted baseline,
invalid checker, inconsistent semantics, unbounded execution or unauthorized
external action. A concrete implementation counterexample triggers repair.
At most two causal repairs per cause precede a written plan/audit refinement.

The theorem covers the encoded theory, not English fidelity, authority, client
evidence truth, the Python source-to-IR transformer, all JSON parsers, javac/JVM
correctness or future legal sources. Runtime checking ties a particular decoded
result to that theorem; decoder/encoder and source lowering remain explicit trust
boundaries with independent finite checks, not universally proved compilers.

## Concrete implementation phases

1. Preserve verified S3 code, tests, drivers, pointer and original plan. Record
   every unsupported reading, argument construct and runtime boundary.
2. Implement strict versioned IR with 64 heads, 64 rules, at most 1024 fixed fact
   states, and at most 32 facts and 32 parents per rule. Rule/head/fact identities
   and a context hash are preserved in the lowering map. Reject out-of-range
   indices, duplicate IDs, noninteger/Boolean indices and unknown fields.
3. Implement a synchronous Python reference, an independently structured Java
   agenda evaluator, strict JSON transport and an independent closed-set oracle.
   Retain the actual decoded Java payload, result, source/class/toolchain hashes.
4. Prove generic admission and leastness lemmas in Lean. Generate per-invocation
   proofs from checked data; reject missing witnesses, nonclosed sets, and forged
   proof/result identities. Bound kernel and Java execution time.
5. Add explicit semantic-investigation.v4 opt-in with a v4 context; retain v2/v3.
   Lower source-bound scoped standards and execute the new backend inside actual
   CompleteInvestigation, bind its receipt to every affected branch, and replay
   it in whole-stage verification. Keep legacy Boolean outputs separate.
   Positive recursive theories are supported by the declared IR API; source
   interpretation does not automatically generate recursive legal theories.
6. Run adversarial codec cases, full four-state small-domain tests, seeded and
   unseeded cycles, order invariance, boundary/resource tests, and affected
   regressions. Preserve immutable attempts, commands, manifest, decisions and
   red-team note. Refresh S5 honestly from remaining proof/source gaps.
