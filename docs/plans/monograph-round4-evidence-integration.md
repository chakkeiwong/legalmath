# Revising the monograph after the interpretation-reliability work

24 September 2026. **Executed after user authorization.** The revised pair is a
244-page monograph and a 76-page technical companion. The
[execution review](../monograph/review/round4/integration-review.md) records the
completed chapter changes, checks and remaining acceptance conditions. The
assessment and revision instructions below are retained as the approved plan.
Round-four resource figures describe that checkpoint; later implementation
continues separately.

## Editorial decision

Revise the book from a largely proposed investigation method supported by an
early scripted controller to an implemented, bounded investigation method with
retained development observations and local integration evidence. Explain the
new mechanisms through the running banking questions. Preserve the distinction
between implementation, tested behaviour and established legal meaning.

The target reader remains senior management, compliance, legal, operations and
engineering. Management should understand what can now be exercised and what
decision remains. A reader following the full argument should understand why
combining controls, comparing interpretations, citing an official example and
finishing an investigation are four different achievements.

The main volume should teach those distinctions where they arise. The companion
should give the exact current interfaces, evidence and reproduction instructions.
Phase names, test counts and file identities belong primarily in the companion.

## Evidence inspected and skeptical audit

The starting points were `method-boundaries.md` and `execution-report.md` in
`docs/implementation/interpretation-round4`. The assessment also inspected all
B1–B6 result notes, B2b/B3/B4 design audits, the operator guide, the final red-team
record and next-phase plan; the round-two and round-three execution reports;
selected implementation and result records; and relevant passages in both books.

All eight accepted B0–B6 attempt manifests match the phase-state hashes. Their
855 recorded output files match the hashes resolved relative to each attempt
directory. B6's JUnit record contains 503 tests, zero failures, errors or skips.
Its retained operations summary reports three separate Java host processes and
the controlled source update. These are checks of retained evidence, not new
test or model executions. The evidence check is recorded beside this plan.

The audit rejects four tempting but misleading edits:

1. Replacing every future tense with present tense would promote unimplemented
   legal reasoning, empirical evaluation and institution integration along with
   the mechanisms that actually exist.
2. Adding a B0–B6 chronology to the main book would recreate the reader-facing
   problem identified by the user. A result enters because it teaches a new
   distinction, not because a phase completed.
3. Reporting 503 tests or 474 retained checks as legal accuracy would change the
   measured target. In particular, 224 of the 24EC16 rows are deterministic
   unavailable-program findings, not live model judgments.
4. Describing the entire project as scripted would now understate the evidence.
   Rounds two and three include live development work; round four used retained
   responses and controlled inputs without new model calls. None is a held-out
   comparative accuracy study.

This plan passes that audit as a document update. It authorizes no additional
model calls, new legal conclusions or deployment. The current 235-page monograph
and 69-page companion remain the baseline for the proposed edit.

## Executive summary and contribution

The summary should say that the prototype can generate and investigate rival
readings, check them against separately collected source claims, retain missing
qualifications, combine explicitly scoped controls, and deliver draft Java
packages whose results can be reproduced. It can use retained official examples
conditionally and revisit affected controls after a source change.

Suggested replacement for the description of completed work:

> LegalMath now investigates competing readings of a circular and carries the
> resulting proposals into executable controls. It preserves the passages and
> assumptions behind each reading, checks for requirements that several readers
> may have missed, and uses concrete cases to expose differences where the facts
> can be compared. Separate controls can be combined without treating rival
> interpretations as simultaneous requirements. A local demonstration also
> follows a source amendment into a changed Java result while preserving the
> earlier decision and an unaffected control. The next evidence needed concerns
> performance on unfamiliar regulatory material and operation within the bank's
> own systems.

Keep the summary's positive contribution prominent. The limit is specific:
these capabilities do not establish the correct or exhaustive interpretation of
English, measured reviewer savings or authority to release a bank control.
The 503-test count belongs in the supporting technical record.

## Main-volume revision map

### Chapter 2: teach what the new source work revealed

Extend the source-edition discussion with the retrieved FAQ: a page associated
with 2010 contains later answer updates, so its title does not establish what a
historical reviewer could have read. The Code editions selected for tested dates

Use the FAQ's product-type/fund-house example to distinguish a requirement

Briefly introduce 24EC16 settlement readiness as the later observed challenge:

### Chapter 3: make the three evidence targets explicit

Build on the existing preservation distinction at
`chapters/03-proof.tex:45`. Follow one clause through the retained English and
its applicability, the proposed interpretation and formal expression, and the
generated program. An exact quotation can support the wrong proposition; a
perfectly consistent program can preserve that mistake.

Explain what the source-facing comparisons add to the computational proof and
why model-assigned support remains defeasible. Retain all existing mathematical
claims with their assumptions. Avoid representing a source-support label as a
theorem or renaming the computational preservation equation as end-to-end proof.

### Chapter 4: connect literature to the implemented adaptations

Update the synthesis and adoption discussion with the selected mechanisms now
used: explicit rival readings, bounded search, typed challenges, official-example
registration and executable comparisons. Keep descriptions of the original
papers distinct from the local adaptation.

The project has no general judicial-ratio extractor, binding-priority procedure
or full AGATHA/CATO implementation. The new registry contains official FAQ
examples, not court cases. A concise synthesis can establish this relationship;
there is no need to repeat the implementation history beside every paper.

### Chapter 5: two important new explanations

After the case-based argument discussion at `chapters/05-search.tex:133`, show
what the retained official example contributes. A genuine quotation does not
authenticate an invented case identity or settle which features matter. The two
FAQ branches share one source family. Their twenty conditional moves across
five candidates are not twenty precedents or twenty independent confirmations.

At `chapters/05-search.tex:456`, distinguish a proposed distinguishing case from
one executed through the original candidate programs. A pair may be scored only
after subject, output meaning and fact correspondence have been aligned. The
controlled gift/discount case demonstrates one separation; the retained 23EC46
and 24EC16 investigations supply no unconditional comparable witness in this
acceptance. Explain why that is an informative limitation.

Equation `eq:disagreement-question` should retain its general heuristic meaning,
with an explicitly stated comparison domain. Its implementation specialization
counts executed, comparable pairs. If a separate restricted sum is useful, first
teach why excluded pairs cannot count. An absence of checked comparisons must
remain distinguishable from checked agreement; neither settles source meaning.

### Chapter 6: incomplete work and unresolved meaning

Replace the blanket future-controller language at
`chapters/06-ensemble.tex:1152` and the promise of future scripted tests at line
1195 with an accurate historical or illustrative description. Do not relabel the
specific invented trace as an actual executed run without matching its evidence.
Add the real shared-omission challenge where the chapter explains shared mistakes.

Use the final integration repair to deepen the existing explanation of finishing
work: a requested source/example check that never completed needs a bounded
retry; completed checks that still leave two defensible readings must retain the
open question. An unchanged source does not turn unresolved meaning into success.
A zero-exit process does not settle either issue.

Present residual questions as exact questions with sources, alternatives,
affected controls and attempted checks. Missing code, missing documents, missing
bank facts and contested legal meaning have different remedies. Internal owners
can answer narrow questions; the workflow does not automatically commission an
external legal consultancy.

### Chapter 7: combining controls is not conjoining rival readings

Add a worked composition explanation after the rule representation is taught.
A gift restriction and a disclosure duty can both need implementation. Two
competing readings of the gift restriction remain alternatives. Combining all
three as Boolean conditions changes the intended problem.

Teach the result as several separately meaningful control answers before naming
a vector or showing formal notation. Preserve each component's scope, modality,
exceptions, dates and unresolved questions. Explain why shared short fact names
must not merge different meanings. Namespaces and exact serialization belong in
the companion.

Report the actual evidence accurately: two controlled multi-component packages
and five alternatives for the retained gift control were built and executed.
This is not completed whole-circular composition for 23EC46 or 24EC16. Group
assignment is still an explicit proposed interpretation.

### Chapter 8: describe the current prototype

The phrase “a scripted interpretation provider” at
`chapters/08-implementation.tex:92` / PDF page 182 is no longer a sufficient
description of the whole implementation. Retain the early scripted evidence as
history and add the later source-driven generation, investigation, source checks,
composition and draft Java delivery in terms of what the reviewer can do.

Use one integrated journey, not a feature inventory: inspect source and date;
see competing readings and missing coverage; examine a distinguishing case where
comparison is justified; receive separately scoped controls and their open
questions; follow a source change into affected work. State where the local
demonstration stops and the institution's registry, identities and fact owners
must enter.

### Chapter 9: reconcile the proposed study with the implemented harness

The five-arm conceptual ladder at `chapters/09-evaluation.tex:258` is not the
implemented four-arm study. Explain the actual single-reader, isolated-readers,
search and assurance comparison by function. Preserve any further ablations as
future research instead of making the two designs appear identical. Avoid using
the same B labels for experimental arms and engineering phases.

Report eight scripted jobs across two development cases as acceptance of the
dispatch, hidden scoring and accounting machinery. Retain unsafe acceptance,
useful accepted answers, abstention and missing output together. No live-method
ranking or reviewer saving has been established.

Explain dependence with the two branches of one FAQ: additional rows do not
create additional independent source families. If the implemented simultaneous
bound is discussed, teach family differences and its assumptions, then give the
derivation retained in `b4-design-audit.md`. The one-family interval covers the
full possible difference range. A convenience sample does not establish a
population error rate. Keep the existing conformal discussion as a separately
conditional research method, not a deployed guarantee of this harness.

The present 64-call fixture reservation exceeds the 22 remaining authorized
calls. That exact arithmetic belongs in the dated technical record. The main
text should explain the more durable requirement: a complete fair comparison
needs sufficient resources and unseen families with defensible reference
outcomes. Extra calls alone do not make the current fixtures held out.

Public official examples with explicit outcomes and authorized recorded
decisions can support suitable evaluation questions. Independent qualified
judgment remains necessary where the target requires it; neither a universal
external consultancy requirement nor developer/model agreement should become
the default reference procedure.

### Chapter 10: demonstrate amendment and remaining adoption work

Deepen the amendment discussion at `chapters/10-operation.tex:209` and the
conclusion at line 838 with the executed local source-update example. Adding a
fee-discount exception changed the selected restriction's answer in a separate
Java host while the unrelated control and earlier versions survived. Identify
the example as a controlled source/rule fixture, not an observed regulatory
amendment interpreted independently by a model.

End with two concrete next streams: empirical performance on unseen material,
and institution staging with actual host/service identity, control registry,
fact owners, scheduler policy and release roles. Local monitoring and host
packaging now exist. Institution acceptance, confidentiality, audit integrity,
real concurrency and activation authority are not thereby established.

Put a short current-implementation map before the detailed historical records.

that search is merely optional future implementation no longer describes the
current local system. A phase-by-phase status check is required; evaluation and
bank integration remain incomplete even where adapters and local tooling exist.

Add a current reference organised by the task an implementer performs:

- Resolve retained authority editions and record uncertain historical use;
  document the dual extraction path and missing OCR/statutory-definition limits.
- Compose component controls; state grouping inputs, alternative selection,

- Generate and verify a distinguishing case; state comparability, exact replay,
  resource-deferred work and scoring semantics.
- Register official examples; state issuer, edition, factors, outcome meaning,

- Present candidate prose and retain partial checks; distinguish known corruption
  diagnostics from source support, preserve raw proposals and all concerns, and
  record capacity and incomplete-execution rules.
- Freeze and execute an evaluation; document the four adapters, concealed labels,
  budgets, paired family outcomes and conditional uncertainty calculation.
- Package a draft control for Java and monitor source changes; document immutable
  inputs, bounded retries, unresolved completion, attention states and release
  authority separation.

Use the exact `assurance-compose`, `assurance-evaluate` and `assurance-schedule`
interfaces from the current operator guide and code. Keep full schemas and
