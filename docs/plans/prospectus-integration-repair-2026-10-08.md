# Prospectus tool integration repair and attribution program

Baseline: `4dfd34071`, branch `feature/prospectus-evidence-master`, plus the
retained tool-decision audit. Preserve historical A0–A6 and INCEpTION attempts.
The user authorizes implementation, bounded execution, and narrow allow rules.

## Question and evidence contract

Can correct adapters and supported usage meet the specific legal-source,
annotation-authoring and financial-comparison requirements? When they cannot,
does evidence locate the failure in our program, configuration, package behavior,
missing source inputs, or an untested capability?

Comparators: original PDF/raw-word occurrences and A3 attempt-005; INCEpTION
run-020 exchange and deliberately authored expected spans/relations; exact
financial fractions and dates already checked against QuantLib 1.38. Original
source bytes, old failures and old receipts are immutable. New attempts retain
commands, method/input/output hashes, environment, wall time and failure details.

Primary criteria: exact source conservation and unique occurrence binding;
normalization changes explicitly accounted for; measured margin relationships
against source-reviewed development targets; actual persisted authoring operations
and password authentication on the official server; exact export reconstruction;
unchanged peer annotations; independent derivation for financial controls.
Package installation, HTTP success, test counts, string presence and speed are
explanatory only. No population ranking, independent human reading, complete legal
interpretation, or production/default promotion follows from this program.

Promotion vetoes: wrong quotation/edition/offset, lost negation/number, ambiguous
binding, unchecked relationship, changed peer record, accepted wrong password or
cross-account access, incorrect fraction/date, or unsupported instrument defaults.
Continuation vetoes: corrupted input/comparator, runtime identity mismatch,
unplanned external/paid action, exceeded finite resource budget. Candidate failure
triggers repair and does not veto independent later phases. A fundamental-package
verdict requires a minimal reproduction in the pinned package and a documented
requirement mismatch that a supported configuration or lossless adapter cannot
resolve; otherwise classify the narrower observed failure or leave it untested.

CPU only, `CUDA_VISIBLE_DEVICES=-1` before imports. Reuse installed packages,
models, Java and browser; no GPU, paid APIs, external messages, deployment or
global approval-policy changes. A server attempt has a 300-second startup and
900-second workflow bound, 2 GB Java heap, owned-process cleanup and sealed output.
New evidence/runtime storage is capped at 2 GB; layout uses two pages and four
CPU threads. Optional public-source feasibility refresh is capped at ten HTTP
requests and 20 MB, restricted to official project repositories; no installs.
Stop an affected run for invalid inputs, not just because the candidate failed.

The run could pass misleadingly by copying expected annotations into the server,
normalizing away legal punctuation, comparing outputs from different models,
counting fixed status strings as measurements, or declaring synthetic users
independent. Raw initially empty exports, real browser actions, independent
expected edits, source-preserving maps, paired configurations and explicit
scope statements prevent those particular conclusions.

## Commands and approvals

Use the literal prefix `python3 -m scripts.prospectus_integration_repair` with
fixed actions: `preflight`, `check`, `layout`, `authoring`, `feasibility`, `analyze`,
`run`, `status`. No arbitrary command, URL, output path or shell input is accepted.
The wrapper selects the application interpreter and an explicit CPU environment.
An isolated sidecar is used only for Cassis/Docling/QuantLib operations.

Prepare and test repository `allow.rules` before installing a separate narrow
file in `/home/chakwong/.codex/rules/`. Installation outside writable roots and
trusted loopback execution use the platform's normal escalation mechanism. The
rule does not weaken sandbox mode, approve unrelated edits, or guarantee that
new rules are hot-reloaded into an existing session. Existing local edits need
no extra approval. Exact wrapper calls avoid shell substitution/redirection and
environment-prefix mismatches. Record actual installation and matcher evidence.

## Skeptical review before implementation

Verdict: PASS after narrowing package claims and adding the following safeguards.
The baseline is the actual pinned configuration, not every release/model. The
two-page corpus is exposed development evidence. A strict-map failure remains a
failure of that path; raw projection changes the integration design and must be
evaluated separately. Margin scope cannot be inferred merely from proximity.
The authoring schema derives provenance from actual selections, never expected
answers; source text stays immutable. Real password authentication is testable
without claiming real human independence. ACTUS/CDM are feasibility decisions,
not failed numerical candidates. No proxy metric is a promotion criterion, and
explicit stop/repair bounds prevent unbounded retries. Remaining defaults are
named hypotheses with counterexamples. The result must preserve any unresolved
package attribution rather than manufacture a binary conclusion.

## Continuation review after live diagnosis

The first eight live failures locate driver defects in button/display-name
selectors, the changed SVG representation, and feature-save synchronization.
INCEpTION registers two queued change handlers; network-idle alone does not mean
the Wicket queue has finished updating the DOM. The ninth attempt waits for the
actual queue and passes all eight exact exports and four access denials. The
final run repeats this changed method with stronger provenance and an additional
unauthenticated-access control. No failure attempt is discarded.

The runner now freezes phase-specific code, source inputs and runtime bytes,
verifies complete output sets, refuses corrupt reuse, preserves interrupted
attempts, serializes phase execution and reuses only current successful results.
The final check includes the installed adoption program and its identical replay;
the historical repair verifier must not be run. Check/adoption outputs are new
attempts. Final analysis redecodes the raw live exports without contacting the
server. Source acquisition is separately receipted before comparison input freeze.

Audit: PASS for this bounded continuation. Source projection deliberately uses
