## Evidence contract

Question: does the implemented source-to-review-to-Java workflow satisfy the
specified finite semantics, provenance, temporal, identity and transaction rules?
Comparator: manually specified conformance outcomes and adversarial expectations,
plus full Python/Java semantic agreement with independent native-hash checks.
Primary criterion: each core task's actual executable acceptance conditions.
Vetoes: altered source anchors, contradictory/collapsed evidence, incorrect exact
arithmetic or event order, false authority, wrong binary, corrupt persistence,
unreproducible results, unbounded or unsafe source/model execution. Stop dependent
work to repair these; keep unrelated work moving. Compilation, fixture counts,
matching two implementations and solver UNSAT alone do not establish fidelity
to law, complete proof, usefulness to reviewers or bank readiness.

Record commands/results in artifacts/runs and task evidence in a separate current
execution ledger. Update the reset memo after each meaningful milestone. No GPU,
training, stochastic method ranking or live model experiment is planned.
