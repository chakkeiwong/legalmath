## Question and proposed repair

Can the actual answer preserve source qualifications and stated case premises,
and what observable difference does each selected tool make to that answer?
The failed correction introduced a P11 premise absent from the case, lost the
distinct confidence-scope rival, and never supplied tools to the live answers.
The old full-matrix investigation has unqualified populations and resources.

Use a bounded, question-directed product entrypoint built from the existing
ToolSession, ProductToolBackend and CompactProvider. It reads the entire retained
54-unit source packet and exact P10/evidence questions, constructs explicit
source obligations and typed case premises, obtains two fresh source analyses,
and independently proposes formal readings and an argument graph. Every answer
arm receives identical sources, cases, analyses and successfully validated
representations. Only selected tool feedback differs. The baseline and each
tool arm run regardless of another arm's legal acceptance. This directly tests
the missing downstream connection without requiring a correct baseline first.

This proposes a separately qualified, focused answer method. It does not remove the
old RouteBudgetProvider live refusal, claim complete all-claim/all-candidate
coverage, reuse historical hand-written graphs as model-generated evidence,
or substitute activation for fulfillment. P14 obligations relevant to the two
answers remain mandatory. The complete P14 and Gatecoin questions retain their
own source-readiness and population review; their unresolved source scope cannot
block the P10/evidence experiment.

## Evidence contract and acceptance

Comparator: contemporaneous baseline with the same full source packet, exact
questions, case text, two source analyses, common successfully prepared inputs,
model, caps and effort policy. Retained prior answers are regression controls,
not the matched baseline. Primary criterion: executor source inspection of
answers against all explicit obligations and cases, plus traceable treatment
of the actual tool outputs. Classify each obligation preserved, violated or
unresolved with quoted evidence. Never infer semantic correctness from an ID.

Promotion vetoes: an invented P11 case premise, lost confidence-scope or request
rival, unsupported incorporation, lost original question, trigger substituted
for fulfillment, solver agreement treated as legal warrant, fabricated quote,
or an unsupported compliance conclusion. These reject that answer; they do not
cancel another candidate. Input corruption, missing exact sources, mismatched
arms, unrecorded spending and expired authority invalidate the affected run.

Explanatory diagnostics: byte size, latency, retrieval rank, schema success,
engine agreement, test counts and self-reported tool use. Actual tool context
must appear in the persisted wire request before dispatch. Source review must
inspect the answer's use, rejection or non-use of that context. One stochastic
answer per arm gives descriptive results only; no ranking, universal English
accuracy, general legal correctness or default-policy promotion follows.

The method must state what remains unassessed: full formal populations, general
English-to-law equivalence, complete case-law transfer, current-law completeness,
and actual client compliance. A fully evaluated tool can be unhelpful or harmful;
installed and invoked are separate from fully evaluated.
