## Evidence contract and research intent

| Role | Required evidence |
|---|---|
| Engineering pass | All original 492 distinct pairs have two validated perspectives and all four dimensions assessed; old and new evidence verifies; completed restart adds zero calls. |

| Continuation veto | Unknown dispatch state, broken evidence identity, unreviewed method/route, exhausted actual grant or absolute deadline. A returned invalid response stops dependent dispatch until a specific repair is reviewed. |
| Repair trigger | Retained invalid model response or reproducible interface defect. Count implementation revisions and live recovery attempts in the new repair ledger. |
| Explanatory only | Request size, runtime, label frequencies, model agreement, tool invocation counts. |
| Excluded conclusions | General English/case-law correctness, calibrated legal accuracy, independence, tool superiority, closure of the original obligations, fresh end-to-end generation or release readiness. |

The main question is whether the retained product can finish its real scoped
assessment without confusing candidate targets. Expected failure is a model
choosing an expression or reasoning about a question from a neighboring
candidate. Schema constraints can veto invalid expression selection but cannot
prove that a free-text rationale interprets the source correctly. Successful
processing therefore remains distinct from legal interpretation accuracy.
