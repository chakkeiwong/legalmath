## Evidence contract and assumption audit

The exact comparator is each predecessor request, schema, provider binding and
response. The candidate is the sealed optional typed account contract. Passing
means successful responses remain valid under their original contract and every
prospective changed packet has a measured disposition: fits, needs the existing
lossless partition, or cannot yet be constructed because children are missing.
No source text or required member may be removed to achieve a fit.

Changed retained bytes, source/question identity or unknown dispatch are
continuation vetoes for that recovery. An oversized candidate is a repair
trigger and promotion veto, not a reason to cancel unrelated work. Successful
local schema validation does not establish live compatibility, legal entailment,
whole-route affordability or tool benefit. Counts, failure frequencies and token
sizes are explanatory diagnostics; this is not a stochastic method ranking.

The inherited 12,000-token limit is retained policy, not a newly established
service limit. Measure both product and provider wrappers using the retained
tokenizer. Hidden service framing remains unmeasured. The completed request
population is exact only for settled owners; evidence/Gatecoin snapshots remain
provisional. The new negative-lookahead schema remains a compatibility hypothesis
until an actual bounded qualification. Original dates, grant, circuit state,
replacement limits and historical charges remain governing constraints.

## Revision after the population diagnostic

The retained `account-recovery-audit/result.json` rejects immediate adoption of
the sealed account candidate as a sufficient repair. P10 has 84 failed accounts
out of 85; P14 has six out of eight. Their 58 reconstructible combinations all
exceed the unchanged limit. The active evidence snapshot adds 31 oversized
combinations. Seven failed leaf requests also exceed the limit under the typed
candidate. All 325 terminal successful partial responses revalidate exactly.
The run made zero provider calls and verified all 31 frozen continuation inputs.

Add one bounded local representation experiment to the same account package,
independent of the active supervisors. Test an exact transport table that stores
overlapping source text once, names repeated input citations, and expresses the
existing response-span selections as compact tuples. The complete text, every
partial reading, every citation occurrence, every original question and every
assignment must reconstruct identically. Source slices remain available in the
same request. This tests redundant representation cost, not semantic summarizing
or a larger context allowance.

The comparator is the already measured typed candidate on all 89 concrete
combinations and every failed leaf. The primary engineering criteria are exact
round-trip reconstruction and measured fit under both wrappers. A mismatch vetoes
that representation. A packet that remains oversized stays blocked; do not drop
source text or promote fit on only an easy subset. Tests must cover overlapping
and disjoint source spans, Unicode offsets, conflicting overlap, corrupted
references, and an unchanged default transport. Local fit would nominate a
candidate for later live qualification, not establish model comprehension of
the tables or close an account. Preserve unresolved parent inputs whose children
have not succeeded. No existing source, response or sealed candidate is edited.

Skeptical review: PASS for this single zero-call experiment. The newly reproduced
failure is an inability to combine successful readings, distinct from the
citation failures. The experiment preserves that hard baseline and explicitly
tests the tempting but unproved assumption that redundancy alone explains the
overload. If exact tables are insufficient, report the residual sizes and revise
the adoption plan before any live dispatch; do not spend account attempts on
the same capacity failure.

## Bounded capacity candidate and live prerequisites

The exact-table experiment passed all 211 reconstruction checks and 13 adverse
unit controls. All 122 failed dispatched requests now fit locally. Only 31/89
known combinations fit; the other 58 need up to 15,736 product-wrapper tokens
(15,542 provider-visible tokens). Thus exact transport repairs part of the
problem but is rejected as the complete capacity solution. There is no measured
gateway failure at those larger sizes: the existing 12,000-token policy rejects
them before dispatch.

Prepare an isolated, opt-in account-input profile with a 16,384-token cap only
for typed requirement combinations. It retains the 12,000-token default for
every other request, the existing byte/output limits, source bytes, original
question, shared grant, circuit and deadline. The value 16,384 is a convenience
hypothesis: the next binary capacity step above the observed 15,736-token
maximum. It is not a statement of the model's advertised or proven capacity.
The earliest diagnostic is exact wrapper measurement on the full retained
population, with controls rejecting larger or foreign requests. The profile
must enter request and saved product identities. Old valid requests retain
their old input profile and provider identity for exact reuse.

This local implementation is independent of the active supervisors and writes
only an isolated candidate. It follows the failed representation experiment
within the same account repair; no new live owner or reset is admitted. Skeptical
review passes for implementation because it addresses the reproduced refusal
directly, leaves all old contracts reproducible, and does not silently change a
default. Unit controls and the retained-packet measurements must pass before
adoption review.

After both supervisors settle and a same-master amendment records the complete

Gateway refusal, timeout or wrong output retains the result and blocks only

if the protocol qualifies. The full matrix still needs a prospective budget
including correction and transport headroom, not merely the 4,655-call floor.
