10 October 2026. This revises the method of the existing `product-contribution`
pilot after its four-call failure. The original protocol, source snapshot,
requests, responses, terminal result, grant and ledger prefix remain evidence.
There is no new grant, clock, legal target or tool-completion claim.

The engineering question is whether the existing exact-source-reference adapter
removes transcription fragility sufficiently to run the original matched
P10/evidence comparison. The substantive question and acceptance criteria remain
those in `legal-mission-live-pilot-400.md`: complete qualified source arguments,
including conduct/outcome alternatives and the limits of reconciliation.

## Reviewed method and resources

Both arms use `legalmath.source-spans.v1` with the existing reversible
`readable-tables.v1` encoding. Source text, unit IDs, qualifications and questions
are identical to the failed pilot. A model selects request-bound spans; local
code reconstructs the exact Unicode source text. Unit accounting, claim-to-unit
links and substantive validators remain in force. No failed response is edited
or fed to the new run as an accepted inventory. Both investigations start fresh.
No product source change is proposed.

Each arm now receives **32 core calls**, the baseline's actual remaining core
capacity. All other stage caps remain 3/82/64/1/1. Each fresh arm therefore has
183 calls; the initial four calls remain spent, for at most 370 across both
attempts. The original grant and per-stage ceilings are unchanged. Four candidate
core slots are deliberately unused to preserve equal effort. The assessment
reservation and 25 unallocated calls remain untouched. The global deadline stays
12 October at 04:28:01 UTC; the core clock stays 10,800 seconds. Automatic
transport retries and uncertain restarts remain prohibited.

This is one additional bounded enabling package, counted as the **fifth**
engineering detour even though work stays on `product-contribution`. The reviewed
exception authorizes only configuration, continuation accounting, local checks,
and one matched execution attempt. Allow at most 90 minutes for enabling work,
ending at 06:35 UTC on 10 October. It does not renew the ordinary one-detour rule

## Evidence contract and skeptical audit

The exact comparator is a fresh same-method baseline without optional tools;
the candidate differs only by the six selected tools. Primary pass requires
complete answers followed by inspection of their source arguments and reduction
chain. Passing source inventory is only an enabling diagnostic. Corrupted
references, source/method mismatch, missing required stages, deadline exhaustion
or missing accounting veto continued comparison. Inadequate legal reasoning
vetoes promotion and triggers source analysis. Request sizes, tests, tool
invocations and elapsed time are explanatory only. There is no statistical
ranking, individual-tool attribution or default change from this single pair.

| Choice | Provenance/status | Failure risk | Earliest check |
|---|---|---|---|
| Exact source spans | Existing qualified product capability; repair hypothesis | IDs can still be wrong or absent; a located quotation can be irrelevant | Reconstruct the actual NBSP unit unchanged; reject foreign IDs and bad unit links |
| Readable table encoding | Existing reversible codec; capacity convenience | Encoding may lose a field or source qualification | Exact request round trip on all four retained calls |
| Whole packet, 55 units | Original retained full input; baseline | Omissions and unwieldy inventories can persist | Both inventories must account for all 55 units; no pruning |
| 32 core calls each | Remaining baseline allocation; reviewed equal-effort cap | Less capacity for later criticism than originally planned | Stop on actual required-stage failure, retaining generated content |
| 200,000 input bytes | Existing product limit; capacity hypothesis | Span metadata and longer resolved quotations may overflow later stages | Measure inventory requests now; enforce actual later requests before dispatch |
| Same model and arm order | Original route policy; descriptive only | Correlated errors and service variation | Source-grounded review; no superiority claim |

**Audit: PASS for implementation and local qualification of this one revision.**
The first inspection found the original literal method had left an existing
reference capability disabled. A diagnostic reconstruction of its four requests
found readable span requests of 128,525; 178,262; 128,609; and 154,433 bytes,
all below the existing cap. All round trips were exact. This does not qualify
future generated requests or the complete product. Preserve that distinction.

Material risks remain: source-span validation can fail before an answer reaches
the ordinary output-repair loop; complete unit coverage and correct link choices
still depend on generation; larger reconstructed quotations may inflate later
requests. These are explicit continuation checks, not reasons to weaken
validation. Do not enable decomposition or increase caps speculatively in this
revision. A successful adapter invocation cannot answer the legal question.

Before dispatch retain a concrete qualification report, source/code snapshot,
matched method identities, manifest and mission revision. Run targeted grant,
source-context, reference and encoding checks. Execute baseline first and run the
candidate only after a complete baseline answer. Retain the actual result in
`live-pilot-400/source-spans/` and a separate result note. Refresh mission history
after each completed package.

Pre-mortem: the run can pass structurally while losing a decisive contrary reading
or answering duty activation instead of fulfillment. Inspect actual complete
answers against the original dossiers. It can fail for formatting or capacity
without discrediting tools. The next smallest evidence is the valid pair of
inventories, followed by generated readings and the complete answer, with every
failure preserved. No later success retroactively validates the first pilot.
