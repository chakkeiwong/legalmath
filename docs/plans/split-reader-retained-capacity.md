# Actual-source split-reader capacity diagnostic

Question: after lossless source-locator compaction, can the implemented split
reader carry the actual 263-unit authentication packet through interpretation,
all coverage pieces and whole-source reconciliation within its declared byte
limits? This is a deterministic processing diagnostic, with simulated responses,
not a legal reading or a live capacity claim.

Use the unchanged frozen source and the tested split protocol. The simulated
reader proposes an explicitly synthetic unencoded reading, accounts for every
unit, and retains every per-unit cross-piece concern. It receives no legal
answers. Its purpose is to stress the complete retained context, including the
final response's dependency on every earlier piece. Do not drop concerns, source
text or questions to obtain a successful result.

Comparator: the actual uncompressed initial request exceeded 200,000 bytes;
the repaired initial request fits. Primary criterion: the run either accounts
for every declared source unit/question/concern with exact identities, or stops
with the exact remaining stage and limit. Source loss, unsupported completion
or omitted concerns vetoes the implementation. A final context limit is a repair
trigger and prohibits a complete-capacity claim; it does not invalidate the
already preserved source or the interpretation research direction.

Use `.venv/bin/python`, CPU only, no randomness, no model/network calls. Preserve
the actual command, original source digest, protocol settings, stage request
sizes, results and elapsed time under
`artifacts/assurance-continuation/2026-09-29/split-capacity/`. The initial/default
20-unit and 6,000-character pieces are reviewed convenience bounds, not
scientifically optimized settings. Their provenance is the implemented bounded
coverage plan. The cheap diagnostic is each actual request byte count.

Skeptical audit: PASS for capacity/accounting only. A simulated reader can miss
every true legal issue while producing perfect coverage identities. No result
here estimates legal accuracy, measures live latency or supplies evidence that
the real authentication circular has been fully interpreted. Explicitly retain
any final context failure for the next measured repair.
