# Second-circular verification — 22 September 2026

## Question and skeptical audit before execution

The user asks whether a different circular has been tested and how correctness
can be established. The current 154-test engineering acceptance executed the
23EC35 SPI profile. Other pilot circulars were imported and their metadata checked;
they did not supply independent executable controls. The drafting provider is a
deterministic fixture stub. Calling those tests evidence of accurate automatic
translation of unseen circulars would be wrong.

Run a new, explicitly bounded engineering validation of **23EC46 paragraph 10**,
the restriction on gifts in promoting an investment product or product type,
including the exception for discounts of fees or charges. This differs from the
SPI financial/consent example. It is already in the retained research corpus,
so it is not a blind held-out circular. The rule and test materials have the same
agent author: independent oracle *representation* is feasible, independent legal
adjudication is not supplied by this exercise.

Audit verdict: proceed with a manually specified candidate and precommitted source
cases; leave legal issues and external Code/FAQ dependencies unresolved. Build and
test the candidate JAR without manufacturing meaning approval or releasing it.
Preserve the original accepted program, suite and Java artifacts unchanged. The
new evidence must say exactly which paragraph and assumptions it tests.

## Evidence contract

- Engineering question: can the existing unchanged RuleIR-to-Java system express
  and execute the selected gift restriction while preserving scope, exception,
  unknown information, source evidence and review blocks?
- Comparator: prose case outcomes written from the source before creating RuleIR;
  separately, a small truth-table oracle derived from that stated interpretation.
  Neither oracle reads the candidate AST or either evaluator's output.
- Pass criterion: every named scenario matches its specified result in Python and
  the generated Java class; the finite T/F/U table matches; native hashes/traces
  validate; deliberate omission of the fee exception, product-type route, unknown
  evidence and scope is detected; unresolved issues/dependencies prevent approval.
- Vetoes: altered source spans, invented legal permissions, source facts that
  were silently classified by the translator, Java disagreement, unblocked release
  or a case expected value changed merely to match observed code.
- Repair trigger: a software mismatch opens a specific defect; an ambiguous source
  case remains unresolved and cannot be converted to a passing legal judgment.
- Continuation veto: corrupted source/expectations invalidate the experiment; repair
  provenance before further interpretation.
- Explanatory only: case count and run time. A large truth table does not represent
  many independent legal questions or establish translation accuracy.
- Not established: correctness of the complete circular, automated language-model
  translation, regulatory compliance, bank readiness or comparative effectiveness.

## Scope and assumption audit

Each assessment concerns one proposed incentive component. An offer containing
both a fee discount and a separate gift must assess the gift separately; the
discount exception cannot exempt the whole offer. Inputs describing whether an
incentive is a gift, solely a fee/charge discount, or linked to a product/type are
reviewed facts, not text classifications established by the program. The surrounding
paragraphs say guaranteed returns *may* constitute structured products or gifts;
this test must not turn that into a universal classification.

The selected profile concerns distributors promoting SFC-authorised funds, based
on the circular's stated subject. That is a deliberate narrow test scope, not a
claim that Code paragraph 3.11 has no application beyond those funds. FALSE means
this selected gift prohibition is not established on the supplied facts; it is
not permission to publish an advertisement. OUT_OF_SCOPE likewise grants nothing.
Rule validity is a declared synthetic test interval, not a derived legal-effective
date. Original publication metadata remains separate.

Unknown legal/data classifications stay UNKNOWN whenever they can change the
answer; conflict remains CONFLICT. A known sufficient exception or a known absent
trigger may settle this subcondition despite other unknowns. Reviewed input mapping
and paragraph-by-paragraph coverage are separate verification duties.
