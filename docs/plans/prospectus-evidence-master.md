## Research question and evidence contract

Question: how far can the repaired reader and investigation progress on unseen
issuer families, missing contractual sources, source-bound loss computations and
explicit private-input requirements without misrepresenting incomplete evidence?
Comparator: the preserved 32-case candidate-002, 734 passing tests, 16 qualified
positives/16 qualified negatives. Its source readings are not gold labels.

| Source criterion | An obligation resolves only with retained bytes, a checked identity/edition, exact source anchors and a reasoned applicability review; a successful fetch or candidate reference alone does not resolve it |

The engineering, source validity and interpretation ledgers remain separate.
Candidate failure triggers repair when the next planned step addresses it. It
does not terminate the direction. Missing actual client facts block real legal
clearance, not useful software work or delivery of an explicit requirements file.

Controller state records attempts, status, material-input hashes and elapsed time.
Each terminal attempt includes result, review and a next-phase-plan bound to the
result hash; the latest plan is refreshed atomically. Method/source changes mark
dependent phases stale. An interrupted attempt is preserved as interrupted, its
dependent evidence invalidated, and a new attempt created. A lock prevents two
controllers mutating state together. Public requests are counted before dispatch
so a crash cannot reset the budget. Completed acquisitions are reused only when
their bytes still match; failed responses remain inspectable.

Repair has two paths: predefined deterministic repair (metadata migration,
Poppler extraction fallback, regenerated derived inventories, transport alternate
route) is executed by the runner; a new semantic defect stops dependent promotion
and writes an actionable patch/test queue for the supervising coding agent. After
the agent implements and reviews that patch, `run` detects the changed method,
reruns dependent evidence and freezes again. No arbitrary shell or Python code is
accepted from data files. Merely writing a repair plan is not a repair result.

Pre-mortem: the program can succeed operationally while proving the wrong source
interpretation, counting repaired documents as fresh, turning a cap into a payment
right, or treating a retrieved trust deed as applicable without amendment review.
Early identity checks, frozen chronology, exact boundary tests, full conditional
quotes and independent witness inspection address those risks. Source packets
contain no authored expected-answer/quality labels. Human review is not invented.

## Commands and permission scope

Every invocation uses exactly this prefix from the isolated worktree:

```
.venv/bin/python scripts/run_prospectus_evidence_master.py authorize
.venv/bin/python scripts/run_prospectus_evidence_master.py review
.venv/bin/python scripts/run_prospectus_evidence_master.py run
.venv/bin/python scripts/run_prospectus_evidence_master.py status
.venv/bin/python scripts/run_prospectus_evidence_master.py verify
```

Bounded auxiliary actions use the same prefix: `acquire`, `inspect`, `register`,
`phase`, `refresh`, `freeze`, `check`, and `repair`. Arguments are fixed choices
or validated campaign-local paths/approved public URLs, never shell fragments.
The reviewed allowlist records actions, hosts, budgets and paths; the matching
prefix rule is tested with `codex execpolicy check`. `authorize` installs only a
new dedicated rule file, retaining any differing previous content. It requests
trusted execution upfront for this exact prefix. Existing broad rules and
approval policy are not weakened. No private-data fetching, access certification,
email, account creation, model spending, dependency installation or unrelated
file mutation is authorised by this runner.

## Skeptical pre-execution audit

REVISED AND ACCEPTED FOR BOUNDED IMPLEMENTATION. A literal promise to close every
gap would be wrong: real client facts and full legal completeness cannot be
manufactured. The executable design advances supported calculations and source
investigations, with explicit unavailable-input outcomes. Neither all tests
passing nor all phases attempted counts as evidence closure. The wrong-baseline,
proxy-metric, stop-condition, environment, default and artifact-question risks
have separate checks above. New semantic failure schedules repair and invalidates
dependent evidence. The acquisition limit stops retrieval only; independent
validation and honest delivery still execute. Review the actual implementation,
failure paths and allow-rule match before approving long or network execution.
