## Why more definition attachments cannot finish the answer

The ordinary clause evaluator collects uncertainty from several different
sources: nodes whose effect is unknown, unresolved reference closure, assembly
units with an UNKNOWN role, uncovered units, unresolved dependencies and an
incomplete declared question scope. The service also discovers reference
dependencies from both OPERATIVE and UNKNOWN assembly units. These safeguards
currently preserve a much broader source inventory than the selected German
contract used for the definition investigation.

A successful source supplement does not establish that all this uncertainty is
relevant to the same legal question. Equally, an item outside the selected
continuous text may remain relevant through incorporation, governing language,
an operative alternative or dated law. Removing everything outside that text
would be wrong. The next substantive step must explain the actual unresolved
question entries and their source paths before adding more local readings or
declaring a question complete.

The inspected code paths are service.dependencies and clause_graph.evaluate.
The retained definition investigation already distinguished the selected
continuous text from the larger assembly and preserved eleven exact source
copies lacking an assembly occurrence. Those gaps must be included in the
question audit; a new filter must not hide them.

## Question and evidence contract

Question: for each unresolved item in the complete current ordinary answer,
what source, role, dependency or missing premise causes it, and what is the
smallest justified repair? The baseline is the complete sealed answer following
the definition application and packaging work. This first package is a
read-only investigation. It must retain every original item and reference,
including items later shown to be irrelevant.

Primary pass criterion: lossless reconciliation of every actual unresolved
entry into an evidence-backed explanation, with unknown classifications left
explicit, and an ordered next program keyed to the original obligations.
Inspect source examples from each class, including selected-contract uses,
alternative or language selection, incorporated reports, missing source,
statutory application, absent meaning and real-client facts. Do not use a
dependency prefix as a substitute for tracing the source.

Counts and runtimes are explanatory. Smaller uncertainty lists are not a
promotion criterion. The investigation cannot promote a legal answer, establish
general recall or erase unresolved entries. Corrupt baseline input, missing
source reconstruction or exceeded reviewed limits veto continuation; a
misclassified item triggers a changed, source-reviewed repair.

## Ordered work

1. Bind the complete current products and answer, current method hashes and
   protected original obligations. Retain the actual unresolved identifiers and
   match them to graph nodes, assembly occurrences and service dependencies.
2. Distinguish proven selected-source relevance, explicit exclusion supported
   by source, incorporation or statutory dependencies, missing meaning, unknown
   relevance and conditional client facts. Preserve overlapping causes.
3. Trace representative originals and every exceptional/unmatched identifier.
   Separate a missing source from a missing application rule and a missing
   client fact. The user's decision to postpone real holdings does not stop
   conditional reasoning on source premises.
4. Rank the repairs by which original question they can actually advance.
   Missing definition and calculation-date issues remain substantive; package
   mechanics cannot substitute for them. If broad default relevance is causing
   spurious uncertainty, propose a source-bound scope admission with adverse
   cases before implementing any filter.
5. Refresh the same authority with the reviewed next work, preserving original
   denominators and cumulative resources. Define positive question effects and
   refusal controls before implementing a semantic repair.

able to conclude that. It must not presume that an UNKNOWN answer is a bug or
that a shorter list is more correct.
