# Five additional circulars: integration and candidate verification

## Intent and evidence contract (revised before semantic execution)

Question: do five previously untested circulars survive retained-source intake,
explicit scoped interpretation, adversarial boundary cases, Java compilation,
cross-backend comparison, bounded discrepancy processing and refusal to release
unreviewed candidates? Existing 23EC35 and 23EC46 examples are comparators for
the engineering workflow, not held-out interpretation ground truth.

The initial source/workflow-only draft was rejected during skeptical review:
two existing circulars were reused, anchors were sentence fragments, proposals
were generic placeholders, no repair ran, and the durable report discarded its
underlying investigation. Its result survives in `preliminary/structural-only.json`
as superseded evidence, not acceptance of this plan.

Five **additional** circulars, all from the retained SFC product index:

| Circular | Selected executable slice | Easy error targeted |
| --- | --- | --- |
| 23EC49 | Money-market annualised-return display conditions | omit seven-day companion; exclude exactly six months; confuse interactive and print duties |
| 24EC16 | US/Canada standard-security settlement-regime transition | miss Canada's 27 May footnote; apply T+1 to FX; confuse business-day count with calendar-day due date |
| 24EC50 | e-IP submission route from 30 November 2024 | retain obsolete October cutover; exclude the first mandatory day; turn optional fee-payment functionality into a duty |
| 24EC57 | Type 9 ESG-provider diligence and group-resource controls | omit incidental Type 9 activities; require voluntary-code membership; transfer local responsibility |
| 26EC23 | Connecting-broker price alert and primary-market reminder | use >= rather than >; invent a regulator-set threshold; omit the primary-market alternative |

25EC48 is an additional announcement-only negative control. A survey statistic
of 76% is not automatically a transaction limit. Existing 23EC53/26EC22 snapshots
remain lineage/dependency material, not separate diversity cases.

Primary pass criteria, required for each selected circular:

1. Raw and text digests match a frozen manifest. Every non-whitespace character
   of each retained source derivative belongs to the packet inventory; the MMF
   appendix is acquired and inventoried. Exact spans, relevant footnotes and
   encoded versus deferred scope remain visible.
2. Manually specified named scenarios match the declared interpretation in
   Python and the generated Java class. Check complete semantic responses,
   source traces and backend-specific hashes, not just Boolean answers.
3. Two intentionally incorrect variants per circular compile, remain valid
   RuleIR, and are detected by fixed scenarios in both Python and generated Java.
   A compilation error does not count as detection.
4. Three concrete first readings survive. A shared omitted source unit triggers
   bounded scripted repair. Three repair attempts close structural omission only;
   unresolved legal questions/dependencies remain reported. Exact initial
   candidates remain unchanged. No probability of legal correctness is invented.
5. Full investigation/report evidence survives on disk and verifies after
   reopening the database. An actual meaning-acceptance request and the bound
   bundle release guard reject the candidate despite successful Java tests.

Comparator: source-written cases with expected values frozen before candidate
execution, tested against the proposed bundle and two deliberate wrong readings
under the same facts. This deterministic engineering comparison cannot rank
stochastic methods or estimate legal accuracy.

Promotion vetoes: wrong source identity; missed relevant anchor; unexpected
status/value/trace/hash difference; undetected mutant; lost reading or issue;
unbounded work; accidental approval/release; incomplete preserved evidence.
Continuation vetoes: corrupted official snapshot or invalid harness assumptions.
A candidate or test failure triggers diagnosis and repair; it does not abandon
other planned cases. Preserve failures before fresh attempts.

Explanatory only: inventory counts, issue counts, actions and wall time. Passing
cannot establish legal correctness, independent adjudication, whole-circular
implementation, live translator accuracy, current bank applicability, or
production readiness. Oracles and proposals share an author and are development
fixtures. Unknown classifications, calendar policy and authoritative external
versions remain open legal/data issues.

## Assumption/default audit and pre-mortem

| Choice and provenance | Justification | Risk and early diagnostic | Status |
| --- | --- | --- | --- |
| Frozen official English JSON and MMF appendix | Reproducible cited text | Wrong revision: verify refNo, hashes and complete text before intake | Reviewed fixture source |
| One scoped rule per circular | Five different semantics within RuleIR 0.1 | Slice mistaken for full coverage: inventory all text and list deferred obligations | Test hypothesis |

| Integer market codes and local dates | Typed vocabulary; exact Gregorian comparison | Wrong jurisdiction/timezone: test Canada footnote and first-day boundaries | Explicit abstraction |
| Absolute deviation and threshold in basis points | Exact comparison | Threshold is supplied policy, not an SFC constant; test varied and unknown values | Scenario parameter |
| Four scripted roles, three repairs | Existing reference policy, repeatability | Correlated opinions: retain scripted authority, unreviewed inventory and competing readings | Engineering fixture |
| Java 17 and existing venv | Matches accepted runtime | Environment mismatch: validated toolchain, bounded subprocesses, no silent skips | Reviewed environment |

The strongest misleading pass is agreement between implementations of a wrong
reading. Source-written scenarios and wrong-reading mutations reduce that risk;
independent legal adjudication remains pending. A perpetual blocked status is
also insufficient: require successful executable results before the separate
release veto. Inventory/citation coverage never means every clause is encoded.

Skeptical audit: revised plan passes for engineering validation only. It fixes
the initial proxy criterion and records remaining same-author and scope risks.
No live provider, bank data or approval is used. Source acquisition is read-only
and creates new retained files.
