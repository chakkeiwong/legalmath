\section{Preserving the whole investigation under bounded processing}
\label{sec:processing-continuation}

The unfamiliar-source investigation encountered a failure before any legal
disagreement could be assessed. A reader quoted the authentication circular
with ordinary spaces where the retained document contained nonbreaking spaces.
A later response substituted null characters. The source validator rejected
both. Rejection preserved the evidence boundary, but repeated requests to copy
the same characters spent the allowance without answering the interpretive
question. Exact copying is work that software can perform deterministically.

The September continuation separates that task from deciding what a passage
means. Before asking a reader for evidence, the software gives each retained
source unit an identifier. It also offers bounded adjoining spans for longer
units. The reader selects identifiers; the software retrieves the corresponding
characters from the unchanged source. Every selection is bound to the source
edition and the particular request. An identifier from another request, an
altered source, a repeated selection, or disjoint fragments presented as one
quotation is rejected. The whole source remains available to the reader, so
selecting a short passage does not remove a remote exception from the context.

For an engineer, the coordinate convention matters. A span starts at one
Unicode codepoint and ends immediately before another. These are neither UTF-8
byte offsets nor Java UTF-16 offsets. In a string containing an astral character,
those coordinate systems give different lengths. The implementation uses
precomputed identifiers rather than asking the reader to count positions.
Nonbreaking spaces, combining characters, carriage returns and line feeds
survive unchanged. If a selected fragment occurs more than once in its unit,
the reader must select enough adjoining context to distinguish it or select the
whole unit. This preserves the earlier quotation contract.

An authentic quotation can still be irrelevant. After retrieval, the original
source-support and question-correspondence checks therefore run unchanged. A
reader may select the correct paragraph while leaving its support for the
proposition unestablished. That is a valid uncertain result. The resolver never
changes such a judgment to supported merely because the identifier was valid.
Both the original identifier response and the resolved quotation response are
retained, allowing a later investigation to distinguish transcription failure
from a disputed reading.

\subsection{Give every question an initial hearing}

Consider three batches of source claims, two initial perspectives per batch,
and a budget of six requests. A schedule that completes both initial and
follow-up rounds for the first batch can consume four requests there. Only two
requests then remain for the second batch; the third receives no assessment.
An exception in that last batch would remain unseen even if the early readers
agreed enthusiastically.

The implemented round-first option offers both initial perspectives to every
batch before allocating follow-up depth. Under the same six-request workload,
it reaches all three batches. Both perspectives in a round receive the same
earlier evidence; the first answer in the current round is withheld from the
second. Invalid responses remain recorded, and every unattempted pair remains
in the denominator. A transport interruption preserves the consumed attempt.
Changing a partition or response schema cannot replenish a source issue's
attempt allowance or restart its oldest deadline.

This ordering improves a specific accounting property: eligible initial work
is not displaced by routine follow-ups on an earlier batch. The deterministic
comparison does not establish a ranking in legal accuracy. An early objection
may still matter more than a later routine question, and the current policy does
not pretend to estimate that legal importance. It preserves the questions so
that capacity limits cannot silently choose which ones disappear.

\subsection{A small executable answer must not replace the circular}

The authentication baseline attempted to return one interpretation and a
263-unit coverage table in the same response. The split-reader option now asks
first for the interpretation and its exact questions. Each question names the
actor, assessment unit, temporal basis and output meaning. Bounded responses
then account for the source units against that unchanged reading. A response
may link a unit to several questions, classify it as context with a reason, or
retain uncertainty. Dependencies on units in other pieces remain explicit.

Merging is deterministic. Every required unit must occur once; invented,
duplicate or missing identifiers fail. The merger retains every cross-piece
concern. A final whole-source response must account for each concern and each
declared question. It may retain the reading with uncertainty or propose a
revision. A revised reading has a new identity, so the previous correspondence
table cannot certify it. The implementation rechecks coverage, subject to the
same nonrefundable source-unit limits, or reports the remaining work.

This is also a guard against answering the wrong question well. Suppose a
program answers whether a material investment-policy change needs prior
approval. A separate transitional question asks how an application already
pending at the effective date is processed. Both outputs may be Boolean, but
they are different decisions. The coverage record cannot attach the first
program to the second question merely because the types agree. An unencoded
question remains visible beside an executable proposal. The declared question
inventory is itself a proposed reading of the source; exact accounting cannot
prove that the reader identified every possible legal issue.

The retained authentication source also reveals the distinction between input
capacity and response capacity. Its 263 units and the initial reference schema
occupied 261,822 request bytes before earlier interpretations or coverage
results were supplied. The single-reader limit is 200,000 bytes, so dividing
the response table alone did not remove the input limit. A deterministic
diagnostic using the existing locator-compaction function preserved all unit
identifiers, text and normative flags while reducing the initial transport to
153,212 bytes. The subsequent repair connects that function to the optional
split-reader path. It explicitly distinguishes the original packet identity,
which the coverage result must name, from the compact transport identity used
by the reference table. Tests reject their substitution and check that the
263-unit initial request fits. Later whole-source reconciliation still has a
size limit; a completed authentication investigation does not follow from the
smaller initial request alone.

A deterministic capacity exercise then carried that exact packet through all
coverage pieces using deliberately synthetic proposals. It retained all 263
source units and one cross-piece concern for each. Their whole-source
consistency request occupied 382,396 bytes and stopped at the input limit,
preserving the coverage and concerns. This is a measured final-context failure,
not a completed interpretation. The next processing repair must reduce repeated
representation while retaining the information needed to examine interactions
among the concerns, or state an explicitly narrower supported capacity. Deleting
concerns or labelling the completed pieces as a completed circular would give
a misleading result.

\subsection{Extend arithmetic without changing the proposed meaning}

One retained private-market-fund proposal used four addition operands where
the compiler previously accepted exactly two. Let $D$ and $I$ denote the
proposal's direct and indirect exposure quantities in the same exact valuation
unit. Its expression was $D+I+D+I$. The repeated terms represent a proposed
doubling of aggregate exposure for comparison with NAV. Whether those exposure
definitions and that classification rule follow from the circular remains a
source question. A compiler repair must preserve the expression it receives,
including every repeated operand.

The extension defines addition as an ordered fold. For operands $x_1$ through
$x_n$, first add $x_1$ and $x_2$, then add $x_3$ to that result, continuing in
the supplied order. The lowering relation is
\begin{equation}
  \operatorname{Add}_n(x_1,\ldots,x_n)
  = \bigl(\cdots((x_1+x_2)+x_3)+\cdots\bigr)+x_n,
  \qquad n\geq 2.
  \label{eq:continuation-ordered-addition}
\end{equation}
For $D=25$ and $I=25$, the four terms sum to 100. Deduplicating the operands
would give 50 and change the proposed test. Existing binary expressions retain
their previous representation; subtraction and multiplication do not gain
additional arities by analogy. Expanded expression size and depth are checked
before a compiler is invoked.

The arithmetic theorem uses exact unbounded integers and a tagged missing
value. Adding a missing operand yields missing. By induction over the remaining
operand list, the ordered binary fold equals the specified n-ary operation;
if every operand is known, it equals the integer sum; if any operand is missing,
the result is missing. Lean checks these statements. The recorded proof names
its standard logical dependencies explicitly. A separate constructor check
compares the independently parsed proposal with the emitted model, while Java
and Catala execute finite challenges, including negative values and integers
larger than machine integers. Conflict, applicability and time selection retain
their separate semantics and checks; the addition theorem does not establish
them by integer associativity.

The twenty-operand challenge also exposed an implementation problem outside
arithmetic: the schema validator recursively explored alternatives whose
required operator already contradicted the expression. The repair discards
only those logically impossible alternatives and retains the original schema
checks for every remaining branch. Comparisons against the original validator
and the unchanged backend challenge check that this processing repair does not
weaken acceptance.

\subsection{State what each completed check establishes}

The investigation can now attach the exact source, proposed reading and
question to the shared machine-qualification route. A supported formal
proposition receives its checked domain and premises. An unencoded reading, an
unavailable authority or an unresolved source question remains qualified. A
formal theorem can be obtained while the product still withholds translation
because source dependencies remain unresolved. Separate hypothetical execution
may investigate that expression under declared mathematical inputs, but it
does not remove the product's unresolved conditions.

Applying the adapter to all nine retained UCITS readings illustrates a different
limit in that recorded run. Eight readings contain a date fact, which the
constructor proof then did not support; the ninth has no executable formalization. Every reading also
retains unresolved source questions. The adapter verified all nine identity-bound
qualification records, reporting eight unsupported formal profiles and one
unencoded proposal. It reported zero executed target cases. A preliminary
Boolean-only challenge generator stopped as soon as it encountered the date
fact; it did not replace that fact with a convenient date. Thus the new adapter
accounts for the actual proposals without presenting a finite Boolean test or
the integer-addition theorem as a proof about dates. The subsequent declared
calendar extension in Section~\ref{sec:executable-dates} addresses this proof
limit while preserving the unresolved source questions.

Numeric and date mappings also require a declared comparison domain. The
domain record names every common fact, its type and unit, the listed values,
and whether they are mathematical probes or an expressly declared finite
domain. A separating case is replayed through the original programs. Matching
probes establish no result outside those listed values. The system neither
extracts a convenient domain from expected answers nor turns a source quotation
into proof that a finite list exhausts the institution's possible facts.

Historical failures remain part of this account. The earlier unfamiliar-source
phase completed none of its four whole ensemble investigations, despite the
passing software regression. The continuation implements and tests specific
processing repairs and pursues only live issues whose original limits permit
another request. It does not rename the earlier failed phase as successful.
Changes to the method also prevent its new results from entering the earlier
frozen prospective window as if its method had remained unchanged. English
interpretation and unknown future circulars continue to receive explicit
qualifications until the corresponding propositions and premises have support.

\subsection{What the live continuation actually resolved}

The repaired live route used the remaining 37 authorized reservations. One
provider stream disconnected; its reservation remained spent. The resumed run
reused nine completed responses under their original identities before making
further calls. It completed both initial perspectives for all fifteen selected
batches and then six follow-up responses, with no current-round answer shown
to its paired reader. Of the 36 returned responses, 27 passed the response
contract and nine were rejected. All returned source-span selections resolved;
the rejections concerned executable quotations, unencoded candidates or
inconsistent assessment dimensions.

Those failures matter. In several batches, both initial readers assessed an
executable omission for a candidate that had no executable representation.
Agreement between them did not supply the missing program. The validator
rejected the assessment and preserved both explanations. In another case, both
readers questioned whether keeping a pending application under the existing
approval process implied that the proposed substantive relief was unavailable.
One retained unassessed correspondence; the other proposed a conflict. The
source, exact question and disputed inference remained attached to both views.

The combined old and new evidence covers both validated perspectives for 165
of the 225 UCITS claim--reading pairs, compared with 48 before the continuation.
Sixty pairs still lack a complete validated review. The continuation itself
has 90 pairs with all four assessment dimensions filled; completing those
fields does not establish that their judgments are correct. The final
reconciliations retain 42 disputes. The original 500-reservation grant is
exhausted, so further live investigation stops with those questions visible.

The master also detected concurrent additions to separate repository components
during execution. Its unchanged-tree condition failed even though all 424 files
in the repaired assurance snapshot retained their hashes. The failed phase
receipts remain failed. A separately recorded final assessment checks the
retained evidence, documents and current regression; it does not rewrite the
live phase or declare the four-circular study complete.
