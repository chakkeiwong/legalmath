\section{From an interpretation dossier to a continuing investigation}
\label{sec:successor-assurance}

Consider a firm implementing the transition to STREAMS~2. The circular says
that, during the blackout, firms should contact the JFIU directly about STRs
requiring urgent submission. A program can correctly identify an urgent STR
and still answer the wrong question. An obligation to make contact is different
from evidence that contact occurred. A telephone call about another STR, a
message sent after the assessment time, and an incomplete communication log
must produce different evidential conclusions. These distinctions motivate
the successor implementation described here. It joins the previously separate
investigations while preserving their different meanings.

The predecessor's engineering result remains useful: its retained readings,
counterexamples and generated programs can be replayed. The new work adds a
continuing investigation of source meaning, a narrow proof checker, and an
event-history demonstration. The execution record distinguishes three kinds
of progress. A capability may be implemented and tested; a particular source
question may receive additional support; and an uncertainty may remain after
the allowed investigation. Only the first of these follows from a passing
software regression.

\subsection{Ask the question before judging the answer}

A source-fidelity assessment needs four separate judgments. First, does the
inventoried claim have support in the retained source? Second, does that claim
bear on the precise question the candidate program answers? Third, does the
program preserve the relevant claim? Fourth, are the required authorities
actually available in the retained source set? Combining these into a single
``correct'' label confuses errors with differences in scope.

For example, the requirement to resubmit an off-channel STR through STREAMS~2
can be supported by the circular while remaining outside a question about the
means of making one original submission. The assessment must retain the
resubmission duty and explain its relation to the selected question. It must
not report the original-submission program as a complete implementation of
all STR duties. Conversely, an inventory statement that misreads the source
does not establish a defect in every program that omits that statement.

Each proposed question therefore specifies the actor, unit of assessment,
temporal basis, and meaning of true and false. The question's identity travels
with the assessment. Changing ``is contact required?'' to ``has the required
contact occurred?'' invalidates the old assessment even if both answers are
Boolean. The validator checks the question identity, exact source quotations,
candidate identity and output convention. These are necessary consistency
checks. They cannot establish the entailment of an English proposition merely
because its quotation is authentic.

Two fresh contexts initially assess the same bounded batch without seeing one
another's answer. One starts from the source proposition; the other concentrates
on qualifications and exclusions. Disagreement produces a further request
containing the competing explanations and the exact unresolved question.
Invalid quotations or inconsistent labels instead produce a response-repair
request. Both kinds of request consume the same finite allowance. After the
configured final round, remaining disagreement is reported with its evidence.
The inherited backlog permits three rounds; the unfamiliar-source pilot
declares two rounds before collecting answers. The system
does not select the last response simply because it arrived later.

The product's acceptance rule is a checked proposition or an explicit
qualification. Human answer keys, adjudication, ratings and approval are
excluded as quality evidence. A source text remains a premise; its authenticity
does not prove a proposed interpretation. Model agreement also remains a
proposal. The useful output therefore identifies exactly which formal relation
has been checked and which source meanings, classifications or authorities
remain unresolved. Future publications must enter a frozen observation window;
a repaired development example cannot be presented as a fresh prospective test.

The first live successor batch illustrates why mechanical checks matter.
Both initial responses marked an authority as available although the packet
did not bind the required dependency to source bytes. The validator rejected
both responses. A subsequent response repaired the inconsistency. This is
evidence that the check can catch that failure; it is not evidence that the
repaired reading is legally correct. Agreement between the initial readers
would have concealed the missing source.

\subsection{A factual model is part of an interpretation}

Two formulas cannot meaningfully be compared until their facts have compatible
meanings. In the gift example, one reading may assess an offer as a whole while
another assesses each benefit component. In the STR example, one Boolean fact
may mean that any JFIU contact occurred, while another means that the named firm
contacted the JFIU about the particular urgent STR before the assessment time.
Renaming both facts \texttt{contact} would conceal the disagreement.

The successor retains an explicit assessment frame: actors, objects, unit of
assessment and temporal basis. A proposed bridge between frames must identify
both source-bound factual models, define common facts, and give an expression
for every original fact. It also states the assumptions needed to connect the
frames. If the actor or unit changes, an omitted connecting premise is a
validation failure. If no bridge is available, the readings remain incomparable.

Once such a bridge is proposed, the implementation can enumerate an explicitly
bounded common domain, derive each reading's original facts, and execute both
original Java programs. A separating case then has a precise conditional
meaning: under the proposed factual mapping and its assumptions, these programs
give different answers. Agreement has the same conditional meaning. Neither
result establishes that the mapping is faithful to the source. The live study
therefore retains the proposed bridge, its assumptions and any failed comparison
alongside the program results.

\subsection{Authentic authority can still be inapplicable}

The legal-argument literature separates the structure of an inference from the
acceptability of its premises and the priority of competing reasons
\citep[secs.~2--3]{aspic2010}\citep[secs.~3--6]{carneades2007}.
The successor uses a bounded version of that distinction. An authority record
states its source type, proposition, role in the document, jurisdiction, actor
class, relevant factors, effectiveness interval, later treatment and supporting
passages. For a case, a party's submission is not silently treated as the
court's holding. A genuine quotation concerning a different actor or an earlier
legal regime remains a context mismatch.

Priority is represented as a reasoned relation between authorities, with its
own source evidence and premise status. A later date alone does not confer
priority. The implementation reports unresolved effectiveness, adverse treatment,
unsupported priority and priority cycles. It does not break a cycle by insertion
order or model score. Nor does it remove a candidate solely because a language
model labelled another authority applicable. These records make the open legal
question inspectable; a complete judicial corpus and an automatically reliable
treatment service remain distinct requirements.

\subsection{Exactly what the Lean certificate checks}

The registered successor profile is deliberately small. It accepts Boolean
facts, true and false, conjunction, disjunction, negation and conditional
expressions. Facts may be true, false or unknown. Conjunction with false is
false, including when the other operand is unknown; a conditional with an
unknown condition remains unknown. A conflicting dependency produces a conflict
result. In the absence of conflict, a false scope produces an out-of-scope result. Arithmetic, dates and
event histories are outside this theorem's language.

The checker parses the proposed formal expression with a parser separate from
the production translator. It also reads the emitted RuleIR expression through
a separate fixed encoder. Both become expressions in a fixed Lean semantics.
For each supported candidate, Lean checks that the two expressions produce the
same result for every valuation and the declared conflict indicator. The proof
uses fixed source code generated by the checker. It does not execute Lean text
supplied by a model or certificate. The checker rejects missing premises,
unsupported syntax, a changed target, an incorrect lowering and a failed kernel
execution. Its record identifies the source expression, RuleIR bundle, Lean
executable and semantic prelude.

This is a proof about the two formal descriptions. It does not yet prove that
the production Java emitter and JVM implement those semantics for every possible
request. The accompanying Java check serves a narrower purpose: for up to six
Boolean facts, it executes every assignment of true, false, unknown and conflict,
at the recorded assessment time, and compares the result with an independently
written evaluator. Larger domains remain explicitly unexecuted under this
profile's 4,096-case ceiling. Even a complete enumeration of these abstract
states does not enumerate arbitrary JSON encodings, dates or event histories.

These distinctions matter when comparing this work with Catala. Catala supplies
an executable language and formal compilation work designed for legal rules
\citep{catala2021}. The existing LegalMath Catala route is useful for a different
implementation of the same proposed formal meaning. Its shared fact preparation
and source interpretation remain common dependencies. A Lean certificate, a
Catala comparison and a Java replay can therefore reinforce different formal
checks without becoming three independent votes about English meaning.

\subsection{An urgent-contact example that reaches the Java boundary}

The contact demonstration makes its assumptions explicit. It interprets the
circular's local clock times as Hong Kong time, identifies one licensed firm
and one STR, and takes urgency as a supplied factual classification. The stated
blackout begins at midnight on 28 January 2026 and ends at 9 a.m. on 2 February
2026. Conversion to UTC belongs to the recorded interpretation; the software
does not infer a legal timezone from a publication timestamp. The demonstration
also keeps the validity of the generated rule version separate from source
effectiveness.

A contact record names the firm, STR, recipient and communication channel. It
contains an occurrence time, a recording time, evidence identifiers and a
confirmed or disputed status. To count as the declared witness, contact must
concern the same STR and firm, address the JFIU through email, phone or fax,
occur during the declared interval and by the assessment time, and be known by
the evidence cutoff. The recording time prevents information learned later
from silently entering an earlier assessment.

Absence needs more evidence than presence. One matching confirmed event can
establish an observed contact. An empty log establishes absence only if a
supplied completeness record covers the firm, STR, recipient, all permitted
channels and the whole factual interval. Partial email history cannot establish
that no telephone call occurred. Without sufficient history the result is
unknown. A disputed relevant event produces conflict. Reusing the same event
identifier for different actors is rejected.

The packaged Java entry point accepts these raw records and applies the fixed
contact policy. A separately implemented Python projection checks the same
cases. The demonstration includes different firms and reports, wrong recipients,
late contacts, records learned after the cutoff, disputed events, missing
history and partial channel coverage. The Java program then returns the trigger
and observed-performance results separately. ``Required contact not yet
observed'' is not labelled a proved breach: the circular does not supply every
criterion needed to infer a deadline violation from that fact alone. Observed
contact is likewise not overall STR compliance or proof that the communication
was substantively adequate.

An additional packaged boundary accepts exact decimal percentages as strings.
It converts the value to an exact rational representation before evaluating the
selected numeric rule. Boundary tests distinguish values immediately below,
at and above a threshold and reject malformed strings and attempts to submit
internal numerator or denominator fields. The accepted representation does not
establish a permissible financial exposure range. That range requires its own
source and product meaning.

\subsection{Learning from unfamiliar circulars without training on the answers}

The new study freezes four source families before their model interpretations:
private-market complex-product designation, simplified eDDA verification, UCITS
post-authorisation changes and authentication controls. These are retrospectively
unfamiliar tasks for the retained development record. They are not documents
published after the system was frozen, and possible model pretraining exposure
is unknown.

Both study arms receive the same explicitly selected sources. For authentication,
that includes the incorporated appendix as well as the main circular. Merely
placing an appendix in a retained catalogue does not put it into an interpretation
when reference traversal is disabled; the controller must select it as an initial
source. The shared-source freeze preserves every original root passage and
reference quotation. A larger inventory is processed in bounded pieces with
cross-piece checks, while exact text and source identifiers remain available.
This prevents a source-access difference or a dropped appendix from masquerading
as a difference in interpretive ability.

Sixteen conditional cases probe express source distinctions. Exactly 50 per
cent exposure tests an inclusive threshold. Exposure below that threshold,
without designation evidence, tests whether discretion is incorrectly converted
to a definite non-complex classification. A client-supplied deposit screenshot
tests the eDDA footnote requiring more than sole reliance on such documents.
A pending UCITS application tests the transition provision, while an already
bound device tests the authentication exception. Each expected answer is tied
to a retained clause and explicit factual assumptions before the unfamiliar
model answers are generated.

The reference is useful precisely because its limits are stated. It is a
source-condition challenge set prepared by the executing researcher, not an
independently adjudicated set of complete legal outcomes. A successful result
does not estimate deployment accuracy, and these historical probes do not
qualify a legal-correctness claim under the product's current machine-only
evidence rule. During evaluation, models receive the
case facts and question but not the expected answer or selected reference
passage. They must either propose a factual mapping to an unchanged candidate
program or declare that the program answers a different or unencoded question.
Actual Java execution follows a validated mapping. Its factual and interpretive
premises remain visible rather than becoming an invisible test oracle.

The comparator maintains one reading and revises it against the source. The
ensemble also constructs rival factual models and readings, searches their
differences, and pursues scoped objections. Both have the same declared per-task
invocation ceiling, but their actual expenditure can differ. The report retains
that difference, every selected task, failed generation, unaligned case,
unsupported program and unanswered question. It records common misses and
contrary decisive proposals without presenting this small study as a statistical
ranking. Multiple versions can share errors; diversity of names or prompts
cannot establish independence \citep{knight1986diversity,littlewood2001diversity}.

The live pilot also exposes the cost of this design. Its two source inventories
yield 46 retained claims, while generation and investigation retain eight
readings. Reviewing each claim against each reading creates 368 pairs. If a
request covers at most $b$ pairs, two initial perspectives require
$2\lceil 368/b\rceil$ calls; a second round for every batch raises the bound to
$4\lceil 368/b\rceil$. These counts exclude extraction, generation, criticism,
factual mapping and response repairs. They explain why a fixed allowance cannot
be translated into a fixed number of circulars before their complexity is known.

Scheduling determines which questions receive attention before that allowance
ends. The current scoped reviewer completes a batch's initial and follow-up
rounds before moving to the next batch. This differs from the earlier breadth
stage that constructs rival interpretations. Under a binding limit, later
claim--reading pairs can therefore lack an initial review while earlier pairs
have received repeated attention. Their identities remain in the report; they
are not silently removed from the required work.

The continuation specification consequently includes a separate scheduling
extension. It would allocate initial perspective opportunities across the
complete matrix before routine follow-ups, while allowing explicitly justified
priority for a consequential objection. That extension has not been implemented
in this run. Its comparison must retain the same workload, spending history,
deadlines and unresolved objections. Wider initial coverage is a processing
benefit only; whether it reduces consequential interpretation errors requires
separate case evidence.

The first 32-pair request reached its 300-second deadline without a completed
answer. A 24-pair request grouped by candidate did so too. A synthetic size test
had established that the requests fit the transport ceiling; it had not
established their live completion time. The next partition uses twelve pairs,
the size executed on the inherited backlog, while retaining every pair and the
whole source. Earlier success supplies a capacity hypothesis for this transfer,
not evidence that a different circular will finish. Both failed calls remain
spent. A smaller batch must not replenish the request count or deadline of the
underlying claim, reading and perspective.

The twelve-pair partition subsequently completed three batches, including both
perspectives and both rounds for all 36 pairs. That observation justified
starting the other frozen circular families concurrently. It did not justify
stopping the unfinished matrix or declaring the first circular complete.
Completed responses were reused with their original source, question, schema,
route and reservation identities; an interrupted request remained spent.
The full study still requires every selected investigation to finish. This
distinction lets a useful mechanism check improve scheduling without becoming
an easier acceptance criterion for the study itself.

A different capacity failure appeared in the UCITS comparison. Its smaller
legacy batches required seventeen possible model responses. The admission
check multiplied that count by the maximum permitted response size, producing
a bound of 3,409,937 bytes against a 2,097,152-byte aggregate limit. It therefore
stopped before obtaining a response. Reducing the batch size had made this
worst-case bound larger, even though the intended responses were smaller.
The bound established that completion could not be guaranteed in advance; it
did not establish that the actual responses would exceed the limit.

The implemented optional repair admits validated parts incrementally. Let $L$ be the fixed
aggregate byte limit, $A_k$ the retained aggregate after $k$ admitted parts, and
$P_{k+1}$ the next individually bounded response. Each part must first pass its
pair, quotation and representation checks. The conservative admission test is
then
\[
  \operatorname{bytes}(A_k)+\operatorname{bytes}(P_{k+1})\leq L.
\]
Combining their lists removes repeated JSON envelope overhead, so the sum bounds
the merged representation's size. A separate count limits retained concerns.
An excessive part is preserved outside the aggregate, processing stops, and the
matrix remains incomplete. Small responses can therefore finish a matrix whose
worst-case forecast was too large, while an actual overflow still blocks
completion. No concern is deduplicated or omitted to make the result fit.
The focused tests exercise both successful accumulation and a late overflow.
The live UCITS continuation then validated all seventeen batches and accounted
for all 225 claim--reading pairs, including the retained diagnostics for an
unencodable reading. This establishes completion of that comparison stage;
its interpretation judgments and the other required stages remain separate.

One returned reading also revealed a concrete language boundary. It wrote an
addition with four operands, whereas the advertised expression language
accepted binary addition. A separate reading used nested binary additions and
was executable. The unsupported reading therefore remains a proposal with an
explicit encoding failure. Supporting its syntax requires a checked translation
that preserves operand order, repeated operands, exact numeric types, unknown
facts and conflicting evidence. It cannot be accomplished by relabelling the
failed check. Nor would that extension put arithmetic inside the existing
Boolean Lean theorem; arithmetic needs a separately stated semantics and proof.

Another retained reading makes the distinction between input meaning and
program correctness particularly clear. It takes four Boolean facts: public
SFC authorisation, membership in the stated fund exclusion, exposure at or above
half of net asset value, and an operative case-by-case designation. Its scope is
authorisation together with absence of the exclusion; within that scope, its
result is exposure-above-threshold or operative designation. That Boolean
program can be checked exhaustively in the supported profile. But it accepts
the exposure threshold as an already classified Boolean input. It does not
calculate net asset value, classify a business development company, aggregate
direct and indirect holdings or establish that a designation is operative.
Those tasks remain in the input meanings and their supporting evidence.

This is a useful small control when its caller can supply the required facts.
It becomes misleading if presented as a complete implementation of the
circular. The scoped reviews explicitly proposed omissions in the asset and
designation classifications while preserving the narrower Boolean reading.
The product must therefore deliver both the rule and the unresolved obligations
of its caller. A proof over every Boolean valuation cannot decide whether the
bank assigned the correct valuation to a real portfolio.

The same distinction applies to substantive comparisons. In the pilot, a
proposed factual bridge initially carried the wrong model or source identity.
Stronger validation sent it through its remaining bounded repair opportunity.
The repaired identities allowed inspection of the proposed mapping, but its
numeric and date facts still lacked a declared comparison domain. The system
therefore retained an unsupported comparison, rather than reporting conditional
equivalence. Repairing a request makes the next check possible; it does not
predetermine that check's result.

\subsection{Retrieving a quotation without regenerating it}

The authentication investigation encountered a simpler failure before it could
complete its semantic assessment. Returned quotations replaced source
nonbreaking spaces with other characters. The exact quotation check rejected
them. The eDDA inventory separately repeated required source-unit rows. These
failures concern response construction and source accounting; they are not
evidence of successful detection of a legal misunderstanding.

The proposed repair moves exact copying into deterministic software. Each
request would contain a closed set of source-unit and precomputed-span
identifiers. An identifier resolves to the unchanged source text, its digest
and a half-open interval of Unicode codepoints. The model selects an identifier;
the resolver retrieves the characters. It neither asks the model to count
offsets nor searches for a nearby quotation when the identity is wrong.
Adjacent spans and their surrounding provision remain available so that a
sentence boundary cannot silently discard an exception. Coverage partitions
separately require one disposition for each assigned unit and reject omissions
or duplicates. This extension is specified, but was not executed in the
reported campaign. Its acceptance requires exact reconstruction on difficult
Unicode, repeated text and cross-unit qualifications, followed by a retained
live comparison of response validity. Even a perfect resolver establishes
where the words came from, not whether those words support the proposed rule.

\subsection{Changes reopen the investigation}

An investigation's identity includes source bytes, selected question, assessment
date, authority catalog, method implementation and bounded settings. A changed
source or method creates a new revision and immediately marks the active
investigation as unfinished. The old dossier remains valid evidence of what was
checked for the old revision. It cannot be retrieved as the current result for
the new revision. Successful resume reuses exact retained responses without
claiming a new independent judgment or spending another model call.

Historical replay needs the historical implementation as well as historical
source text. During the scheduling repair, the earlier replay correctly failed
against two changed implementation files. The preserved source archive supplied
the exact old bytes for verification in an isolated directory. The working
implementation was left intact, and the historical receipt explicitly remained
historical. Current implementation acceptance requires its own regression and
executable checks. Otherwise an innocent orchestration repair could either
destroy readable evidence or, more dangerously, make yesterday's result appear
to certify today's code.

The additional 500-call grant is a separate record anchored to the exhausted
earlier grant. Reservations occur before dispatch and are not refunded after
timeouts, invalid responses or interruption. Local arm limits sit inside this
same total, so parallel requests cannot create additional authority to spend.
After each phase, the master records the result, remaining uncertainty and next
justified action. A failed phase needs a documented repair and an executed
focused check before retry. This mechanism makes continued investigation
auditable while preserving the substantive rule: exhausted processing leaves
an explicit unresolved question, never an invented legal conclusion.

The execution also tests whether this discipline survives ordinary software
failures. One authority request was rejected before an answer was generated
because its evidence fields did not satisfy the service's structured-output
format. The corrected request kept the failed reservation, original question
deadline and remaining action limit. A separate resume failure arose when
parallel PDF jobs reconstructed an ordered list of peer answers differently.
The repair checks the completed investigation against its original journals
and source images, preserving the answers actually examined. Neither incident
justifies a change to a source conclusion. Both justify strengthening the
machinery that records what was asked and what was checked.

A failed repair must preserve what the investigation already recorded. The
UCITS exercise supplied a concrete counterexample: after source-fidelity
processing timed out, both replacement inventory requests failed. The engine
then replaced its active inventory with the empty replacement set, reducing
25 retained claims to zero. The initial inventories and nine candidate readings
were still preserved, so the loss was detectable and recoverable. The implemented
repair keeps the previous inventory until both replacement readers return
validated proposals, records any unsuccessful replacement and leaves the
investigation incomplete. Preserving the old claims does not establish that
they are right; it prevents lack of new evidence from erasing the questions
that still need examination. The resumed UCITS run retained all 25 claims and
nine readings and completed its legacy comparison. A later scoped request
reached its deadline, leaving 177 claim--reading pairs without both required
perspectives. The inventory repair therefore succeeded without making the
entire investigation complete.

Literal evidence also needs useful rejection messages. In the authentication
exercise, a proposed quotation replaced nonbreaking spaces in a deadline with
ordinary spaces. Its attempted repair introduced a null character. Both failed
the exact-source check. Reporting the offending unit, occurrence count and
character difference can help a bounded repair succeed while retaining exact
quotation as the acceptance condition. Automatically normalising the quotation
would answer a different question about source identity. In either case, an
authentic quotation still needs interpretation in its surrounding provision.

A specified next extension would let a model select a passage by source-unit
identity and character positions, leaving the software to copy its exact text.
The source packet and unit text would each have to match their recorded digest;
the start and end would refer to Unicode codepoints in that unchanged unit.
The resolver would reject absent units, changed text, out-of-range positions
and ambiguous fragments. It would then construct the quotation and apply the
existing evidence checks. This protocol has not yet been implemented. Its
purpose is to reduce transcription errors, while preserving the separate
judgment of whether the selected passage supports the proposed rule. Selecting
an irrelevant passage perfectly still gives poor evidence for the rule.

A resource-limited study must also remain reportable. The master has a separate
assessment mode for case evaluation, document production and current engineering
verification after a terminal study failure. It binds those activities to the
exact failed attempt and retains every selected task. It leaves the study
failed and overall execution incomplete. If the study later changes, the old
assessment becomes stale. This permits an informative account of unfinished
work without changing the acceptance criterion to match the available results.

The execution tables accompanying this section report the actual phase results.
They should be read alongside the retained stronger closure requirements:
source completeness, source-supported factual classifications, legal priority,
complementary error evidence and future-circular validation. The availability
of an executable successor is a necessary step towards the product, but does
not discharge those distinct evidential requirements.
