# Review of the isolated validation campaign

Date: 2026-09-28. Decision before execution: proceed with one bounded, isolated
campaign under the existing instruction to complete the implementation and its
repairs. This is an author engineering review, not independent legal review.

V2 has exhausted its allowance. Its last focused command passed 30 tests, but
four monograph files changed while the phase ran. The master correctly refused
acceptance. The changes incorporate Catala documentation from the other writer;
they must not be reverted. Package enumeration also repeats identical installed
distributions when the source directory is on the import path more than once.
That separate fingerprint defect is repaired by sorting unique name/version
pairs while retaining distinct versions. A focused regression checks this.

| Skeptical question | V3 decision |
|---|---|
| Does this hide an exhausted budget? | No. V2 is closed and retained without current acceptance. A separately named, explicitly reviewed successor validates changed inputs. The program cannot create further campaigns or reset attempts. |
| Is a previous passing suite being reused? | No. All six phases and the full disjoint regression partitions execute again. |
| Can concurrent edits contaminate a result? | The complete repository is copied to a fixed isolated path; all material hashes must match before execution. Any change within the copy still invalidates acceptance. |
| Can a frozen result be applied to different live sources? | Copy-back requires matching material inputs and a second manifest/dossier verification in the original repository. A mismatch prevents that acceptance. |
| Is the comparator weakened? | No. The same five retained readings, source boundaries, criticism, Java/Catala paths, probe limits, pair coverage and no-skip tests remain required. |
| Does the environment change? | No package installation. The existing environment is copied, its editable project path is rebound to the copied source, and the same Python, JDK and Catala binaries are retained. |
| Does a proxy become legal evidence? | No. Finite replay, test counts and agreement remain engineering observations. Missing fresh generation and proof certificates remain explicit. |
| What stops execution? | Three attempts per phase, unsafe/corrupted evidence, unavailable required tools, or unreconciled source drift. No automatic new campaign. |

The smallest pre-run diagnostic is the supervisor suite, including duplicate
distribution enumeration. The full evidence contract, material defaults and
source-meaning limits remain in the master plan. The result must retain its
actual execution root, original dirty input bytes, logs, unsuccessful attempts
and portable verification result. No provider is called and the exhausted
500-call allowance is unchanged.

The research direction is not rejected by the concurrent-edit failure. The
failed claim was that all phase inputs remained unchanged. Isolation directly
addresses that failure; it does not address omitted English qualifications.

The final pre-run contract review also found that the verifier checked the
underlying search results without requiring their discrepancy summary to retain
the same severity and disposition. It did not bind all hypothesis objections or
the exact wording/domain of proof obligations. Those omissions could mislead a
reader even though release remained blocked. The repaired verifier binds all
these fields, the source scope, required critical-question evidence and shared
method dependencies to the registered execution profile. Nine adversarial
cases attempt deletion, severity downgrade, unsupported explanation, objection
substitution, weakened evidence requirements, hidden dependencies and stronger
propositions/domains/scope. These are part of the frozen v3 implementation;
no phase has yet been accepted under this revision.
