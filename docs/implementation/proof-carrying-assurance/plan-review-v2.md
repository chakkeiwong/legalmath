# Skeptical implementation and plan review

The v1 plan audit missed a decisive implementation mismatch: generated success
labels did not refer to actual tool outputs. This was found before final
acceptance and is classified as wrong relative to the stated engineering target.
The old attempts are retained, not promoted. The repaired plan is a different
acceptance protocol with explicitly recorded lineage.

The current implementation was inspected from input loading through source
anchoring, criticism reevaluation, candidate breadth, common-vocabulary pair
comparison, RuleIR lowering, actual Java/Catala compilation and replay, dossier
verification and master finalization. The application interface accepts retained
investigations through a hash-bound manifest. It accepts no executable model
text and does not make a live model request.

The most important corrections are substantive:

* a fabricated digest or status does not constitute checker evidence;
* the verifier recomputes exact targets, source quotations, criticism semantics,
  typecheck results and Python behavior, and checks stored Java traces and JAR
  bindings;
* unimplemented proof-certificate checking cannot emit PROVED;
* an incomplete required obligation blocks the dossier even if method labels
  all say AGREES;
* candidate deletion, missing questions, invented method families and omitted
  Java/Catala shared dependencies are tested attacks;
* unknown grammar retains an extension question and produces no substitute rule;
* the supervisor records failed/interrupted commands before retry, executes a
  repair check, enforces its ceiling, and refreshes from verified predecessors;
* accepted hashes have no controller/plan/allowlist compatibility exception;
* regression partition coverage is audited, including the newly merged common
  translation module; an unlisted test directory blocks execution.

The trust base remains explicit. Retained hashes establish integrity relative
to trusted inputs; they are not independent signatures of a past tool process.
The execution adapter runs the actual compilers and executors. The portable
verifier rechecks stored results, not an independently signed execution log.
The pinned runtime, compiler, RuleIR semantics and verifier can still share
bugs. Java and Catala share interpretation and fact preparation. Five archived
readings provide no estimate of recall on future circulars, and no source-meaning
probability is calculated. These limits are material and remain in the plan,
monograph and result status.

The initial small execution exposed a timestamp lacking the repository's six
fractional digits. That fixture was corrected before phase acceptance. The next
real execution checked five readings, ten pairs, two separating witnesses and
both runtime backends, with interpretation still blocked. The live allowance
was inspected at 500 calls against a maximum of 500; no new calls are made.

Decision: proceed with the repaired engineering phases and complete document
and full-regression checks. This author review does not approve a legal reading,
a bank release or human readability. Any new concrete failure triggers the
recorded repair procedure, rather than removal of a check or a reduced test scope.

The post-regression red-team check then reproduced deletion of the original
input-manifest reference without loss of the embedded configuration. This was
an evidence-provenance defect, even though the legal/release fields remained
false. Schema v3 now requires that reference, rejects duplicate upstream file
paths, reparses the retained manifest under the bounded schema and compares it
to the embedded target. The three new manifest regressions passed. A further
supervisor regression checks that input changes replace a current passing report
with STALE_REVALIDATION_REQUIRED while preserving the original report bytes.
All ten supervisor tests passed after that change. P0 now archives actual input
bytes and records package versions, so the dirty implementation can be
reconstructed rather than identified only by unrecoverable hashes. The repaired
acceptance uses the third existing attempt allowance, without increasing it.
