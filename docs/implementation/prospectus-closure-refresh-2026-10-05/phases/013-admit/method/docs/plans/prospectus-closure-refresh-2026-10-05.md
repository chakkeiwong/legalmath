## Executable phases and repair mechanism

1. **baseline**: verify completed manifests/history and selected source identities;
   record baseline bindings, environments, source inventory and current gap map.
2. **prepare**: extract bounded word geometry and render BASF selection/operative
   pages and the implicated Deutsche page(s). Review images and complete explicit
   source and region review records. A missing review blocks admission only.
3. **checks**: implement and run meaningful adverse tests of source selection,
   quote bindings and lossless region extraction. Repair failures and preserve
   failed receipts before retrying.
4. **admit**: execute BASF source/option admission and the reviewed bilingual
   derivative, compare frozen-reader evidence on exactly matched pages, retain
   unresolved dependencies and explanations. Recheck source/review integrity.
5. **document**: write the result, decision table, gap actions and reset memo;
   create a separate LaTeX addendum and inspect its actual rendered pages.
6. **verify**: verify source, method, tests, review and output bindings and protected
   history; seal a run manifest and refresh the next plan from actual results.

Commands use the same driver and one phase argument. The driver permits only
the listed bounded actions, enforces phase prerequisites and writes a new numbered
receipt for every attempt. After failure, next action is repair plus the same
phase. After a method/review change, affected checks and downstream phases become
stale and must rerun. Completed results are never rewritten in place. Phase
receipts include actual command, commit, interpreter, tool versions, elapsed
time, input/output hashes, plan path and result location.

A development review of the rendered source is required between prepare and
admit; this is work for the executing agent, not an automatic user approval.
The final rendered addendum review likewise records observed pages, not human
acceptance.
