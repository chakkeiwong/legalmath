## Engineering order and concrete acceptance

These are the next deliverables, not already implemented capabilities. Before
running an implementation phase, extend the fixed master supervisor with its
exact commands, input hashes, pre-run review and bounded repair/refresh loop.
Preserve P0–P12 manifests and histories. Each phase must state the target,
baseline, diagnostic roles, stop conditions and remaining assumptions.

| Order | Deliverable and connection to existing code | Mandatory discriminating cases |
|---|---|---|
| A1 | Source completeness and evidence acquisition: combine source discovery, dependencies and search retrieval; compare independent document inventories; retain versioned official references | Dropped footnote or annex, cycles, inaccessible authority, superseded version and second-parser disagreement remain visible; unchanged source yields reproducible scope |
| A2 | Source-facing semantic check: independently extract atomic actor/action/modality/condition/exception/time/dependency claims; bind claim evidence; compare original source with reconstructed meaning | All candidates agree on a rule omitting an exception; authentic quote used for an unsupported claim; remote qualification; may/must and scope changes; absent evidence is not contradiction or approval |
| A3 | Structured arguments and interpretation operators: define bounded premises, assumptions, strict/defeasible steps and typed attacks; add explicit analogy/distinction/counterexample constructors | Premise attack differs from inference attack; unsupported priority cannot defeat a candidate; source provenance required for a precedent; negative cycles or resource limits stay unresolved |
| A4 | Stage-specific semantic repair and comparable outcomes: add stage diagnosis, explicit output conventions and conditional derived-fact mappings to the current reconstruction | Upstream repair invalidates downstream results; compliance versus prohibition polarity; split offer/gift facts; UNKNOWN/conflict, changed event date and hidden exception; original Java replay |
| A5 | Per-input challenges and continuing change detection: source/formula mutations, controlled metamorphic relations, public examples and update-triggered reinvestigation | Exception removal, wrong threshold, attachment change, stale reference, model/prompt change, novel fact schema and harmless formatting; no silent clean result or stale evidence reuse |
| A6 | Cost-aware resolution and narrow escalation: choose useful evidence actions, deduplicate questions, reuse source-bound decisions and report uncertainty at the limit | Identical repeated prompt is not progress; answer reuse requires matching scope; changed premises invalidate reuse; unrelated controls remain distinguished |

A2 is the principal correction to the earlier priority: check semantic evidence
against the retained source, not only against another generated rule. A1 supplies
the connected context it needs. A3 must specify a supported argumentation profile
rather than label the existing Dung graph a full ASPIC+/Carneades engine.
Case-law mechanisms require actual sourced case records; hypothetical examples
stay hypothetical. An SFC FAQ or incorporated definition may supply the needed
evidence without introducing court cases unnecessarily.

Inspect original library code before importing it. Different legal languages
and argument models have different semantics; installing every surveyed package
is not the goal. Choose complementary checks with clear targets and reproduce
their reference examples before connecting them to candidate pruning.

## Evidence without a large consultancy

Start with retained development circulars, official worked examples where the
expected result is explicit, and controlled challenges whose expected effect
is declared before execution. Public legal datasets can exercise generic
evidence/exception behavior; their results are not SFC accuracy estimates. If
existing bank decisions or internal compliance answers are later authorized,
retain their provenance and date. Do not assume they are infallible or send
them to an external provider without authorization.

Freeze challenge definitions and separate development from held-out source
families and transformations. Evaluate each added checker against P12 on the
same inputs. Public outcomes, engineering invariants, seeded defects, model
judgments and actual adjudication are separate evidence classes. Tuning on an
example removes it from independent acceptance evidence. No minimum legal
accuracy or percentage cost saving is established by the current pilot.

The initial acceptance set must include **shared-error cases**, where all model
readers make the same mistake, and clean controls, where an irrelevant formatting
change should not force another substantive review. Passing only disagreement
cases misses the central failure mode. Escalating everything fails the intended
useful-coverage criterion.

Measure missed seeded defects, unnecessary escalations, unresolved dependencies,
useful coverage, distinct material questions, provider calls and reviewer time
separately. Actual review-time savings require observed reviewer work; packet
count is an explanatory diagnostic. Declare the paired comparator, challenge
set, limits and uncertainty analysis before running a comparison. A few
circulars support descriptive findings, not a population-wide ranking.

## Resolution and future inputs

Each unresolved issue needs a specific next action: acquire an authority,
inspect another extraction, check a premise, generate a distinguishing scenario,
run a formal comparison, or repair a diagnosed translation stage. Reuse the
persistent call/round/issue accounting and retain failures. Justify new limits
before execution. At exhaustion, report attempted actions and open questions;
do not repeat a generic interpretation prompt until the majority agrees.

Changes to the circular, incorporated definitions, relevant bank fact bindings,
or model/prompt configuration trigger affected-control analysis and replay.
An unchanged source hash alone does not validate an old check after the method
changes. New source versions create successor investigations; they do not
rewrite old reports. The monitoring cadence and detection-latency target need
explicit operational settings and tests before deployment.

Some questions can be answered from retained official evidence and recorded
for reuse. Others need a fact owner or a narrow internal compliance decision.
An external expert becomes a proposed next step only when the record identifies
a material unresolved question, why it matters and which cheaper evidence paths
failed. Preparing that dossier authorizes no purchase or external communication.
Broad consultancy is not a gate for A1–A6.

Machine-supported issue closure and bank approval remain distinct. Record which
check resolves each discrepancy, with its version and limits. Do not fabricate
human approval, close an issue because its budget expires, or turn agreement
into a legal confidence score.

## Live allowance and comparative evaluation

The authorized live ceiling remains **100 total invocations**, including
failures: **41 used, 59 remaining**. This plan/audit revision uses none. A live
phase must declare its source question, complete-case budget, provider and
acceptance before spending the allowance. Existing Codex access can develop
different reading methods; shared-model errors remain an explicit risk.
Additional paid providers or private data are not assumed available.

After the components pass their discriminating cases, compare a single reading,
independent-role generation without search, and BFS/UCT with and without the
new checks. Give arms the same source access and resource allowance. Separate
retrieval gains from reasoning gains: do not supply one arm a missing definition
while denying it to another. Prioritize detection and useful coverage jointly,
then measure cost. Rewards and branch counts are not correctness scores.

Independent source-first annotations remain valuable for later effectiveness
evaluation. The existing API can support limited internal review or targeted
funded research if available; that does not imply a large consulting engagement
or manual adjudication of every reading. Candidate-exposed correspondence
packets are not blind annotations. Without true labels, report detected
inconsistencies and remaining uncertainty without an absolute English-error
rate claim.

## Decision and repair rules

| Event | Decision | Next action |
|---|---|---|
| A checker misses a mandatory omission or silently accepts stale authority | Reject that increment | Repair; retain failed evidence; refresh/review and rerun |
| Outputs agree but an independently extracted qualification is unaccounted for | Keep the semantic issue open | Reconcile the source obligation and affected candidates |
| Extra method increases calls/escalation without detecting the declared defects | Do not promote it as a better default | Revise or remove it after the predeclared comparison |
| A valid challenge reveals unsupported representation | Retain the reading and limitation | Extend defined semantics or report a narrow question |
| Required source is unavailable or corrupted | Stop dependent conclusions | Repair acquisition or retain the missing dependency; continue unrelated engineering |
| Resolution budget is exhausted | Report the material open question | Seek existing answers; consider narrow expert escalation where consequential |
| Independent labels are unavailable | Continue engineering and public/controlled validation | Limit the claim; do not invent accuracy or block all software work |

Each accepted phase must refresh this plan with actual findings. A failed
implementation or unhelpful current model candidate is first a repair signal;
rejecting the research direction needs evidence against its mechanism. The
next phase is A1/A2 specification and implementation, with the shared-exception-
omission challenge as an early diagnostic.
