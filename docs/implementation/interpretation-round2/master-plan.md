# Executable program: source-grounded interpretation search

The requested outcome is a working procedure that generates competing readings
from a source packet, expands and investigates them, preserves dissent and
uncertainty, and connects every executable candidate to Java verification and
the existing release controls. The previous E01–E09 increment did not deliver
this outcome: its members and repairs were supplied fixtures. This program
explicitly forbids counting a replay provider as evidence of English generation.

User authorization: implement, critically review and execute this program;
use fresh Codex sessions for live public-source generation. The authorized live allowance:
at most 100 invocations across the pilot, including failures, with no automatic
transport retries, 180 seconds per invocation and a 1,200-second run deadline.
These are conservative engineering bounds, not statistically chosen defaults.
No bank records, production changes, external human messages or legal approvals
are authorized or needed. Absolute absence of interpretation errors cannot be
established; the required behavior is to expose unsupported conclusions and keep
them from release, including when all models agree.

## Evidence contract and skeptical pre-execution audit

Question: does the product actually construct and investigate rival readings,
and do its evidence and release controls survive disagreement, shared omissions,
invalid encodings, interrupted calls, exhausted search and source changes?

Comparators: the existing scripted controller and its retained tests; hand-stated
engineering invariants; small enumerated argument frameworks and input domains;
independently executed Python/Java semantics. Development circulars are not a
blind legal-accuracy benchmark. A source-first annotation tool and paired
evaluation machinery will be built, but actual independent human annotations
cannot be manufactured by the implementing agent or another model.

Primary engineering acceptance: live generation consumes source text and no
supplied candidate answer; alternative hypotheses carry exact citations and
explicit distinctions; a real search tree records branch expansion, bounded
selection and evidence; formal disagreement is replayable; round-trip
reconstruction is isolated; every unsuccessful action and unexplored branch is
reported; all resulting unreviewed candidates remain release-blocked.

Promotion vetoes: missing mandatory dimensions, lost dissent, treating a string
match as semantic agreement, false legal probabilities, an unsupported solver
result counted as proof, omitted failed calls, stale source/review, a budget
overrun, forged citations, incorrect Java parity, or a required regression failure.
Repair triggers: any such engineering defect or a pilot result exposing missing
functionality. Fix the implementation and add a discriminating test before rerun.
Continuation vetoes: corrupt evidence, unavailable authorized model service after
a trusted probe, exhausted live allowance, or a prerequisite requiring actual
human authority. These stop the dependent experiment, not independent coding.
Runtime, branch counts, entropy and model agreement are explanatory diagnostics.
They never authorize release or establish legal accuracy.

Audit verdict before implementation: PASS WITH EXPLICIT LIMITS. Rejected plans
included merely adding model-shaped stubs; letting the model assign its own
passing score; pruning uncompiled readings as legally false; treating recovered
citations as resolved meaning; and calling repeated model votes independent
legal annotations. The revised phases below directly test these failure modes.
Model diversity remains unestablished when fresh contexts share one model.
Search completeness is bounded by a declared inventory, not all possible English
meanings. This limitation is carried into every terminal report.

## Implementation decisions and assumption audit

* Reuse immutable SQLite records, authenticated ownership, action reservations,
  source packet identities and release binding. Add a research search profile;
  existing fixture behavior must remain explicit and unchanged.
* Three independently prompted initial readings cover normative reading,
  formal reconstruction and adversarial alternatives. Each must account for
  scope, definitions, exception attachment, modality, time and dependencies.
  Counts are resource hypotheses; diagnostics expose unexplored dimensions.
* A candidate is a claim plus source quotes, explicit assumptions, a typed formal
  expression when expressible, and unresolved questions. A rejected encoding
  remains a visible interpretation with an encoding problem.
* Use deterministic breadth-first expansion as a transparent baseline and a
  bounded UCT option with explicit visits and backpropagated engineering evidence.
  UCT is investigation scheduling, not a probability or an optimality guarantee.
* Formal comparison is confined to a declared, feasible RuleIR domain. Dates and
  unsupported constructs produce explicit unsupported results. Finite scenario
  disagreement may still be exhibited without claiming domain-wide equivalence.
* Implement small argument graphs with grounded and bounded stable semantics.
  These answer a declared graph question, not the authority of its legal premises.
  This is a specified subset inspired by argumentation literature, not a complete
  ASPIC+ or Carneades implementation.
* Deterministically render supported formal expressions in controlled English,
  ask a fresh context to reconstruct them without the original expression, then
  compare. Agreement cannot establish fidelity to the original circular.
* The Codex adapter uses a fresh temporary working directory, read-only execution,
  ignored user/project configuration and rules, disabled shell/apps/web tools,
  structured output, bounded process lifetime and no automatic retries. Preserve
  the CLI version and requested model configuration; do not copy authentication.
* The search engine may retrieve only frozen, explicitly supplied local source
  units. Missing outside authorities become questions; model-provided URLs do
  not authorize downloads or execution.

Python 3.11, Java 17 and SQLite are inherited tested engineering choices. Fixed
resource ceilings prevent unbounded work; exceeding them must be a reported stop,
not silent truncation. Source parsing and business-fact definitions remain
reviewable assumptions even when every execution check passes.
