# Skeptical implementation review

The master is accepted for bounded execution after its automated review action
passes. The baseline is the preserved 32-case candidate; no answer labels are
introduced. Source availability and row counts remain descriptive. The code
does not turn a successful HTTP response into an applicable contract, a formal
proof into English correctness, or a source-dependent calculation into an actual
bank decision.

The supervisor has one entrypoint and a tested prefix rule. Its approved action
choices never accept arbitrary subprocess code. All execution uses argument
arrays, stable CPU imports and scoped outputs. The public downloader counts each
dispatch before running it, validates HTTPS hosts, does not follow redirects
implicitly, retains errors and rejects missing or altered bytes. The numerical
module rejects floats and undocumented effectiveness/currency assumptions.

The earlier failure pattern was mistaking final positive answers for valid
supporting witnesses. E5 therefore writes every applicable cash/mechanism quote
for contextual review. E6 refuses to advance on a rejected or unreviewed witness.
After an actual semantic patch, stale methods require review and full dependent
validation; newly frozen chronology makes inspected cases exposed. Metadata and
transport/derivative repairs are executable actions, and controller tests exercise
a failed attempt, executed repair, retained history and refreshed next plan.

Known limits are explicit. Deutsche arithmetic covers a stated allocation and cap
under supplied determinations, not a complete event settlement engine. Other
issues remain in an implementation queue. Missing private facts do not block
independent public-source and software phases, but they prohibit actual clearance.
The existing input-evidence and bank engine remain the authority for all fourteen
obligations. New contract applicability and whole-document language correspondence
require source review and may remain open after public retrieval.

Pre-mortem: a passing controller could still accept a misleading source selection,
use a circular legal interpretation, or overstate a small challenge. Check source
identity and edition before classification; inspect complete quotations and nearby
conditions; report family/exposure denominators and no statistical ranking. A
failed candidate triggers its causal repair. Only corruption or an exhausted
applicable resource stops dependent execution.

Approval boundary: the installed rule matches only the literal two-argument
runner prefix. A saved rule and operational approval are not evidence of correct
legal interpretation. No paid models, private retrieval, access certifications,
new dependencies, destructive cleanup or mutation of prior campaign evidence is
part of the approved execution.
