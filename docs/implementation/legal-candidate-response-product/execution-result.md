## What changed and why

Package modules now implement the reviewed alias and candidate schemas without
importing runner scripts. `response_profile` selects the option through
`CompleteInvestigation`, the scoped dispatcher and source/executable transports.
The profile constrains each pair to its own candidate's executable expressions
while retaining unavailable, blocked and uncertain judgments. Existing
validators check the expanded output; rejected raw output is preserved.

The actual setting is part of revision, journal and observation identities.
Changing it cannot silently reuse another method's evidence. The literal
response default remains in place. Candidate responses require executable
references v2 and literal input; readable input tables are rejected before
dispatch because their original-span integrity check is incompatible with the
shortened identities.

The strongest alternative explanation for the successful replay is also its
known limit: the local provider returned already validated judgments. That is

or stale journal reuse would overturn the engineering result; the content
comparison and adversarial tests address those failure modes. The weakest
remaining evidence is live applicability beyond the retained dataset. The result
neither rejects the interpretation program nor establishes legal correctness.
