## Review repairs actually executed

The first complete regression passed 845 tests before the automatic v2 controller
was added. Review found that reconciliation alone requested processing without
executing it. An opt-in local route now runs that procedure, while preserving the
legacy v1 route. The first controller diagnostic failed six checks because tuple
pair IDs changed shape after JSON serialization; the normalized binding repaired
resume. The failed diagnostic and executing source remain under `controller-debug`.

A stronger counterexample then showed that two successful responses from one
perspective could be counted while the other repeatedly failed validation. The
added test reproduced that defect: the old controller stopped after four calls.
The repair requires valid responses from both declared perspectives, continues
to the three-round limit when one is missing, and reports the missing perspective
explicitly. That counterexample and the superseded code are retained under
`pre-perspective-repair`. The in-progress second regression was intentionally
stopped after this finding; action 11 retains its logs and failed execution
record. It is not a completed passing suite. The final attempt reruns every
phase with the repaired code and the original limits.

The final focused suite passes 66 checks. The retained N1 worked example executes
six scripted local invocations in three rounds, preserves all six proposals and
reports uncertainty. These scripted responses are not additional legal judgments
or independent votes. The controller refuses live providers; the allowance
remains exhausted and unchanged.

Final acceptance is action 17's complete 855-test run. The two existing
FastAPI/Starlette deprecation warnings remain; they are not test failures. The
master consumed 18 phase reservations in total, three per phase, retaining the
earlier runs and stopped regression. Completed evidence replays under the same
