# Single-authority implementation and execution result

The prospectus worktree now has one active work-selection authority. Revision
3 of `program.json`, immutable revisions and the hash-chained event history
govern admission, fixed worker execution, retained agent work, reviewed
continuation, refresh and interruption recovery. The generated reset/status
views agree with that state. This completes the bounded authority cutover and
real-transition exercise in the reviewed implementation plan. It does not
complete the remaining prospectus delivery program.

The design review prevented migration from dropping obligations or turning
test totals into closure. Real execution then exposed a detached-worker
lifetime bug and a byte-versus-JSON hash mismatch; both are retained with
their failed attempts. Final code tracing reproduced two further defects in
partial-work continuation and supplied-external-evidence admission. Those were
repaired under the cumulative revision history. Ordinary file edits and all
local runs required no new approvals; the host allow-list was not changed.

The final snapshot is `verification/final-001.json`: it checks 70 files across
retained output manifests, the original admissions and history, current
specification, 41 passing tests, Python syntax and `git diff --check`. It is a
snapshot, not an immutable seal over the live program. Commands, environment,
git identity, code/test/document hashes and elapsed time are retained there.
No stochastic ranking is involved; durations are descriptive and seeds are
not applicable.

Remaining authority integration: only the first two tasks have automatic
handlers and substantive validators. Other admitted tasks run as agent work
or external review and need their task-specific validators before acceptance.
The repaired continuation path allows that work without silently resetting
budgets. Shared controller/worker method hashes are deliberately conservative;
future validator changes may require reviewed revalidation of earlier tasks.
The CLI's zero exit code alone must never be interpreted as task completion.

Remaining product work includes the isolated native build/patch, fresh callback
ABI execution and full downstream comparison, broader real layout families,
Portuguese 2008 report consumption, original-source authority and dates,
fourteen onward dependencies, BASF source/meaning tasks, automatic relations,
financial conventions, native confinement, portability and genuine independent
readings. ACTUS and CDM retain their explicit prerequisites and dispositions.
All four completion streams and whole-program completion remain false.

The next selected task is `portuguese-2008`; no worker is left running. Its
retained Portuguese PDF is already available, and the layout package has a
native P1 of that source. The next task must inspect the actual audit pages,

Post-run red-team: the strongest remaining objection is that a controller can
organize missing work while appearing to solve it. The explicit unaccepted
partial states, absence of whole-program completion and real source artifacts
address that risk within this package. They do not eliminate the substantive
work. Evidence of an unsupported COMPLETE transition, lost obligation,
corrupted retained record or duplicate worker would overturn acceptance of
the corresponding controller behavior.
