# Design required before another native-binding admission

This is a design, not a new native allowance. All twelve native-binding
admissions and failed/rejected attempts remain counted. No native call,
installation, permission change or edit to a sealed attempt occurs here.

The current driver fixes `HERE` to attempt008 and its preparation requires
current production to equal attempt006. The validator's `current_methods`
and `evidence` also embed those historical contexts. Re-running either cannot
answer whether fresh extraction with today's methods is correct. The shared
verification wrapper writes no final manifest when validation raises after
`started.json`; this independently explains unrecordable attempts.

The next engineering proposal must contain all of the following before any
native execution is admitted:

1. A new driver accepting only the current authority's admitted output path,
   validating admission/binding before writes, refusing any historical folder,
   and using exclusive files plus the existing process ledger. Historical
   attempt006/008 files are baseline inputs only.
2. A current method inventory including every successor module, the new
   initial-agent module, driver, validator and relevant tests. Freeze current
   snapshots and compare each with the working file before and after runs.
   Validate historical snapshots against their historical hashes separately;
   do not demand that current code equal those snapshots or replace their
   inventory hashes with current ones.
3. An explicit supported-cell matrix: original 2009 default/fresh/retained
   routes and original 2010 fresh/retained routes, with original PDF identity,
   request identity and exact native receipt expectations per route. Inventory
   actual executable/library/environment/negative-lookup dependencies and
   counts from retained receipts before proposing any numeric call allowance.
   Do not invent a default2010 arm or silently drop a failed arm.
4. Before the matrix, a source-only fresh canary on one original document.
   Preserve raw P1 and extraction receipts. Check full occurrence geometry,
   punctuation, header/table boundaries and original worker/source identity
   against the protected P1. Any difference is retained and reviewed before
   widening the run; source text equality alone is insufficient.
5. On every supported cell, build current P2–P5 and complete answers. Compare
   semantics after explicitly enumerated provenance differences only; retain
   raw and compared representations. Questions, dependencies, unknown geometry,
   assembly, source maps, source-report qualifications and permission flags
   cannot be discarded. The retained-P1 preflight is preparation, not a
   substitute for this end-to-end evidence.
6. Execute changed/missing file, missing lookup, environment, race and outside
   boundary cases against the new driver/validator. Check that refusal is for
   the intended reason and that sealed bytes remain unchanged. Demonstrate
   injected validator failure still creates result/error/outputs before using
   the wrapper for a live campaign.
7. Specify cumulative call reservations, wall/storage limits, one bounded
   repair and its return to the substantive source task. A new attempt name
   does not reset spent counts. Use one-second yields and poll the existing
   session. Audit full manifests and actual RECORD/ACCEPT history afterward.

The primary engineering criterion is current end-to-end evidence for every
declared supported cell with exact source/method/receipt identity and actual
refusal controls. Missing bindings, invalid receipts, unexplained output
differences, silent extra native calls or failed failure-finalization veto the
campaign. Runtime and successful old replay are explanatory only. Passing
cannot establish universal dependency closure, general package suitability,
independent legal acceptance or completeness of the financial interpretation.

Local preparation can continue by tracing cell consumers and finishing the
source-reading repair. The native proposal must be reviewed for a substantive
need and an exact finite call budget before a thirteenth admission is considered.
