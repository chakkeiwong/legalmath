# Multilingual and correction recovery result

All eight actual closure-executor states equal separate clean subprocess
recomputation. The baseline preserves the original BES Portuguese page images
and source units. Changing the selected environment invalidates the old receipt
before the recovery marker changes. Missing Portuguese model data, an incorrect
source-page image identity and an invalid correction interval each cause the
expected rejection. Restoration returns the complete original output. The
retained focused controller and correction checks also pass.

The reproduced implementation defect was environment-only receipt reuse. The
controller now includes hashes of selected runtime environment values and the
effective OCR interpreter file. This is a finite binding repair. The actual
executor and clean comparator share the same product implementation, so their
agreement establishes recovery consistency, not independent legal correctness.
The correction case uses a retained synthetic scan and an unchanged-text map;
it does not establish a new human reading of the Portuguese source.

The strongest alternative explanation is shared implementation error in both
executions. Original image/source-unit checks constrain that explanation for
the protected Portuguese baseline; they do not eliminate semantic errors.
An unequal restoration, changed source identity or accepted malformed input
would overturn the corresponding engineering result. The result does not
reject OCR or multilingual processing as a research direction.
