# Current live campaign implementation audit

The candidate uses two new owned snapshot manifests, exactly equal to006/008,
instead of rewriting historical receipt identities for a merged manifest. New
snapshot paths share hard links only with other blobs in the same new attempt;
no blob is linked to old evidence. The mutable probe sentinel belongs only to
the new2009 snapshot. Actual runtime receipts can therefore compare exactly to
the protected historical receipts. Every unexpected difference is retained and
refused. This is stricter than removing enumerated provenance fields and avoids
an unproved normalization rule.

Source stages use real source_product, SourceRuntime and native execution. The
recorded-byte adapter is imported only for its request/downstream helper
functions and is never installed in the live driver. The explicit task grant
must exactly name five routes,11 reservations, historical floor50,zero repair
reservations,512MiB cap and120s stages. Without that grant all live stage writes
refuse. Current admission and output paths are checked before writes.

Each source stage permits at most two supervised starts and checks the expected
cumulative position. The first2009-fresh route is the sole canary. All later
routes require it to pass. Eight actual prelaunch controls run under subprocess
prohibition. Only one boundary call is allowed after all ten source calls.
Spawn failures consume their reservation and seal failure evidence. Downstream
construction, consumers, test runs and final validation cannot launch native
workers. Finite validator rechecks full source/answer parents and actually runs
the current consumer for every route; a recomputed answer hash alone cannot pass.

The current validator preserves old method snapshots but binds every current
prospectus Python method, driver, wrapper and test independently. The proposed
registry change is retained for later reviewed application; it is not applied
under this preparation admission. A final live test report must be made after
that change, because shared authority method bytes then change.

Failed-stage finalization handles Python exceptions, KeyboardInterrupt and
cooperative SIGTERM/ALRM. SIGKILL, power loss and filesystem failure remain
outside its guarantee. The stage ledger counts explicit Popen reservations,
not all worker-internal descendants. A finite Linux/CPU pass remains separate
from independent interpretation, portability and universal dependency closure.
