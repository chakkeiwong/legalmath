# Recovered table text and its limits

The existing strict v1 hybrid path retained **2,006 OCR words**: 523 on p60,
1,202 on p162 and 281 on p163. The actual P1 retains 33,221 source units across
the introducer and 175-page report. All worker output, selected page images,
geometry and raw text remain available. This count is explanatory, not an
accuracy score or completion criterion.

The rendered cash-flow statement p60 shows end-of-period cash equivalents of
1,847,043 and 794,606 (thousands of euro); both values are present in the raw
OCR beside the correct row label and again in the bottom total. The p163 image
shows loan totals 53,355 and 50,531 (million euro) and 100.00% for each column;
the corresponding OCR total line retains these values. These are finite visual
spot checks, not a review of every number or proof of table-cell associations.
Page 162 contains two sector-risk tables with distinct 30 June 2010 and
31 December 2009 headings. Its complete word list remains raw evidence.

OCR noise includes decorative-header symbols, inconsistent numeric spacing and
punctuation in subtotal lines. No normalization of financial values or automatic
calculation is justified by this run. The final service reading must preserve
the table words while reporting its semantic identity as unknown. Further
table work needs explicit row/column/date/unit associations, image comparison,
and arithmetic checks under a declared financial target.

The original missing-table finding was an extraction-selection issue; the
installed OCR path can recover source words under the existing profile. This
does not establish a fundamental package limitation. The missing interim-review
classification is separately attributable to the local report model.
