# Tighten the reviewed Scope form before sealing

The first implementation passed78 focused controls and the original-reading,
matched current-consumer and eight omission-consumer checks. Its methods and
results remain retained. A second skeptical check found that recognition
required only the first Scope sentence. A source variant with a truncated Scope
could therefore receive conditional review support. The retained negative test
reproduces that failure. An added Scope qualification already withheld support
when omitted from the supplied span, but was not rejected as an unreviewed form.

The repaired recognizer requires the whole inspected Scope wording, including
inquiries, analytical procedures, substantive tests on material non-current
transactions and the reasonable basis sentence. This is deliberately a narrow
reviewed English BES form. A different procedure or qualification remains
incomplete pending its own substantive review; the pattern cannot establish
arbitrary report semantics. This is preferable to certifying an unknown form.

The first positive/negative consumer stages are not repeated or rewritten.
After this implementation change, revalidate their retained products through
the current consumer and retain a new method-bound validation. Additional
source-variant consumers check the Scope omissions. The original audit
counterexample and all source bindings stay protected.

Failures remain failures: tests-first.xml records a test response-shape error;
tests-scope-redteam.xml records two failed assertions of the stricter check.
Neither failure establishes a package defect or invalidates the source.
The revised check is a bounded repair within this admission, not a new budget.
