# Real table and rotated-label development cases retained

The actual P1/layout consumer preserves all seven frozen regions on the two
new source pages: the reporting unit and date, three financing rows with their
complete coupon qualifiers, and two rotated Latin labels. All six adverse
controls refuse projection. The retained P1 products still report unknown
publication and knowledge dates. No source fact was filled in merely to make
the consumer run.

The 768-page native-text scan nominates many financial tables and rotated
labels. The inspected 2009 page 136 is a real financing table; the inspected
2008 page 24 contains rotated Latin labels in an organization diagram. No
whole-page PDF rotation, native vertical-writing flag or right-to-left Unicode
character was found in the native text of these three sources. Image-only
text and other retained documents were not exhausted, so this is a bounded
search result, not a universal absence claim. True vertical writing,
bidirectional text, whole-page rotation and unexposed independently reviewed
readings remain missing.

The scan took 1.70 seconds and the actual P1 consumer took 17.86 seconds;
durations are descriptive. Full command/environment/source/method evidence is
in `source-nominations.json`, `page-selection.json` and `consumer-result.json`.
The source-reading contract and pre-run skeptical review are in `WORK-PLAN.md`
and `READING-REVIEW.md`. Seeds do not apply; GPU devices were intentionally
hidden.

Post-run red-team: the strongest alternative explanation for success is that
the supplied rectangles already solve most of the layout task. That is true
and bounds this result. A candidate must discover or consume its own geometry
on the same frozen readings before automatic capability can be judged. The
weakest evidence is family coverage and reading independence. An altered
coupon qualifier, wrong row, source mismatch or omitted character in the
matched consumer would overturn the corresponding finite success.

The authority retains this package as `RESULT_RECORDED`. Its generic handler
does not confer acceptance; no task-specific validator has been implemented
for complete independent layout coverage. This is an explicit remaining
implementation requirement, separate from the missing source families.
