# Required table regions are now explicit consumer gaps

The optional declared-region coverage API identifies all four visible table
regions on page84 as REQUIRED_CONTENT_UNAVAILABLE. The retained native source
contains three nonspace characters, `6` and `84`, on that page. Those characters
do not represent any of the four Time to Default/Prepayment Rates tables. The
report retains each region's reason, displayed-page rectangle, original PDF hash,
render hash and graph/inventory identities. No table cell has been transcribed,
and grey areas have not been interpreted as zero.

The positive HETA comparison projects the full corrected English maturity
paragraph, including `The decree of`, the published-edict qualification and
`will therefore not become due and payable`. All supplied nonspace characters
match retained source words through the actual layout consumer. The original
omitted-words failure from002 remains historical evidence. Matching this declared
paragraph does not establish complete HETA page or document coverage.

The278-page source's exact retained P1 was consumed by current construction,
interpretation, law and financial stages without new extraction. Its full
baseline answer and the coverage wrapper answer agree exactly. Q1/Q2 remain
UNKNOWN and Q3 PARTIAL; the source and10418 original units are unchanged.
The same full-answer equality holds for the retained HETA P1–P5. Every output
keeps page_complete, document_complete and may_claim_coverage false.

Thirty-seven focused tests pass. Eight actual-data controls either refuse or
remain explicitly unresolved: missing/duplicate regions, foreign page, changed
render, unsupported independent-review claim, omitted negation, omitted edict
qualification and a rectangle intersecting only part of a word. The last case
checks a real weakness of center-point selection: a word can have its center
inside a region while part of the word lies outside. The coverage API retains
that partial intersection instead of presenting a complete projection.

The strongest alternative explanation for a seemingly complete region result
is an incomplete supplied inventory. The API therefore makes no whole-page
claim even when every declared reading matches. File hashes also cannot prove
publisher authenticity or render fidelity. A changed source, a contradicted
region reading or an omitted required region would require renewed review.
There is no stochastic comparison or supported ranking of extraction packages.

This repairs our reporting and coverage interface. The underlying native-only
extraction still misses the table text; no OCR package was tested or rejected.
The new module is optional and its installed use remains unevaluated. All six
stages completed below120seconds; no native worker, GPU framework, model call,
network request or installation ran. No local repair was needed.
