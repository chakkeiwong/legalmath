# What this continuation implements

The product generates and investigates alternative interpretations, preserves
source evidence and compiles explicit candidates to Java. Its evidence has three
distinct targets: retained English text and applicability, a proposed interpretation
and its formal expression, and generated Java behavior. A passed Java replay
checks the third target. It cannot settle either of the first two.

| Procedure | Executed implementation | Remaining limit |
| --- | --- | --- |
| Competing hypotheses | Existing isolated generation, breadth-first/UCT investigation, retained frontier and bounded repairs | Fresh contexts can share errors; finite search is not exhaustive English interpretation |
| Source redundancy | Independent claim/qualification inventories, two text extractions, hash-bound authority editions and bounded context selection | OCR is not implemented; image warnings and unacquired definitions remain unresolved |
| Complete controls | Explicit source-bound component groups, alternative Cartesian selections, namespaced Java rules and fact mappings | Group assignment is a proposed specification; unmodeled interactions and whole-circular coverage remain unproved |
| Discriminating questions | Concrete source-bound scenarios replayed through original Python/Java programs; scores count separated pairs | Exact declared comparability is required; unaligned fact meanings cannot earn an unconditional score |
| Shared mistakes | Source-inventory checks retain priority even at zero behavioral separation; source/code mutation challenges remain available | Absence of detected errors is not a bound on future omissions |
| Arguments and cases | Existing typed attacks plus a catalog-bound official-example registry, analogies, distinctions and countercase constructors | No general judicial ratio extraction, legal priority determination or full AGATHA/CATO implementation |
| Bounded automatic repair | Per-issue repair counts, action/input identities, call/deadline limits, retained failures, refresh and review between implementation phases | Exhaustion reports uncertainty; it cannot manufacture a correct answer |
| Evaluation | Frozen four-arm dispatch, hidden finite-scenario scoring, family-level paired counts and conditional uncertainty bounds | Only scripted development acceptance has run; empirical accuracy and review-cost reduction remain unmeasured |
| Continuing checks | Immutable source/registry revisions, bounded scheduler, affected-control invalidation, Java-host package and source-update exercise | Institution registry, fact ownership, release identities and staging access are not supplied |

The real B1–B3 evidence is public SFC material. The 2010 FAQ page currently
contains updated answers, so its historical use is conditional. Two branches of
Question 1 are one source family, not independent precedents. The 23EC46
source-to-example comparison preserves the difference between applicability of
paragraph 3.11 and a fully resolved prohibition after exceptions.

Every unresolved question should carry its exact source, surviving interpretations,
affected controls and attempted automated checks. Internal fact owners or compliance
staff can answer a narrow residual question. No implemented procedure automatically
commissions external legal consultancy. Nor does the software promise to remove
all legal judgment: the current engineering evidence does not prove that English
interpretations are correct, exhaustive or robust against every future change.
