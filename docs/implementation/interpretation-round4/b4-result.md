# B4: harness accepted; empirical comparison blocked by budget

The fixed B4 acceptance passed 178 tests and executed eight scripted jobs: a
clean/altered pair through single-reader, isolated-reader, search and assurance
adapters, followed by hidden Java scenario scoring. Every arm/case is retained;
none is missing. The real allowance check refused live dispatch before any model
initialization or call. The ledger remains 78/100 consumed, 22 available. The
two-case eight-call-per-arm design reserves 64 calls. More importantly, these are
development fixtures; additional calls alone would not make them held out.

The reported simultaneous intervals span the full possible difference range in
this one-family exercise. The implemented calculation and its derivation appear
in `b4-design-audit.md`. The deliberately worse-treatment and all-abstain tests
prevent omitted errors or abstention from looking like useful improvement.

The strongest alternative explanation for apparently favorable fixture counts
is that the developer wrote both the controlled inputs and scripted answers.
They validate the dispatch/scoring/accounting code only. No natural-language
accuracy inference is made. The live-call shortage is a continuation veto for
the live comparison, not for the implementation direction or B5 engineering.
