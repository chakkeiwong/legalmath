choosing another implementation attempt.

## Proposed remedy within the existing product task

The recommended design is staged evidence review followed by a complete answer.
Keep the existing single-request consumer as the comparator for small dossiers.
Do not rebuild investigation, the source readers, argument engines or coverage
controller. This is a substantive method change: model summaries can lose legal
qualifications even when every identifier is accounted for. That risk must be
tested and disclosed, not hidden behind coverage totals.

The proposed work package has these finite steps:

1. **Define the evidence boundary before implementation.** Bind a fresh verified
   dossier, its active revision, original questions and source qualifications.
   Preserve the entire raw investigation in the evidence archive. Build a
   deterministic registry for readings, judgments, concerns, criticism and tool
   checks. Exact duplicates may share storage, with every occurrence and role
   retained. Keep every reading, including null formalizations. Distinguish
   substantive evidence from file inventories and execution receipts; document
   precisely which operational fields stay outside model input. Never present
   an unreviewed selection as the entire dossier.
2. **Build bounded review requests.** Preserve full source access, original
   questions and the same source qualifications in both arms. Supply enough
   candidate, claim, role and attack context to interpret every assigned record;
   a detached rationale or JSON fragment is not an adequate review unit. Each
   record must have a deterministic assignment and reference. Use actual encoded
   bytes to admit a batch before dispatch, including the fixed context cost.
   A record that cannot fit with necessary context stops the attempt; it is not
   split across legally meaningless fragments or dropped.
3. **Connect the reviews to answer synthesis.** Each review must distinguish
   source support, inference, contrary evidence, unresolved premises and tool
   limitations, with exact source references and assigned-record accounting.
   Check cross-batch exceptions and attack dependencies explicitly. The final
   answer receives the source packet, original questions, every reading's
   disposition and the reviewed findings, with a trace to every earlier review
   and the original evidence. A summary's explicit coverage is not proof that
   its substance is faithful. If the final request or review output exceeds the
   declared bound, retain it and stop; no implicit recursion, summary truncation
   or automatic budget growth. The exact reduction design and ceiling must pass
   the static stress case before any live proposal is priced.
4. **Qualify locally with the right comparators.** First exercise the actual
   consumer with a fresh current-code `CompleteInvestigation` dossier and
   `ProductToolBackend`, using an explicitly synthetic provider. Then use the
   retained full-scale evidence solely as a capacity/accounting stress case,
   with no claim that it is today's valid live dossier. Verify all 984 judgments
   and 473 concerns survive the registry, batch assignment and raw reconstruction.
   Negative controls must reject missing/duplicate/corrupted records, stale
   revisions, omitted unformalized readings, missing source qualifications,
   detached graph dependencies, oversized requests and lost contrary evidence
   in any *explicitly checkable* part of the response. Include a deliberately
   unhelpful but structurally valid summary to demonstrate the semantic limit.
   Preserve evidence of that limit rather than describing schema checks as legal
   fidelity. No live answer-quality conclusion follows from these fixtures.
5. **Freeze a complete comparison only after those checks.** Use the actual
   investigation and answer route in both arms, one without the optional backend
   and one with explicit backend injection. Freeze method, model/service route,
   full source, qualifications, original questions, all stage ceilings, a global
   deadline and the assessment rubric. Count investigation, question assignment,
   both scoped perspectives, evidence-review batches, cross-batch review and
   final synthesis. A capacity failure is a retained result, not permission to
   drop pairs. Use a fresh independent grant anchored to all relevant historical
   ledgers, without falsely marking an expired grant exhausted. Request live
   resources and any narrow execution approval together only when this invocation
   is concrete. Custom-route charges must be established or explicitly accepted
   as unknown; public list prices cannot supply that missing fact.
6. **Assess the complete answers before expanding.** Apply the original P10 and
   evidence-sufficiency rubric and trace each apparent tool contribution to the
   final answer. Review summaries against the retained contrary passages as well
   as checking their identifiers. Missing client facts permit conditional
   answers. Tool agreement never supplies the legal warrant. An unchanged or
   worse answer is reportable; this first pair supports a descriptive case study,
   not a tool ranking, general English accuracy or closure of the mission.

Two details of the old rubric also need correction. First, the ten-unit
entitlement with two matching zero entries is an assessor's counterexample to
an unconditional inference that reconciliation proves accuracy. It was not
stipulated in the two original questions. Do not penalize a model for failing
to mention those unstated numbers. Either use it only to test the logic of the
answer or explicitly supply the same hypothetical facts to both arms and record
that additional input. The recommended pilot uses it as an assessor check.
Second, source qualifications must reach the investigation's early source
reasoning as well as the final consumer. The prepared roots carry reconstruction
metadata, but code tracing has not established that those extra root fields
reach the early model requests. The local qualification must check actual
request bytes rather than infer delivery from a prepared file.

## Research intent and evidence contract for the remedy

| Item | Required interpretation |
|---|---|
| Main question | Can the actual product produce a complete source-grounded answer while considering a dossier larger than one bounded request? |
| Mechanism | Explicit evidence assignment, bounded source-aware reviews, cross-batch reasoning and traced answer synthesis |
| Comparator | Existing single-request consumer; later legal comparison uses identical staged method with optional backend absent/present |
| Engineering pass criterion | Fresh actual dossier connection plus complete retained-evidence accounting and bounded requests at the retained stress scale |
| Legal pass criterion | The original source-grounded P10/evidence answer rubric, reviewed against raw evidence and contrary readings |
| Promotion veto | Lost decisive qualification, trigger substitution, unsupported legal warrant, unformalized reading hidden, unequal sources or inference from tool PASS to legal truth |
| Continuation veto | Corrupt/stale evidence, necessary context that cannot fit, unavailable route, missing accounting, exhausted declared effort/call/deadline bound |
| Repair trigger | A reproduced failure that blocks this exact complete-answer comparison; it consumes the specifically reviewed engineering attempt |
| Explanatory only | Test totals, invocation counts, compression ratio, latency and the number of populated review fields |
| Unsupported conclusions | Full tool evaluation, legal entailment from structural validation, statistically supported superiority or general legal-product readiness |

| Material choice | Provenance/status | Failure mode | Earliest check |
|---|---|---|---|
| 200,000-byte request ceiling | Existing enforced setting; retained baseline | Source fits but generated evidence does not | Measure every complete request before reserving a call |
| Staged source-aware review | Proposed hypothesis, not an established default | Local summaries lose cross-record exceptions or legal force | Counterexample spanning two assigned batches; inspect raw-to-summary-to-answer trace |
| Full source and qualifications | Existing source preparation, with unresolved applicability/extraction | Source selection is represented as complete current authority | Inspect actual first inventory request and final synthesis request |
| Exact record accounting | Proposed engineering invariant | Legally empty summaries still account for all IDs | Deliberately empty-meaning positive control; keep legal acceptance separate |
| Same configured model/route | Current local configuration; pricing unknown | Route drift or unfair model comparison | Freeze a credential-free route identity and verify before each dispatch |
| One pair before a wider matrix | Existing pilot's descriptive scope | Stochastic variation mistaken for benefit | No ranking; assess failures and answer changes case by case |

Pre-mortem: the most dangerous apparent success is complete accounting with a
summary that drops the only contrary rule. The cheapest discriminating check is
a cross-batch qualification whose omission changes the answer, followed by
source review of the actual summary. A size failure may instead reflect a poor
representation; it is not evidence that legal reasoning or the tools are futile.

Skeptical audit of this remedy: **PASS AS A PROPOSED BOUNDED REPAIR; IMPLEMENTATION
AND LIVE READINESS NOT ESTABLISHED**. It addresses the reproduced answer-capacity
failure and preserves the original target. It avoids weak historical comparators,
has explicit stops, separates process checks from legal acceptance, and names the
new semantic compression risk. No model comparison, provider price or final
payload is yet qualified. No second engineering attempt has been admitted.
