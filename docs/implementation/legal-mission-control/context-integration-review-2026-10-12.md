# Context integration: skeptical review and bounded correction

The revised capacity plan passes review for a local engineering package, with
no model calls or legal promotion. Its comparator is the retained original
regulatory envelope, not a small synthetic replacement. Complete source and
requirement delivery, exact reconstruction, bounded requests and failure
isolation are the engineering criteria. Legal interpretation remains a separate
source-reviewed outcome. The 120-minute package, one correction cycle and
historical 41-call ledger are unchanged.

Initial code review and focused controls exposed two implementation defects:
repeated passages could be mapped to the wrong occurrence, and a mutable batch
list changed the response schema after packet measurement. Both were corrected
before the original-input rehearsal. The review also required reconstruction
of every original field, persisted product-level failure reporting, and rejection
of stale or incomplete footnote links. The resulting 27 controls passed.

The first original-input rehearsal preserved 55 units as 71 chunks, all 46
obligations, 35 readings and 12 conditional cases. It delivered 86 reading and
43 dependency packets with scripted unresolved responses and exercised the real
LlamaIndex hierarchy in 11 calls. No live interpretation was attempted.

The rehearsal did **not** pass the expanded-retrieval candidate: all four expanded
question requests exceeded the declared capacity. Nine footnote links in the
second circular also remained unresolved. Those are candidate failures, not
evidence against bounded context processing. The program retained the failures
and completed its independent checks; 82 existing mission/product tests passed.

Root causes are specific. Expansion selected every chunk in a retrieved source
unit and its neighboring units. A unit containing almost a whole circular could
therefore restore the overload. Separately, a locator index whose unit contains
many paragraphs cannot assign one paragraph label to that entire unit. Rejecting
it is sound, but original indexed paragraph text can still locate an exact span.

The single declared correction cycle will expand around adjacent **chunks** in
document order, while preserving the same retrieval hits and request limits.
Footnote endpoints will use unique exact indexed text occurrences, joined across
source-unit boundaries only when their source identity and offsets prove
contiguity. Dependency packets will select chunks intersecting those spans.
Missing or repeated occurrences stay unresolved. The source store is unchanged;
no source is shortened or silently dropped to make a packet fit.

Pre-correction audit: **PASS**. This tests the recorded failure mechanism without
changing the baseline, budgets, questions or criterion. Negative controls must
reject stale indexes, incomplete endpoints, ambiguity and fabricated quotations.
The original attempt and its source code remain retained; one correction directory
does not create another allowance. If this correction still fails, retain its
failure and finish independent documentation and assessment rather than launch
another repair. Tokenizer/service equivalence, complete corpus acquisition and
source-reviewed answer quality remain unqualified even if the local screen passes.

The raw retained envelope is 375,247 UTF-8 bytes. The earlier 353,561-byte number
measures the v2 logical compaction of that envelope. The unchanged shared-context
comparator measures 252,110 bytes after canonical reload. These are distinct
representations, not conflicting measurements of one serialized request.

## Post-correction review

The correction passes the declared local screen. All eight retrieval arms fit;
all 52 explicit bridges are materialized without missing endpoints; the full
retained envelope reconstructs exactly. The largest measured packet is 40,234
bytes / 9,747 local tokens. All 31 focused controls pass. The real hierarchy
contracts from 17,263 input tokens across leaves to 160 tokens across its next
level, using 11 scripted completions. These summaries deliberately say unresolved;
the contraction is a mechanism check, not evidence that legal distinctions survive.

The installed 0.14.25 implementation was inspected at its actual token splitter,
metadata-replacement and recursive synthesis methods. `TokenTextSplitter` keeps
whitespace when requested and may tolerate an oversized indivisible split; our
boundary rejects such a chunk. `TreeSummarize` recursively repacks model outputs;
our adapter checks each prompt/output, finite calls and strict level contraction.
The rank-bm25 0.2.2 scoring implementation was inspected as well.

Remaining material choices are explicitly baseline hypotheses: BM25 inherits
`k1=1.5`, `b=0.75`, `epsilon=0.25`; lexical terms use lowercase Unicode word
characters; retrieval uses four hits and one neighboring chunk on each side.
Eight records per reading request, 12,000 input tokens, 3,000 output tokens and
512 local request attempts are convenience limits. They have passed mechanical
fit/coverage controls, not a target-specific semantic or cost comparison. The
800/400 split is likewise unpromoted. The two scripted passes verify destinations,
not independence of two actual readers.

The first run's V2 success flag described source delivery too broadly: expanded
retrieval had failed and nine links were unresolved. The corrected runner now
requires all comparison arms and explicit endpoints before V2 can succeed. The
first flag/result is retained as historical evidence and is not a candidate pass.
This is an acceptance-reporting correction within the same declared cycle.

Q1 now has eight actual source-reading requests and eight empty reviewer templates.
Reviewer input reserves candidate output. The smallest proposed candidate output
cap is 1,761 tokens; exact serialization and provider overhead still require runtime
checks. This is a planning hypothesis for a canary, not permission to shorten a
legal answer. A failed cap retains the failure and blocks only that arm. The earlier
uniform 3,000-token draft does not by itself establish that a later review fits.

Post-run verdict: **PASS for local source-preserving capacity integration;
NOT QUALIFIED for live legal answers or complete tool integration.** The strongest
alternative explanation for earlier legal failures remains missing extraction,
entailment or contrary reasoning. Every passage fitting would not reject that
explanation. The weakest evidence is semantic preservation: all completions here
were scripted. A live answer omitting a remote qualification would overturn any
attempt to promote this local screen to legal efficacy. There is no statistically
supported method ranking, default promotion or newly fulfilled legal obligation.
