These failures locate two integration defects more precisely. First, the provider
schema allowed arbitrary strings for supplied case facts and tool keys while the
consumer required exact values. The prompt did not make those invariants explicit.
Second, the generated argument graph treated competing interpretations as attacks
without satisfying their logical relation. The installed engines did not create
that error: they never received a valid graph. Passing an XML, Prolog or argument
engine check would still leave source warrant unproved.

Executor inspection of the raw baseline and BM25 responses finds the previously
missing P11 condition, both P14 axes, relevant-incorporation distinction and
reconciliation counterexample. That is evidence about those passages, not a
validated matched comparison. Case-name leakage also deserves attention: the
baseline and LegalRuleML secondary-copy conclusions refer to H, although only the
shared-error case names H. The independent source review in the recovery must
check actual prose as well as copied premise fields.
