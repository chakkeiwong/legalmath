## What changed

Numbered assertions now bind the exact response field to a document index and
delivered quotation. Cross-document label pooling and borrowing a citation from
another field are rejected. Correct text attribution still does not prove that
the text supports the asserted proposition; fresh legal review remains required.

The product now collects source readers' discovered dependencies, deduplicates
them, retrieves relevant source context and performs one bounded analysis round
per question. Proposed resolutions and unresolved links remain distinct. Fresh
within-question interaction reviews check for lost conditions and exceptions.
The per-question bound is 32 dependency requests; chained or exhausted work
remains explicit. Retrieval hits cannot establish a resolved legal link.

One optional correction is available after complete, valid, source-supported
adverse reviews. It preserves the original answer and reviews, uses the same
source identity and requires fresh source, requirement and interaction reviews.
Invalid, failed or unresolved reviews do not trigger correction. The default
remains zero until a current campaign explicitly budgets one.

Native identities now hash selected installed package contents, schema trees,
native libraries and parser sources, detecting edits, additions and deletions.
This is a declared dependency scope, not whole-host attestation. All six native
identities were stable across the actual native executions.

Compact generated responses retain the 3,000-token / 24,000-byte limits. Exact
local quotation expansion has separate finite 250,000-token / 2,000,000-byte
bounds. Repeated input quotations use lossless source slices; requirement
observations and unsupported quotations remain unchanged. The next complete
request is measured again before dispatch.
