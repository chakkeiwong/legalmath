# Mission-control review

9 October 2026. This is an executor self-review, not independent legal review.

Before implementation, the governing plan rejected another broad coverage runner.
It selected a small read-only admission control and a fixed substantive queue.
The current setup does not evaluate tools again, retrieve new authorities, run
models, or claim a legal advance. The prior dossiers are the starting evidence.

The implementation audit identified these possible failures before testing:

| Failure | Repair/decision |
|---|---|
| A field saying PASS could impersonate result evidence. | Require actual worktree file/hash references, verify bytes and reject path escapes. Their relevance still needs substantive review. |
| A tool could be called integrated on code or scripted examples alone. | Require all seven evidence stages, live product invocation/delivery, unchanged question text and matched input bindings, plus a retained before/after assessment. A no-benefit result is valid; wiring and benefit remain distinct. |
| A renamed repair or a no-progress source note could renew the detour cap. | Count engineering attempts across the complete new history until a recorded substantive advance; no-advance/candidate-failure results do not reset it. Test both a repeated detour and a no-progress intervening task. |
| An empty new history could itself reset prior drift. | Initialize a lower bound of one inherited detour from the latest replay repair, with no new legal result. Require substantive work first; do not treat this lower bound as a complete recount of past campaigns. |
| A selected tool could disappear by being relabeled deferred. | Require a retained disposition revision, its previous decision, reasons and effect on the original question. Deferral never counts as integration. |
| Admission of another task could bypass the current decision. | Require the current task and preceding refresh to agree. A change needs a recorded next-task reason. |
| A required client fact could halt all research. | Conditional source work cannot be marked blocked solely by client facts; a particular authority/harness block remains possible and other questions stay available. |
| Four convenient questions could erase the original obligations. | Check exact question bytes and original obligation/reading sets against fixed historical hashes; preserve the old cross-reference. Four tasks cannot close 46 obligations by a change of denominator. |
| The new control could become the next long engineering campaign. | Only check/status/admit/refresh actions; no dispatcher, scheduler, installer or provider. Setup ends after focused adversarial validation and a reviewed substantive task selection. |

The initial source task's obligation-2 link was checked in the original register.
Paragraph-14 links 4/10/21/42 come from the existing D-family cross-reference and
their explicit footnote/request premises. Gatecoin links 12/14/25/44 come from the
completed case dossier. These are research dependencies, not claims that one
answer closes each entire obligation. The product task preserves all 46 IDs.

The tool register distinguishes direct code inspection, historical raw scoped
receipts, and reported controlled-workflow results. Reported evidence does not
magically become a new executed check. All six selected tool candidates remain
short of full contribution evaluation. The remaining surveyed tools retain
explicit prerequisite, jurisdiction, conceptual or supporting dispositions.

Acceptance of this implementation is limited to the tested admission behavior.
The checker cannot establish that a cited legal argument is persuasive, that a
model actually relied on supplied context, or that an agent has not bypassed it.
Root AGENTS.md provides the normal execution instruction; old sealed runners are
preserved. A source-supported argument and contrary analysis are still required.
An agent can edit code and policy, so any changed targets or limits must remain
visible in a reviewed revision rather than being described as immutable security.

Post-test results and the actual next-task admission are recorded in the execution
note. No completed test is counted as resolution of an original legal obligation.
