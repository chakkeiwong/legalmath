# Post-implementation skeptical review of the focused successor

12 October 2026 Hong Kong. This review examined the actual entrypoint, case
and source bindings, installed-tool transport, schema validators, call ledger,
command rules and independent branch behavior before permitting any live call.
It does not review a model answer, which has not yet been produced.

The first implementation had three material flaws. It offered a bundled
`launch` action that wrote host approval rules and dispatched calls together;
it described 40 additional calls despite only 20 executable stage IDs; and it
treated both auxiliary reader successes as a prerequisite for baseline and
retrieval even though every answer receives the full source. Those choices
would have obscured permission scope, resource accounting and branch
independence. The current code removes `launch`, restricts the successor to 20
enumerated call stages (aggregate at most 37), and continues independent arms
after a reader failure while recording that loss of coverage. Rule installation
is separate and still unperformed.

The old retained packet also named P10 alone in its `selected_slice`, whereas
this diagnostic asks P10 and evidential sufficiency. The new trial projection
changes only that selection metadata to the exact joined original questions;
all 55 unit texts and 54,910 source characters remain in the reviewed retained
projection. The predecessor artifact is untouched. Local original-question
binding now passes. The stronger answer schema requires an account of seven
specific source obligations, exact case facts with unspecified P11 applicability,
and each actual tool check. The reviewer schema must classify every obligation.
These fields catch the observed omissions structurally but cannot establish
the legal warrant. Executor inspection of the actual answer remains mandatory.

Eight targeted tests passed, including the prior P11/footnote regression,
missing tool-account rejection, independent continuation after reader/formal/
review failure, actual BM25 retrieval for both original questions, installed
all-six product checks reaching the same request, and a fake-provider check
that the allowance reserves the hash of the actual compact wire request.
The existing dependency-runner tests also passed. The 55-unit source projection,
validated 300-second Settings, two reader wire sizes and output schemas passed
offline preflight. Installed checks and schema success are engineering evidence,
not a legal-quality or contribution verdict.

The remaining substantive risks are explicit. Generated formal readings can be
unwarranted or too narrow; the graph engines compute supplied premises and do
not discover source entailment. A model may mechanically fill obligation fields
while omitting reasoning. Retrieval can miss a remote qualifier. One answer per
arm supports descriptive comparison only. The focused path does not establish
full two-reader claim/candidate populations, complete P14/Gatecoin answers,
the old whole-route capacity or a default policy. The planned input-review
pause and answer-by-answer source inspection are therefore required. An
unsupported or failed tool branch cannot cancel baseline, BM25 or another
independent tool; a corrupt common source, changed code/protocol, expired clock
or invalid ledger vetoes all dependent dispatch.

Decision: **PASS for a bounded focused diagnostic only if** a versioned
dependency graph preserves predecessor state, the live task is registered,
the separate admission record binds this reviewed code/plan/source/rules and
the original 17-call prefix, and host approval for rule installation or live
execution is obtained through the exact command. The current file does not by
itself grant provider authority. No original obligation or tool is promoted.
