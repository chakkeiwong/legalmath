## What progress means

An advance records the answer before and after, original obligation IDs, the
specific inference, primary evidence, strongest contrary and remaining dependency.
It can establish a conditional answer or expose an unsupported inference without
claiming actual client compliance. Missing private facts remain variables while
source analysis continues. An irreducible interpretive disagreement is an honest
result when the investigation and its limits are supported.

Engineering results have their own status. A completed repair, a valid schema or
a large coverage count cannot finish the mission. The initial control inherits
at least one repair without a substantive answer change from the predecessor;
it does not start a fresh repair allowance. A necessary later detour must name a
reproduced blocker, its substantive parent, one bounded attempt and a return to
that parent. A second detour requires an explicitly reviewed program revision.
Changing directories or task names cannot reset the recorded count.

## Running and refreshing the control

From the repository root:

```text
.venv/bin/python scripts/legal_mission_control.py check
.venv/bin/python scripts/legal_mission_control.py status
.venv/bin/python scripts/legal_mission_control.py admit
.venv/bin/python scripts/legal_mission_control.py refresh
```

`check` validates the retained constraints and evidence references. `status`
shows legal and integration gaps. `admit` returns the current bounded task and
exact original questions. `refresh` checks the preceding result and recorded next
selection. All four commands are read-only and have no provider, installer,
arbitrary-command or budget-override action. The exact forms ran locally without
new approval prompts in this session.

After a task, save its result at the declared path and update the register's
history, task status, current task and reason. Each history entry contains its
task/kind, actual result file/hash, outcome, decision, next task and reason. A
substantive-advance entry additionally supplies the before/after answer,
inference, primary evidence, original obligation IDs, contrary and remaining
dependency. Mark a task done only with a retained result. Run `refresh` before
continuing. A no-advance result does not renew the engineering allowance.

Source work on one question may continue when another question lacks a particular
authority. Client facts cannot be used to block conditional source research.
If the finite work or resource scope needs changing, retain the reason and review
the revision explicitly. Routine refreshes within the existing scope do not need
a new user decision.

Root [AGENTS.md](../../../AGENTS.md) makes this the normal route for subsequent
legal-interpretation work, including after a window reload. Historical programs
remain available for evidence verification. Their frozen methods, source hashes
and allowances remain unchanged; the prospectus program is separate.

The checker verifies declarations and file identities. It cannot establish the
truth of a legal inference, prove that a model relied on supplied feedback, or
prevent an agent from bypassing instructions. Source-grounded substantive review
is therefore required before accepting an answer or claiming tool benefit. Its
highest possible mission status is ready for acceptance review, never automatic
legal certification.
