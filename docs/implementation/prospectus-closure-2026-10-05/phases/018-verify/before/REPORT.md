The new calculator follows Condition 5(a) of the 2013 base: start-inclusive,
end-exclusive Actual/Actual (ICMA), one or two explicitly supplied determination
periods, full outstanding Interbolsa nominal and an explicitly selected half-up
cent rule. An unknown market convention abstains. It does not silently substitute
Actual/365, infer holiday calendars or extend the printed long-period formula to
an arbitrary number of periods. Missing purchase/cancellation or early-redemption
facts do not produce a maturity amount. The Eurosystem designation records
intention and preserves unknown collateral recognition.

## Review and repairs during execution

The reviewed plan corrected a stale Git baseline and distinguished retained
sources awaiting admission from missing sources. It separated extraction from
legal scope and independent adjudication. The initial successor validation
finished reader work but its summary treated an extraction list as an object;
that reporting failure is retained in phase 005. A dossier anchor initially
crossed a printed marginal annotation and matched nothing; the rejected phase
is retained, and the repaired anchor is an exact source substring.

The final code review rejected two additional assumptions: Decimal formatting
could discard cents at very large magnitudes, and Python could accept True as
page number 1. Exact integer formatting and strict page types repair both.
An affirmative eligibility designation also requires its explicit positive
wording; a negated intention is not accepted. All affected checks were rerun.

The driver now verifies prior data/output identities before each phase,
snapshots the current successor code, tests, plan and before/after results,
retains failed phases and refreshes NEXT-PHASE.md. Later phases can therefore
review a concrete failure and repair it without overwriting its evidence.
The first four historical receipts predate this stronger snapshot scheme;
their existing data hashes remain preserved.

The local sandbox failed before execution at /mnt/wslg/distro. The guarded
editor now accepts encoded literal edit specifications through the narrowly
approved command .venv/bin/python scripts/prospectus_closure_edit.py. It retains
the existing path restrictions and exact old-text/hash checks. This reduces
shell-pattern approval mismatches; it does not change the platform's sandbox
policy or grant unrelated external actions.
