# Review of the actual product comparison

The live wrapper can compare external engines on proposed attack edges. That is
an explicit raw-graph check, but it is not the product's final argument graph:
the product validates typed attacks, blocks arguments with unsupported premises,
and propagates defeats through support dependencies. Agreement on raw edges
must not be reported as agreement on the resulting product semantics.

Within G3, independently check each actual retained semantic-stage graph from
the completed product dossier. Use the exact final nodes and defeats, preserve
the original graph and its premise/warrant information, run both external
engines, and compare the corresponding declared semantics with the local result.
Incomplete local construction or an input above the already reviewed eight-node
bound must remain explicit. Do not trim nodes or change the local configuration
to manufacture a passing comparison. Also check each retained Boolean candidate
from the dossier, preserving the original candidate and its fact definitions and
sources alongside the XML expression result. Unformalized candidates stay so.

Question: do external engines reproduce the finite computations the product
actually retained? Comparator: that dossier's final local graph evaluation and
unchanged expression trees. Pass: exact graph-result agreement and supported AST
roundtrips. Veto: altered nodes/defeats, incomplete local construction reported
as complete, changed sources, or ignored unsupported candidates. Counts are
explanatory. No result supplies legal warrant, actual facts or a default change.

These checks run after the live trials, so their results cannot be claimed to
have influenced earlier model answers. A missing dossier is an unavailable test,
not evidence of successful integration. Use new phase-attempt output directories;
retain the live records and the initial raw-graph diagnostics unchanged.

Audit verdict: proceed with this bounded offline correction to G3's evidence
review, together with the already reviewed source-scope diagnostic and G4 original
record coverage. No added phase, source, provider route or call budget. Twelve
existing harness checks pass; inspect the actual outputs before G4 acceptance.

The same review found that live retrieval falls back to the task name when a
request lacks a top-level `question`. The product normally carries the question
in `source_packet.selected_slice`; `SOURCE_INVENTORY` is not a legal relevance
query. The in-flight comparison retains this original adapter. Its downstream
result therefore cannot establish the applicability of correctly routed product
retrieval. Preserve that failure, then test the corrected query extraction on
the exact retained product request and corpus offline. A provider-stage repair
may be considered only after the primary run's failure and remaining per-arm
budget are known. Do not relabel the primary trial as repaired after the fact.
