The primary baseline reached exact question assignment, then stopped with
`Live scoped investigation requires a recorded additional grant`. The user has
already approved this program's 96-call, 12-repair, 24-hour scope. The test wrapper
uses a counted allowance but fails the product's explicit CodexProvider and
GrantedAllowance interface checks. Requiring the user to authorize the same
scope again would not repair this implementation error.

Provide a CodexProvider subclass and a GrantedAllowance specialization that
verifies the actual, hash-bound program authorization and the existing shared
ledger. It must enforce both the original 96-call global cap and the original
24-call per-product-arm cap, validate reservations, preserve elapsed-time checks,
and count failures. It must not fabricate an exhausted predecessor or create a
new permission/budget. The authorization adapter checks its immutable source
before every dispatch. The historical grant class's exhausted-predecessor rule
describes historical extensions, whereas this is an independently recorded new
program grant; document that distinction rather than inventing history.

After both primary product trials finish, use their retained packet, claims,
candidates and validated exact-question assignment. Run the actual scoped stage
on two original claim/candidate pairs: a paragraph 14 request-trigger candidate
against the retained-responsibility claim and against the demonstration claim.
Select these by the recorded claim meaning and typed question, before observing
the diagnostic outputs. Keep both independent perspectives and the complete
source packet. At most two calls per arm, four total, within existing per-arm
and global caps. Corrected retrieval applies to the combined diagnostic. Preserve
all other untested claim/candidate pairs explicitly; this cannot complete the
whole original product trial or its unfinished fidelity matrix.

Question: can the real stage run under the existing grant, and does its explicit
question context separate a supported duty from correspondence with a narrower
trigger? Comparator: the retained broad fidelity findings and exact generated
candidate, without replacing either. Pass: contract-valid stage execution with
source-supported dimension judgments and the correct question identity. Veto:
grant/ledger drift, invented facts, invalid evidence, mismatched questions or
incorrect assertion of fulfillment. Time and counts are explanatory. Two
perspectives do not establish an accuracy rate, independence or superiority.
