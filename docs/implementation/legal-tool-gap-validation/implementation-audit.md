# Audit before trusted execution

The governing plan is `docs/plans/legal-tool-gap-validation-program.md`.
The user requested program preparation, grouped approvals, review and execution.

The implementation review corrected four material problems before dispatch:

1. The provider Settings schema caps inputs at 200,000 bytes; an initial
   400,000-byte setting would have failed before any transport attempt. The
   wrapper now constructs valid settings before recording dispatch. A focused
   test exercises that actual boundary with a non-network provider fixture.
2. Graph baseline material initially included a computed expected result. The
   direct baseline now receives only the graph, while solver results are added
   in the structured conditions. Both conditions receive the same authored
   candidate rules and exact original corpus.
3. Product retrieval alone would repeat the old program's weak integration.
   The product adapter now invokes both graph engines on supported live graphs
   and the official XML schema on supported Boolean product readings. Its
   diagnostics go to subsequent stages. Unsupported numeric/complex expressions
   are recorded explicitly. Controlled-language and case-transfer support remain
   separately qualified; a parser result cannot certify natural-language meaning.
4. A uniform tool list would pretend that missing factual records are solver
   tasks. Mapping now distinguishes factual input, authority, interpretation,
   normative-standard and question-preservation needs.

PASS FOR BOUNDED EXECUTION after the focused checks. The exact CLI rejects
unrecognized commands/overrides. Local execpolicy checks allow the five fixed
forms and reject the tested different interpreter and shell-action forms.
Eight focused checks cover accounting, stale references, symlinks, invalid graphs,
input parity, provider settings and incomplete-run status. No test establishes
legal accuracy.

The resumed pre-execution review found and repaired further harness defects.
Product stages now reject reuse of a partially populated directory and retain
provider provenance. The final evidence inventory includes raw provider logs.
Missing G1 inputs produce explicit unavailable prerequisites. Command timeouts
retain receipts, and method snapshots are taken before execution, including for
failed attempts. G0 binds the resource pin records and the actual solver binary.
Two additional regression checks cover partial-stage preservation and exact
overlapping windows in normalized sources.

The first retrieval annotations included a letterhead and truncated clauses;
these would measure the wrong target. Before any experimental run, the complete
retained units were inspected and those labels replaced with responsibility,
request, rights, consent and contrary-case clauses. Normalized newlines also
made paragraph splitting ineffective. The revised ablation uses explicit source
windows with offsets. Its uncalibrated size and overlap are convenience choices;
coverage is descriptive, not evidence that this is the best retriever.

PASS FOR EXECUTION after these repairs and the focused checks. Source parity,
budget and stop conditions are unchanged. The grouped trusted setup approval
has been granted and setup succeeded; no repeated permission request is needed.

Remaining hypotheses are explicit: the local LE boundary repair may not work;
the XML profile may expose unsupported constructs; passage annotations are
development examples; the original configured provider may be unavailable; and
the full workflow may exhaust its per-arm limit before returning a dossier.
Those outcomes have retained failure/untested dispositions and do not count as
completed integration. The source/semantic gap remains even if every engineering
test passes. No unexamined setting is promoted to a production default.

The command writes only new program documents/artifacts, except setup's one
dedicated user rule file. It reuses pinned local runtimes, makes no tool downloads,
and dispatches at most 96 serial model calls through the existing provider.
The plan sets a 24-hour limit and 12 explicit repairs. Ordinary local edits and
offline checks are already authorized. Trusted setup/execution needs the host
approval because the rules file is outside writable roots and provider requests
require network access. The existing automatic review remains in force.
