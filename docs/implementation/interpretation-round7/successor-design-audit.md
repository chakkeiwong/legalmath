# Successor repair audit while the frozen fidelity run executes

This is a provisional implementation design, not admission of another live
experiment. Its source is the inspected E2 checks on absence of statutory
definitions and independence from the family-office label. Those checks contain
explicit concerns about the compulsory result conventions. Keep E2's method and
inputs frozen; prepare code only in an isolated directory and admit a successor
after the complete result and argument repair have been reviewed.

The assurance prompt currently requires every Boolean rule to begin with
`TRUE_IS_COMPLIANT` or `TRUE_IS_PROHIBITED`. The selected question instead asks
whether three licensing-trigger factors hold. All four retained candidates
compute a conjunction of three supplied classifications. Their prose attempts
to redefine the imposed tag as a trigger, but `representation()` displays the
tag literally, and conditional comparison can negate a COMPLIANT value to
normalize it to PROHIBITED. Thus the output vocabulary creates an avoidable
semantic mismatch. A bare passing Boolean is not an adequate outcome contract.

The proposed repair introduces `TRUE_IS_SATISFIED` for an explicitly named
Boolean predicate, such as the selected licensing trigger. It retains the
existing compliance/prohibition conventions for questions that actually ask
about those outcomes. It must not map predicate satisfaction automatically into
compliance or prohibition. Each composed component retains its question and
output meaning; different meanings cannot be silently pooled or negated.
Existing readings remain unchanged. New generated readings and their Java
packages are new candidates with new commitments and revalidation.

The fidelity representation also omits known runtime behavior. A new request
should describe the actual unknown/conflict semantics and name facts marked
`requires_judgment`. That description needs direct tests against the interpreter
and generated Java. It must distinguish a supplied classification from an
implemented classifier. Adding explanations must not let a prose promise count
as an executable exception. A failed claim remains unresolved when a qualifying
fact can only be supplied through an unimplemented assessment.

Acceptance should include a three-factor truth table, missing/conflicting inputs,
correct positive predicate labeling, rejection of unauthorized polarity
normalization, and a Java package whose explicit proposed output meaning travels
with its exact bundle. Repaired live candidates need source checks, contrary
interpretation generation and a record of every surviving doubt. The original
204-pair matrix is retained as the comparator; relevance opinions cannot delete
unfavorable checks. Changing only a label cannot resolve the ambiguous business
qualification or the absent governing authority.

The broader problem remains: independent readers may produce the same opaque
fact classification instead of executable alternative readings of its disputed
words. A subsequent bounded issue investigation should isolate the business /
profit-objective sentence, enumerate distinct attachments of its negation and
disjunction, ask fresh critics for omitted readings, and construct scenarios
where those readings differ. Formal counterexamples separate encoded readings;
source evidence and explicit unresolved assumptions determine whether a reading
can be rejected. No search score is a calibrated probability of legal correctness.

No population-accuracy or review-cost comparison is admitted here. The retained
four-case reference study has a different target and weak family replication;
larger call capacity does not fix those limitations.
