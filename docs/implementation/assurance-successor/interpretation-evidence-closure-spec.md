# Evidence needed to measure interpretation reliability

Status: superseded, unexecuted specification. The user's 28 September 2026
requirement forbids human answers, adjudication, ratings and acceptance as quality
evidence. Use [proof-qualified generalization](../proof-qualified-generalization/product.md)
and its [reviewed execution plan](../../plans/proof-qualified-generalization.md).
The proposal below is preserved as historical context, not an available quality
route. In particular, `INDEPENDENT_RECORDED_DISPOSITION` and human operating
tolerance cannot qualify correctness or future generalization under the new
policy. Official texts remain source premises, not human-scored answer keys.

The current sixteen source-condition cases were frozen by the implementing
agent before live interpretation answers. They can reveal a contradiction
between a stated scenario and a returned program. They cannot establish an
independent legal error rate. A reference author can share the same omitted
qualification as the interpreting model, while a case-to-fact mapping can
silently change the question. Software regression, Lean checking and a second
compiler address other errors and do not resolve these two problems.

## Reference decisions and their permitted uses

Represent each reference as a versioned decision with a precise question,
stipulated facts, actor, assessment unit, relevant date, source editions,
supporting and adverse passages, and unresolved assumptions. Give the decision
one of three evidence statuses:

1. `OFFICIAL_EXPRESS_ANSWER`: an applicable official worked example or answer
   addresses that same question and those material facts. Record the exact
   conditions under which the match holds. A superficially similar example is
   insufficient, and an FAQ edition mismatch remains unresolved.
2. `INDEPENDENT_RECORDED_DISPOSITION`: a reference decision is produced without
   access to the system's candidate answers, using an established internal
   interpretive process. Record the reasons, alternatives and material
   disagreement. It is a defeasible institutional reference, not mathematical
   ground truth.
3. `CONDITIONAL_CHALLENGE`: an implementing researcher constructs a case from an
   express clause under stated assumptions. It can expose conditional program
   failures and missing coverage, but cannot independently estimate legal
   reliability. This is the current sixteen-case category.

`UNRESOLVED` is an available answer in every category. The reference can retain
multiple admissible answers when the available authority does not decide
between them. Record what additional evidence would distinguish those answers.
Do not settle uncertainty by majority vote or by requiring the reference to
agree with the generated code.

Official examples and prior internal decisions are the first reference sources.
Use narrowly defined internal questions for material residual disputes. This
protocol does not mandate reviewing every generated line of code, commissioning
an external consultancy, or obtaining fresh advice for an unchanged fact/source
combination. A decision may be reused only within its recorded assumptions and
source versions; a new exception or changed applicability invalidates reuse.

## Freeze before outcomes

Before collecting results, retain a manifest specifying the publication window,
source families, inclusion/exclusion rules, questions, reference-author access,
method versions, model routes, invocation and time limits, factual-mapping
protocol, consequential-error definitions and uncertainty analysis. Preserve
every selected source, including unencodable and unfinished tasks. Separate
development repairs from a subsequent confirmation window.

A retrospective set supports conclusions about that retained set. A prospective
window begins after the manifest and implementation freeze. Sources published
during the window enter according to the predeclared inclusion rules. Once an
outcome causes a repair, preserve its original result; it becomes development
evidence, and the repaired method needs a later untouched confirmation window.
This prevents repeated success on repaired circulars from being reported as
evidence of future performance.

## Keep reference, mapping and execution independent

The interpretation route receives the source and question, not reference
answers or a curated list of expected conditions. The case-mapping route
receives the stipulated facts and unchanged candidate program. It must identify
whether the program answers the exact question, its stated negation, or a
different question. It cannot rewrite the program or manufacture a fact such
as `all_conditions_satisfied` to reach an expected answer.

Record a proposed fact mapping separately from a checked mapping. A checked
mapping requires traceable assignments from stipulated facts and a supported
meaning for each declared fact. Missing classification evidence produces an
unknown fact. Competing mappings produce separate conditional executions and
remain visible. Model agreement alone cannot approve a mapping.

Run the generated Java on each accepted mapping and retain program, input,
runtime and source identities. Compare its answer with the admissible reference
set. Distinguish a contrary decisive answer, no aligned executable, an unknown
runtime result, missing source coverage and unavailable reference evidence.
They are different failure modes and must not be collapsed into one accuracy
number. Retaining a correct alternative is useful, but does not excuse also
releasing an unsafe alternative; candidate recall and selection safety are
separate measures.

## Common errors and promotion

For each consequential reference decision, record the single-reader answer,
each ensemble route's answer, the retained alternative set, actual expenditures
and whether the deployed selection policy would have accepted a decision.
Measure joint misses only where the reference and mappings support that
classification. A shared missing program is a coverage failure, not evidence
that two interpreters independently reached the same wrong legal conclusion.

The primary promotion question is the consequential error rate among decisions
the proposed selection policy would accept, together with its coverage and
abstention rate. Declare the loss definition and acceptable uncertainty bound
before outcomes. The bank must choose the operating tolerance; a software agent
cannot infer it from convenient test results. Correlation across clauses from
one circular means those clauses cannot be treated as independent trials.
Choose and justify the sampling unit and uncertainty method before estimating
rates. With a small number of source families, report supported case findings
and leave general error rates unestimated.

No accepted-decision error on a small sample proves zero future risk. A
material false acceptance vetoes the current promotion claim and triggers a
source/mapping/program investigation. It does not invalidate unrelated formal
proofs, erase earlier cases or justify abandoning the whole research direction.

## Executable acceptance for the next implementation

Implement the reference schema, frozen manifests and comparison report before
new model calls. Negative tests must reject a changed source edition, leaked
expected answer, unsupported case mapping, omitted task, retroactively edited
reference and an unencoded program presented as successful abstention. An
amendment scenario must reopen affected decisions while preserving unaffected
historical records. Replay a retained official example and a genuinely ambiguous
case through the actual Java path. Freeze a later confirmation window before
making an accuracy or review-cost claim.

The current campaign already implements conditional cases, blind mapping
requests, unchanged Java execution, full denominators and source-change tests.
It has not executed the independent reference or prospective promotion protocol
described here. Those remain evidence gaps rather than software-test failures.
