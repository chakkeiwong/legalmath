# Run and inspect the continuing investigation

The fixed entry point for this campaign is:

```sh
.venv/bin/python scripts/run_assurance_successor.py status
.venv/bin/python scripts/run_assurance_successor.py run
```

`run` visits S0–S11 in order and reuses passed phase receipts only after checking
their predecessor files. A focused invocation has the same policy and checks:

```sh
.venv/bin/python scripts/run_assurance_successor.py phase S8
```

These commands use the additional 500-call grant recorded in
`artifacts/assurance-successor/2026-09-28/grant.json`. They do not replenish the
exhausted earlier grant. Every remote invocation is reserved before dispatch;
invalid output and a timeout consume their reservations. Fresh contexts use the
same model family. Their agreement is not evidence of statistical independence.

## Where the conclusions come from

`state.json` records phase attempts. `next-phase-plan.json` records the next
permitted action and stale evidence. Each attempt directory has its original
start manifest, subprocess output, result and final file hashes. A failed
attempt is retained. The normal limit is three attempts and the original 48-hour
campaign deadline. Dated protocol-repair amendments permit six S6
attempts, retaining all earlier attempts; individual model-action limits and the
500-call total are unchanged. Reviewed S8 amendments now permit nine phase attempts.
The scheduling amendment uses the preserved 36-pair mechanism pilot to schedule all four frozen
source families concurrently; full study acceptance is unchanged. Its twelve
completed scoped responses retain their original reservations. A separately
verified historical source archive supports the scheduling receipt, not a claim
that the historical replay certifies the current implementation.

The unfamiliar study uses twelve-pair batches, two scoped rounds, a 120-call
ceiling for each arm and a shared stop at 460 calls. The remaining forty calls
are reserved for conditional case evaluation within the same 500-call total.
Those ceilings are resource controls, not evidence that every future circular
will fit. A timeout, unencoded proposal or incomplete source inventory remains
visible and may require a reviewed decomposition or continuation.

The fourth S6 attempt exposed an invalid strict schema before an authority
answer could be generated. The failed reservation remains counted. The corrected
typed schema keeps the original question, spent action and deadline; a local
schema preflight now rejects the same interface defect before dispatch.
The fifth attempt spent no calls: parallel job ordering prevented exact replay
of a completed PDF peer list. The completed investigation is now reconstructed
from its original journals and reused without regenerating that list.

A retry requires `Sx-repair-N.json` beside this guide and a matching executed
`Sx-repair-N.xml`. The XML must contain at least one passing focused test and no
failures, errors or skips. A statement that a repair was tested is insufficient.
The narrow `halt Sx` command can stop only this repository's exact active phase
process and its descendants; it preserves interrupted public-source transport
records and consumes the attempt. It is for a diagnosed implementation problem,
not a way to reset a difficult interpretation.

The scoped backlog has four separate questions for every selected
claim–candidate pair: source support, relation to the question, correspondence
of executable representation and availability of authority. A schema-valid
response may leave one of these unassessed. The report counts that separately
from obtaining responses from both perspectives. Missing authority without a
catalogue ID is a retained source question; the model must not invent an ID to
make the response valid.

The PDF investigation attaches the original hashed page image. It retains
each extractor discrepancy and both visual proposals, with an additional bounded
inspection when they disagree or remain uncertain. Agreement about printed
text does not settle its legal materiality. Authority investigations retain the
full extracted sources locally, state which exact passages were supplied, and
report missing premises even when a proposed answer has an authentic quotation.

## Inspect a complete unfamiliar-source investigation

Each task under `unfamiliar-study` retains a single-reader arm and an ensemble
arm. Both have the same declared invocation ceiling; actual expenditure differs
and is reported. The reference cases were frozen before the answers but were
not independently adjudicated by a legal reviewer. No superiority or future
error rate follows from this pilot.

The ensemble's `current-state.json` identifies its active source/method revision.
Its `current.json` points to a file-bound dossier under `revisions`. Earlier
revisions remain readable, but an active caller must request the exact expected
revision through `complete_investigation.current`. A changed source starts an
unfinished revision before any new execution; an old executable cannot silently
be used as the active result.

The dossier links the actual source processing, search, criticism, question
assignment, scoped follow-up, supported proof certificates and Java/Catala replay.
`complete_investigation.verify` checks those files and the replay dossier. Before
formal promotion, `proof_certificate.verify` regenerates the permitted proof and
executes the actual Java domain check. The final campaign verification does both.
It never runs proof code or shell commands supplied by a model.

The Boolean certificate establishes a narrow formal lowering proposition and
checks actual Java on the declared finite domain. It does not prove that the
English source has the proposed meaning, that factual classifications are sound,
or that every compiler feature is correct. Unsupported arithmetic, temporal or
large-domain readings remain explicit entries, not absent candidates.

## Use the Java boundary correctly

`legalmath.java.contact_boundary.build` creates a JAR accepting
attributed raw contact histories rather than a caller-supplied compliance
Boolean. The adapter binds actor, report, recipient, channel, event time,
knowledge time and coverage. Incomplete history yields uncertainty rather than
absence. It rejects unknown fields and attempts to override the embedded policy.
The contact-policy assumptions remain source-bound inputs, not legal conclusions
created by successful compilation.

The exact-percentage host adapter accepts the specified decimal representation
and retains integer-scaled comparisons. Its demonstrated numeric boundary is
separate from classification of assets, ownership, aggregation and legal scope.
Use the actual S7 manifests and cases for the executed domains and generated
class names rather than copying an illustrative policy into a bank control.

## Decide what remains

After S11, `final-report.json` contains phase results, current implementation
hashes and a retained-evidence inventory. `remaining-work.json` preserves the
specific pending pairs, unassessed dimensions, unresolved question assignments,
parents, PDF discrepancies, authority questions, unsupported live certificates
and conditional case results. The controller invalidates final acceptance when
bound evidence or material implementation changes.

An engineering pass means the declared processing and rejection checks executed.
It never grants bank release. Inspect a contrary decisive case, missing source
premise or unencoded duty as a concrete investigation item. An exhausted budget
is an unresolved result, not evidence that the remaining interpretation is safe.

Repair 7 added explicit origin receipts for slices created directly with the
reviewed 120-call limit. Repair 8 adds incremental fidelity admission as an
explicit study option; other callers retain conservative preflight by default.
`continuation-amendment-001.json` binds the controlled stop, source freeze,
original allocation, review and executed tests. It creates a new orchestration
identity while preserving original issue limits, deadlines and reservations.

When S8 ends with a structured incomplete result, use the fixed `assess S9`,
`assess S10` and `assess S11` actions to finish conditional evaluation, documents
and current verification. These actions require all frozen tasks in the result
and bind the exact failed phase manifest. They cannot relabel S8 as passed.
An interruption without that terminal result is insufficient for assessment.

The earlier human-reference proposal in `interpretation-evidence-closure-spec.md`
is superseded by
`../proof-qualified-generalization/product.md`. The current successor uses
machine-checked propositions, generated challenges, independent runtime checks
and eligible observations in the existing frozen prospective window. It accepts
no human answer keys, adjudication, ratings or quality approval. Conditional

NOT_ESTABLISHED. The next arithmetic and exact-source-reference specifications,
