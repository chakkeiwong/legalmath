# Review findings to resolve before final acceptance

## F12: initial scoped coverage competes with early follow-up rounds

The current `scoped_investigation.investigate` loop visits batches before rounds:
it can spend both rounds on an early batch before giving a later batch its first
two perspectives. This is separate from the candidate generator's initial
breadth. Under a binding arm ceiling, it leaves later claim–candidate pairs
without an initial judgment even though early pairs received follow-ups. The
complete pair denominator survives, so this is a scheduling limitation rather
than hidden source deletion. It does not establish that a different ordering
would yield more accurate interpretations.

The capacity continuation must specify and test a scheduling policy explicitly.
A round-first or fair-queue option should preserve an initial opportunity for
every required pair before routine second-round work, with any priority override
bound to a recorded consequential objection. Both perspectives in a round must
remain blind to that round's peer response. The change must preserve original
pair/role attempts, deadlines, source identities and cached-response provenance.
It cannot replenish exhausted work or imply that a fixed budget will suffice.
Compare complete first-pass coverage and unresolved consequential objections at
the same declared budget on frozen workloads; neither measure alone establishes
legal accuracy. This option is specified, not implemented in the active S8 run.

The scoped implementation was kept stable until all scoped jobs finished. The
validator was then repaired while independent PDF work continued. Original
response and implementation identities remain readable.

## F7: exact quotation repair needs actionable character diagnostics

The authentication inventory's second piece failed on claim c08, unit
`d501ab149f046.u80.12566`. The first response changed two nonbreaking spaces
(U+00A0) in the 8 July 2027 deadline to ordinary spaces; the repair changed them
to a null character followed by `a0`. Both were correctly rejected. The existing
`check_quotes` diagnostic only says that evidence must occur exactly once, so it
does not identify the offending unit/quote or character discrepancy.

A bounded structured diagnostic should identify the requested unit and quote,
exact occurrence count, source presence and the relevant source text/code-point
difference, while preserving strict equality. It must not automatically rewrite
quotes, silently normalize Unicode, accept a paraphrase or turn authentic
quotation into source entailment. Add mutation tests for NBSP, null characters,
repeated substrings and missing units. The actual rejected responses remain
retained. A repair must use only any remaining original attempts; this finding
does not replenish exhausted source judgments.

information, not the validity of the rejected interpretation. It is not merged
into the active implementation, and it does not renew exhausted row attempts.
