## D2: executable evidence references

Implement a separate reference protocol for the exact executable expression,
reading and assigned question. Source-span identity proves a text location and
cannot stand in for an executable quotation. A reference must bind all three
identities, expression kind and exact quoted range; a changed expression,
question, reading or Unicode coordinate must invalidate it. Retain the current
internal quotation validator and test the unchanged rejected live responses
against it before adding the optional transport. A null formalization exposes
the mechanically known absence of a program; it cannot receive an executable
correspondence judgment. Keep this structural fact distinct from a model's
semantic interpretation.

Begin with the retained nine UCITS readings and the rejected unencoded-candidate
responses, but use general identity/shape tests across different expressions.
Do not embed their desired legal answers. If partially valid response rows are
recovered, validate each row under the original batch, pair, perspective and
request identity, preserve every rejected row and cross-row concern, and count
no recovered row as another independent vote. Discrepancies retain their original
attempt and deadline histories. Audit the implementation before a focused
diagnostic, then integration and a frozen regression. Record failed attempts,
execute causal repairs and refresh D3 from the measured result.

The existing `fidelity_v2.validate` contains a constraint that the D2 transport
must preserve: `NOT_APPLICABLE` correspondence occurs if and only if the proposed
question relation is `NOT_APPLICABLE_TO_THIS_QUESTION`. Thus a null formalization
must not be mechanically rewritten to `UNASSESSED` when the response instead
proposes that the claim lies outside the question. The resolver supplies text
and structural availability; it neither chooses the question relation nor
repairs a legal judgment by changing its label. Exercise both branches, as well
as the retained unencoded `OMITS` rejection, before integrating the new schema.
