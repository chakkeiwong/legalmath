## Executed commands and records

The reviewed commands were:

```text
.venv/bin/python scripts/run_assurance_capacity.py phase D0
.venv/bin/python scripts/run_assurance_capacity.py phase D1
.venv/bin/python scripts/run_assurance_capacity.py verify
```

The wrapper sets `CUDA_VISIBLE_DEVICES=-1`, copies each checked material snapshot
to a separate directory under `/tmp`, archives its source, and checks its hashes
after execution. Each command receipt contains its actual environment, command,
wall time and log hash. The trusted-host permission for the narrow wrapper was
obtained for local API regression; it grants no live model budget. The artifact
root contains the preparation archive, failed focused diagnostics, phase state,
bounded-retry history, next-phase refresh and each phase manifest.

The first focused collection failed on an incorrect test import. The second
focused run found a source-schema violation in the overflow fixture and a
synthetic executable claim about an unencoded reading. The import, fixture and
synthetic answer were repaired, and the subsequent 37-test focused run passed.
The implementation validator was not relaxed. These are harness repairs; they
are not evidence against the representation method, nor are the passing tests
evidence for the legality of a proposed interpretation.

## Using the optional encoding

The application entry point is:

```python
from legalmath.interpretation.assurance.single_reader import run

result = run(packet, provider, directory,
             issue_limits=original_issue_limits,
             transport_profile="readable-tables.v1")
```

For live use, the existing entry point still requires an actual supported
provider, an authorized unspent grant and the original explicit issue history.
This example does not create any of them. The old literal and compact-locator
profiles keep their behavior. A protocol change invalidates a journal binding;
it must never be used to create a new issue budget or erase a spent attempt.

For each encoded dispatch, `expanded-wire-request.json` retains the original,
`wire-request.json` retains the readable representation, and
`encoding-validation.json` records the exact comparison and sizes. Raw and
resolved source-span responses continue to be retained under the existing
contracts. The decoder requires an independently held original-request hash;
using an untrusted message's own hash is insufficient to authenticate it.

## Post-run skeptical review

The strongest alternative explanation for the size reduction is the unusually
repetitive synthetic coverage. The long-unique-rationale challenge confirms that
this mechanism has limits, and its retained failure prevents extrapolating the
175,016-byte result to arbitrary future circulars. Equality of decoded bytes
would be overturned by any dropped/changed field or detached hash; the tests
mutate columns, indices, quotes, questions, source text, editions and cross-piece
links. The weakest part of the usable-model claim is that no real model has
read this format in the current phase. That claim remains untested.

The monograph addition teaches the actual byte-preservation check, the completed
simulation and the overflow qualification. The protected manuscript check found
no removed labels, equations, citation commands or code listings. Next work is
specified in [next-phase-plan.md](next-phase-plan.md); the unresolved D2–D6 work
is preserved in full.

A stricter prose comparison identified concurrent edits to the pre-existing
process map between the first protection archive and D0. Those edits belong to
the other ongoing work and remain intact. The earlier text and complete diff are
retained. The D0 archive contains that revised map before the capacity chart was
added; every line of that baseline remains in the current map in order. This
increment therefore preserves the concurrent version it extended, while the
