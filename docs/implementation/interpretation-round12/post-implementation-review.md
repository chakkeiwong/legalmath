# Implementation review and evidence limits

This is an author code/evidence review, not an independent legal assessment.
The phase manifests and execution result supply the final run status. This note
records what was checked in the implementation and what those checks cannot
settle.

The persistent journal reserves an action before dispatch, locks concurrent
writers, records interrupted and failed actions without refunds, verifies
completed outputs and dependent files, and rejects changed resource bindings.
The transport compatibility repair retains the original journal binding while
letting orchestration change. Exact request, schema and provider settings remain
the cache key. A replay supplies the original provenance and explicitly says it
is reused evidence. Hashes assume trusted filesystem control; they are not
signatures from an independent authority.

The abstraction stage retains separate actors, objects, relationships, assessment
units, time bases and classification assumptions. Its readings enter the actual
search. Correspondence is not inferred from identical formula strings. Explicit
missing information is copied into the reading without dropping the original,
and the combined result is revalidated against its bounds. Unsupported prose in
an expression field is retained as unsupported; it is not silently translated to
`true`. The live margin example contains precisely this failure, along with a
gazettal-dependent rival that remains unencoded.

The cvc5 encoder was reviewed against the declared RuleIR semantics, including
lazy conditionals and defaults, unknown and conflict states, exact scaling,
calendar dates, rule references and version/fact timing. The structural validator
restricts a referenced rule to an unconditional true scope, preventing an
`OUT_OF_SCOPE` status from entering an ordinary expression. That validator is a
shared dependency, not an independent second validation implementation. The
separating solver assignment is executed in actual Java. Concrete comparisons
target status/type/value; the combined Catala suite separately exercises full
results and traces. Neither establishes a theorem about every generated program.

Mutation testing changes actual Java runtime source and compiles the result.
The four targeted faults concern an inclusive bound, future evidence, multiple
exceptions and a version end point. PIT exercises the actual temporal selector
with generated-policy and runtime cases. These are named finite fault sets;
the percentage killed is not an estimate of defects remaining elsewhere.

Source reconciliation keeps every non-whitespace token disagreement. A page
action locates an enclosing region, retains its crop and invokes regional OCR.
It does not assert that a table header or footnote is correctly attached, and
one investigated issue does not erase the others on that page. The current
twelve-page campaign still retains all page discrepancies. Repeated Tesseract
configurations share an engine. The controlled common-omission matrix is an
engineering challenge, not a measured distribution of real parser errors.

Source inventories account for every supplied unit, but their assignment of a
claim to the selected control is itself a model judgment. The margin run shows
why this matters: some fidelity responses treat future Code amendment and
gazettal as a missing executable condition, while a retained candidate treats
them as a separate event. Complete claim/candidate pair coverage does not settle
that relevance dispute. Adding a new Boolean prerequisite merely to eliminate
the finding could make the interpretation worse.

The transfer replay requires an explicit mapping for every candidate fact and
every frozen scenario. Candidate and source hashes, additional scope assumptions
and the actual Java build are checked. Mapping and candidate selection occur
after generation and are author reviewed. Successful replay therefore supports
a conditional demonstration; it does not supply independently labelled legal
accuracy or certify real client classifications.

The live controller has a finite provider, request, case, workflow, phase and
wall-clock budget. It distinguishes incomplete evidence from a harness defect.
Only the former can let independent regression finish with a visibly incomplete
final result. A missing result, corrupted input, unaccounted case or arbitrary
exception cannot use that continuation path. An unresolved candidate rejects
promotion; it does not justify cancelling unrelated deterministic verification.

Live execution subsequently found a concrete failure in that classification:
`Assurance.drive` retained a nested `FAILED_INTEGRITY` report, but the new wrapper
initially treated it as ordinary incomplete evidence. The STR packet exposed
duplicate dependency IDs from repeated references to the same external source.
The repaired boundary coalesces only identical dependency records while retaining
all source occurrences, and the wrapper now propagates the nested integrity
failure before independent checks. The real packet and failure path have focused
regression tests. This finding reinforces why a wrapper's successful return is
insufficient evidence that the underlying checks executed.

The STR proposals also separate a submission event's channel/method conditions
from a report's resubmission history. These are distinct control questions, and
an indiscriminate claim/candidate matrix can produce irrelevant omission findings
when a candidate expresses only one of them. The existing selected-slice and
output-convention checks do not fully solve typed control composition. This is
a remaining usefulness and interpretation-modeling limitation; a large number
of fidelity findings cannot be interpreted as a count of actual legal errors.

Remaining substantive gaps include representative unseen-family references,
independent assessment of uncertain reference meanings, a second authorised
model family for empirical common-error measurement, evidence-backed resolution
of the real PDF differences, general bilingual/priority interpretation, and
observed reviewer effort. These remain separate requirements even if every
engineering check passes. Bank integration is outside this round as requested.
