# What this implementation can establish

This map prevents an engineering pass from becoming a stronger interpretation
claim. The live and full-regression results are recorded separately in the
execution result; absence of a result here is not a pass.

| Claim | Implemented evidence path | Remaining condition |
|---|---|---|
| A completed action is reused only for its bound inputs | Persistent action journal checks input, result and file hashes; source/dependency changes create new actions | Hash integrity does not make the underlying evidence true; filesystem authority is a trust assumption |
| Rival factual models can affect the actual search | Two source-only abstraction roles and a schema challenger supply separately versioned readings to the existing search | Three bounded proposals do not exhaust possible legal distinctions |
| An exception missing from two text extractions can be detected | The rendered PDF/OCR route is compared with retained text; region differences trigger crop/OCR actions | OCR shares an engine across configurations; table and footnote attachment can remain unverified |
| A material source disagreement remains visible after bounded work | Unresolved regions, affected source identities, action receipts and report findings persist | The current twelve real-page disagreements still need evidence-backed dispositions |
| The formal rule executes consistently on the checked corpus | Independent cvc5 encoding, Python reference and actual Java; separate Catala builds and trace tests | Shared validation and fact meanings; finite cases; no whole-compiler theorem |
| Certain realistic Java defects are caught | Four compiled runtime mutations, real witness cases, and PIT temporal-selector mutations | Coverage is the named fault set and method, not every runtime path |
| Rule dependencies are sensitive to authority editions | Existing catalog resolution and dependency-monitor integration with missing-definition and changed-edition tests | General legal hierarchy, bilingual provision interpretation and judicial subsequent treatment are not automated correctness proofs |
| Controlled omissions trigger repair or abstention | Clear, repairable-omission and unresolved-omission fixtures execute through the common workflow | Proposer and source-fidelity responses are scripted in these controls; they do not measure live model accuracy |
| An interpretation is accurate enough for selective automation | Source evidence, live alternative proposals and explicit residual questions are available for assessment | Independently supported references and an appropriate unseen-family study are still required |
| Multiple methods reduce common errors | Controlled paired detection matrix identifies complementary checks | Empirical joint-error rates across model families remain unmeasured |
| Review effort is reduced | Reports locate specific residual questions and reusable evidence | No observed reviewer-time study; model-call savings cannot substitute |

The stronger legal-accuracy and reviewer-cost claims require additional evidence,
not simply more unit tests. That evidence can use targeted internal compliance
assessment of reference examples and residual questions. The implementation does
not require a blanket external consultancy for every circular. It also cannot
replace missing assessment with a model-generated approval.

Bank deployment is intentionally outside this round. Generated JARs are retained
for review, conformance and integration development; the existing release
controls continue to govern use in an operational system.
