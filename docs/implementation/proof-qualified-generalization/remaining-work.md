# Remaining limits and their closure criteria

The machine-only quality requirement is implemented on the shared qualification
route. The following extensions remain qualified. They are not requests for human
judgments, and their absence does not invalidate checked properties of the current
formal domain.

| Limit | Next implementation | Evidence required for closure |
| --- | --- | --- |
| Source meaning and completeness | Connect the source-only issue inventory and counterexample investigations to shared v2 models, retaining all candidate/question identities | Mechanically checked source anchors/dependencies plus explicit unresolved premises; no claim that quotation matching proves interpretation |
| Future-source generalization | Acquire publications automatically from frozen source families; bind raw editions, authenticated chronology where available, model/provider versions and training-provenance limits | Untouched subsequent windows with all acquired tasks and failures, frozen selection, separate repairs, source-change replay and scoped statements; no universal future-law claim |
| Exact original question alignment | Bind the upstream task question separately from each candidate statement and investigate differences | Replay retained question/source/candidate mappings; unresolved alignments stay in the denominator rather than becoming evaluated successes |
| Backend and rich semantic proofs | Specify partial values, exact rationals, structured collections, defaults and evidence selection; add checked translation relations and compiler/codec obligations incrementally | Kernel-checked theorems with exact quantified domains and executable correspondence; constructor-tree identity alone is insufficient |
| Independent partial-value evaluator | Implement observation trees, field-path dependencies and state/error priority independently of the production layout | Generated whole/partial/conflicting evidence and lazy-branch counterexamples agree on values, states and used evidence across the independent evaluator and real runtimes |
| Resource capacity | Measure real failing models; share repeated generated computations/types and partition independent output groups with explicit dependency and laziness preservation | Larger representative workloads with exact results and provenance, measured compiler/host/JVM costs, first-failure envelopes and versioned limits; do not just raise caps |
| Additional operators/imports | Use the versioned registry to add specific missing signatures, domain/error rules and pinned library implementations | Independent mathematical oracle plus boundary, interaction, missing-evidence and three-runtime checks for each added operation |
| Recursive structures | First represent finite identity-linked graphs and bounded traversal where meaning is preserved; general recursion needs Catala/compiler or target extension | Explicit termination/domain argument and semantic equivalence; pinned Catala rejects recursive types, so configuration changes cannot close this limit |
| Full trace coverage | Preserve semantic node/source maps through optimization; instrument necessary library boundaries or audited internals | Observed events correspond to actual execution; optimized-away nodes are transformation evidence, not invented events; prove or qualify instrumentation effects |
| Performance ranking | Freeze a workload distribution and equal semantics; measure repeated compilation, cold/warm execution and compiler/host/JVM memory | Paired uncertainty analysis with failed/unsupported workloads included; correctness precedes performance ranking |

The present generated corpus is development evidence. Its negative-scale repair
cannot count as success on an untouched confirmation set. The opened future
window freezes the current code/checker method, not an unspecified future LLM
route. A future source interpreter needs its own frozen model/prompt/provider
provenance before attributing observations to that interpreter. Current reports
do not claim source discovery completeness, model-training independence, original
question alignment, or legal accuracy.

The product also retains older low-level development APIs that accept expected
values for compiler testing and historical release records. They are not quality
authorities under the new requirement and cannot be imported as qualification
grades. Product callers should use `rules assure` and `rules verify-assurance`.
