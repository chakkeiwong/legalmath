The reproduced defect is local. The schedule generator advances every coupon
from its original date; the old reference validator advances from each left
endpoint. After February clamping, those origins can differ. The dates
29, 30 and 31 August 2023 all clamp to 29 February 2024, while their following
August dates differ. Inferring an original day from that February date is
therefore underdetermined. Enabling EOM silently would change the declared
convention. No optional package participated in the reproduced mismatch.

For anchor A and month offset m, the candidate uses the original day of A,
clamped to the destination month's length. If EOM is explicitly true and A
is itself month end, it uses destination month end. For frequency f, coupon
index n advances by n*(12/f) months. The validator requires a reference's left
endpoint at index n and its right endpoint at n+1 on that same lattice.
The schedule uses the same definition. Thus their declared date rules agree
by construction; this alone cannot prove that the rule matches a prospectus.
Independent date lists test the implementation of the shared definition.

The existing exact overlap formula is unchanged. A full reference contributes
days/(f*days)=1/f. The new tests list the relevant dates independently and
check day counts before comparing fractions. They include two regular periods,
temporary February clamps, EOM contrasts, negative index offsets and four
short/long first/final examples. Invalid gaps, overlap, missing coverage,
wrong days/frequency, missing source evidence and version mismatches are vetoes.
An interval can cross two equal-length references and still have fraction 1/f;
the new calculation therefore also checks actual regular or stub endpoints.

`fixed-coupon.v2` is restricted to anchored ICMA and requires a canonical ISO
anchor with an exact quoted English date. `selected-coupon-terms.v3` requires
an operative selected anchor, admitted as `admitted-coupon-terms.v2`. A selected
anchor cannot be overridden by calculation premises. Both direct scenarios
and selected-term P5 use the new profile. Old versions keep their original
meaning and reject the new field. Full selected-contract support stays
regular-only; direct stub calculations are hypothetical.
