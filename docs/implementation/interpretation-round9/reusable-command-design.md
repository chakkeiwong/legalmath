# A source question that can be investigated again

The reusable command accepts a JSON document with exactly three top-level fields:
`packet`, `issue` and `at`. The packet retains the source units, exact text and
source identities. The issue states the question, target quotes, supplied fact
definitions, abstraction assumptions and qualifications that every proposal must
retain. The assessment time is an explicit UTC timestamp. There is no expected
answer, reference expression or hidden scenario in this input.

An issue might ask whether the antecedent of an ordinary-course qualification
holds under a particular parse. Its facts can describe income, purpose and the
arrangement. A fact named “the legally correct interpretation is satisfied” would
assume away the question. The command cannot prove that the supplied vocabulary
is adequate: readers must be able to object, propose a non-executable reading or
retain a question rather than invent a Boolean answer.

Two initial readers work without peer proposals. A challenger then seeks missing
readings, and critics inspect the source and executable distinctions. The
bounded assurance profile includes one further reconsideration and audit. This
is the profile used in the comparative diagnostic, with at most two readings per
generation request, four targets per criticism request and 24 calls in total.
The broader round-eight case used two reconsideration cycles; those separate
profiles must not be conflated in reports.

The product command records the actual profile, source question and limits.
It returns either retained uncertainty or no discrepancy reported within that
profile. Neither result is a legal correctness probability or a release decision.
Non-executable readings remain visible. The generated Java evidence applies to
the encoded formulas and declared state space; it does not determine the truth
of a supplied legal classification.

The allowance must already exist. The command never creates a larger grant or
refunds a failed call. Its absolute reservation ceiling is fixed when the run
starts. Operations on one output directory are exclusive, and runs using a
shared allowance must be scheduled serially for unambiguous run-level accounting.
The returned report states that accounting scope.

A completed result can be resumed only with identical public input, method,
provider route, implementation, JDK path and time limit. The command checks the
final allowance history, method manifest and every task receipt before returning
the saved result. An interrupted dispatch needs explicit recovery, which retains
its charge and execution time. Recovery never silently restarts a paid request.

The proposed interface is:

```sh
.venv/bin/legalmath assurance-interpret-issue \
  --public examples/interpretation-assurance/declared-issue.json \
  --out artifacts/interpretation/custom-issue \
  --allowance artifacts/interpretation/round7/live-allowance.json \
  --jdk .localresources/java-toolchain/jdk-17.0.20.1+1 \
  --method assurance
```

Use `--resume` with the same arguments for a completed or explicitly resumable
run. Use `--recover` for an interrupted run before `--resume`. These operations
preserve the original source and method bindings. A changed source or method
belongs in a new investigation, while the previous uncertainty remains evidence.

This command is staged until the frozen comparison closes. Its installation and
acceptance must be recorded in the H0 continuation; this design note alone does
not establish that the entry point is installed.
