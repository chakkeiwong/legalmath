# Reading the declared-interface comparison

This study compares four concrete procedures on four controlled cases: a single
reader; two isolated readers; those readers plus a missing-reading challenge;
and that search plus source criticism and one discrepancy reconsideration. The
last procedure uses at most eight bounded tasks. Each task permits at most three
attempts, including failed responses. All methods receive the same 24-call
ceiling and one-hour execution bound per job.

Every reader sees the retained source, the question being asked, factual input
definitions and explicit limitations. It does not see the reference formula,
hidden scenarios or expected answers. Supplying the same vocabulary makes
programs comparable without guessing whether differently named inputs mean the
same thing. It also limits the question: this is interpretation conditional on
that vocabulary, not an evaluation of automatic fact discovery.

Generators return at most two readings per request and retain other possibilities
as concerns. Source critics receive all proposals as context but return judgments
for at most four named candidates. A non-executable reading stays visible,
contributes no fabricated output and prevents unconditional acceptance. Source
questions, deferred proposals and invalid-response history remain part of the
record even when a later proposal matches the reference program.

The four cases come from two retained SFC FAQ families. The family-office pair
changes the selected trigger's connective. The RA13 client-money pair changes
whether the transfer-agent role affects the selected applicability condition.
Altered text is a controlled experimental input with no regulatory authority.
The wider qualifications and duties remain visible in each complete source.

## What the recorded outcomes mean

`reference_in_candidate_set` means at least one retained executable proposal
matches an authored reference signature on the hidden scenarios. It is reported
with the number of distinct signatures and excess alternatives. A method that
produces every possible answer cannot be described as accurate merely because
one of them matches.

`ACCEPTED` is an evaluation disposition: one signature remains and the method
reports no outstanding concern or rejected/non-executable proposal. The scorer
then reports whether that signature agrees with the reference. `ABSTAIN` retains
competing outcomes or uncertainty. `MISSING` means the job did not complete.
None of these dispositions authorizes a bank release.

The references are authored translations with explicit assumptions. The source
families were used in development and form a convenience sample. Model training
exposure and dependence among fresh contexts are unknown. These conditions veto
population inference and method ranking; counts remain descriptive. The earlier
study and scorer are preserved rather than silently rewritten.

## Execution and recovery

The fixed reviewed supervisor is `scripts/run_declared_plan.py`. G0 checks the
actual method task paths and adverse scoring cases. G1 executes every reference
in Java and detects a deliberately inverted expression. G2 records all sixteen
randomized method/case jobs. G3 verifies the engineering regression and retained
evidence.

```sh
.venv/bin/python scripts/run_declared_plan.py status
.venv/bin/python scripts/run_declared_plan.py preflight
```

The existing grant starts this study at 81/500 consumed calls. The worst-case
reservation is 384 further calls, absolute ceiling 465. The reservation is not
a spending target. Each completed job has an assignment, exact public-input
hash, request/response journals, counted reservations, source validation,
Java/Python comparisons, score and file manifest under
`artifacts/interpretation/round9/jobs/`.

A service circuit or integrity failure stops dependent work. Preserve the failed
attempt, diagnose it, and use the explicit job recovery only after the supervisor
has stopped. Recovery keeps completed tasks and consumed calls. Elapsed execution
time also persists; a hard interruption is conservatively charged through
recovery when exact runtime is unavailable. A reviewed repair and refreshed
phase plan are required before another supervisor attempt.

The final study summary joins candidate-set recovery, excess alternatives,
unsafe and correct finite-reference acceptance, abstention, missing execution,
actual calls and all inference vetoes. The final report must not turn zero unsafe
acceptances in an all-abstention run into evidence that the method is safe.
