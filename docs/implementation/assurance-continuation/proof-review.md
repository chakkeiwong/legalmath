# Arithmetic and source-reference review

The checked arithmetic target is an ordered finite sum of `Option Int` values.
`some n` means the exact integer `n`; `none` means missing. The definition of
`add` returns a known sum only when both operands are known. The three printed
Lean theorems establish removal of the neutral initial accumulator, absorption
of a missing operand at any position and agreement with the ordinary integer
sum when every input is known. The audited standard logical dependencies are
recorded with the proof. This is not an axiom-free certificate or a proof of
legal exposure classifications.

The constructor-preservation check separately parses the formal expression and
the shared model. Its independent parser implements the same explicitly
declared ordered normalization. The mathematical theorem explains that
normalization's integer/missing semantics; the constructor check establishes
the corresponding expression structure. Neither theorem verifies an arbitrary
Catala compiler, JVM, serialization layer, financial input definition, temporal
selection or regulatory interpretation. Those are separate premises or runtime
checks in the result.

The observed expression repeats direct and indirect exposure. Removing repeated
operands would change it. C4 preserves the original reading, compares it with
the explicit nested binary expression in a declared symbolic domain, and
requires an executed separating witness when the repetition is removed. Its
negative values are mathematical challenges, not asserted admissible bank
valuations. Unknown and conflicting facts exercise existing runtime behavior;
the narrow `Option Int` theorem does not turn conflict behavior into an integer
algebra result.

For source references, the target is exact location integrity. The closed table
is recomputed from the packet, request and Unicode text. The resolver accepts
only known ordered adjoining selections and retrieves bytes through the
declared codepoint-to-text operation. The subsequent original quotation
validator and source-fidelity validator still operate on the resolved text.
This construction eliminates model transcription as a trusted operation. It
does not prove that the selected passage is relevant or that a whole-unit quote
is an adequate explanation.

The strongest alternative explanation for broad end-to-end success is a shared
interpretive error across all model contexts and both generated backends. The
new deterministic checks would not necessarily expose that error. A checked
program disagreement or a failed premise invalidates the corresponding scoped
claim; agreement alone supplies no legal-error probability. The weakest live
evidence remains source meaning and completeness of the declared questions.
The complete investigation therefore retains qualifications even when the
compiler and mathematical checks pass.
