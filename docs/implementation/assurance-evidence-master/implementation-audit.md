## Bounded propagation-output repair

The first two P3 calls timed out at the declared 300 seconds. The previous
failure gate recognised dependency and interruption codes but omitted the
provider's E_RESOURCE_LIMIT deadline code, so another pair was already dispatched.
The supervisor interrupted the verified master, allowing that already-spent pair
to finish or reach its existing deadline and retain evidence.

The repair explicitly counts provider deadlines/output-cap failures as dependency
failures, while distinguishing them from quota limits. Propagation output now
groups question IDs only when status/evidence/explanation are identical within
one reading. Expansion requires every original ID exactly once, detects duplicate
or missing IDs, and retains the original per-question inventory. Explanations
are bounded to 350 characters. Full source/readings stay in the input. This is a
tested output-size hypothesis, not an assumption that a smaller response is
legally more accurate. First repaired calls form a two-role pilot; two further
provider failures stop breadth. Prior calls stay spent and retries use the same
canonical reading/role limits.
