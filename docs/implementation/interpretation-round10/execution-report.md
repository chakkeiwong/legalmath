# Reusable interpretation command and repaired reconsideration

The product now exposes `legalmath assurance-interpret-issue`. It accepts a
retained public source and declared question, generates competing interpretations,
checks their executable consequences in Python and Java, seeks missing readings,
criticizes the proposals against the source, and performs bounded reconsideration.
A completed run can be resumed without paying for its calls again. Its result
keeps the exact question, assumptions, criticism, rejected proposals and remaining
uncertainty alongside generated Java evidence.

The implementation is `declared-predicate-methods.v2`. It repairs three paths in
which the previous implementation could retain a discrepancy without actively
reconsidering it. The version 1 comparison remains preserved under round nine;
its results are not relabelled with the new method.

## Reproduced failures and executed repairs

| Before the repair | Demonstration | Repaired behavior |
| --- | --- | --- |
| A question attached only to an executable reading could miss the aggregate concern list | A counted-provider test completed with zero reconsideration cycles although that question remained | Candidate questions enter the retained concerns and trigger the actual reviser/auditor tasks |
| Critics could support two incompatible programs without causing another semantic cycle | The test supplied conjunction and disjunction, with every critic returning support; no cycle ran | Executed behavior groups trigger reconsideration independently of the critic labels; equivalent expressions can be distinguished from different behaviors |
| A formatting repair could change a proposed formula while its earlier version remained only in the rejected-response archive | The first response had a valid alternative result and an invalid prose scope; its repair replaced the formula | The reviser receives the unchanged rejected proposal and validation error; the test restores that alternative through a fresh proposal and executes its difference |
| Local Java checking could finish after the issue deadline and still be accepted | A simulated clock crossed the deadline after local verification | Completion rechecks elapsed time and rejects the late result |
| Java runtime and schema changes were absent from the implementation hash | Two temporary-package tests changed those bytes after completion; resume accepted them | H3 includes Python, Java, JSON and SQL package sources in command and phase identities |
| A completed command resume initially checked only its starting allowance history | An altered consumed-call timestamp escaped a check against an empty initial prefix in the first staged implementation | Resume verifies the final allowance checkpoint, method manifest and every successful task receipt |

The original failed tests and successive staged checks are preserved under
`.localresources/interpretation-round10/`. The installed H0 acceptance passed
39 focused tests in 59.93 seconds. The tests execute the relevant paths, including
Java differences, counted failures, explicit interruption recovery, stale input
and implementation rejection, and invalid input before any paid call.

The repair also corrected a misleading paraphrase test expectation. Its authored
reference carried two unresolved source questions, yet the old test expected

abstention. A separate explicitly question-free synthetic variant tests whether
a paraphrase with the same declared meaning can receive the narrow evaluation

## Live product-command check

The ordinary command completed using nine model calls: eight validated tasks and
one rejected response that omitted required qualifications. It performed one
semantic reconsideration, retained eight candidates and recorded three distinct
executable behaviors. Six candidates were executable; two remained unencoded
because the supplied vocabulary could not express their proposed reading. The
final comparison executed 384 candidate/state evaluations, with matching Python
and Java results throughout. The report retained 45 generation-concern entries
and both proposed readings from the rejected response; these counts are not
independent legal evidence.

The reconsideration request included the original two rejected readings,
unchanged, together with source criticisms and validated proposals. The final
result is **UNCERTAINTY_RETAINED**. It selects no legal winner. Its eight
candidate readings and questions can be inspected in
`artifacts/interpretation/round10/issue/result/report.json`; descriptors exist
only for the six executable candidates. The audit resumed the exact completed
command, verified its retained receipts and comparison, and consumed zero further
model calls. The shared grant stands at 153/500, leaving 347 calls.

The complete source and declared issue are in
`examples/interpretation-assurance/declared-issue.json`. The live command received
no previous proposals, source criticisms, reference program or hidden expected
scenarios. This is nevertheless a development-exposed case; model training and
same-provider dependence remain unknown. It tests the ordinary entry point and
its evidence retention, not population legal accuracy.

The supplied three Boolean facts distinguish the arrangement, income beyond
reimbursement and a profit objective. The source wording can motivate different
negation or connective attachments. The input vocabulary itself can omit a legal
distinction. The command therefore permits an explicitly questioned proposal
without executable code and retains vocabulary concerns. Java execution compares
encoded proposals over true, false, unknown and conflicting evidence for each
supplied fact. Some combinations may be factually impossible; feasibility is not
assumed merely because the program can evaluate them.

Each request produces at most two readings. Critics judge at most four named
proposals while retaining the complete source and candidate context. Each task
has at most three attempts, and the assurance profile permits one semantic
reconsideration. The command has a 24-call ceiling and a one-hour execution bound.
The earlier round-eight case used two cycles in a separate profile; neither run
establishes exhaustive interpretation coverage.

## What is delivered

The operator guide gives a complete command and input explanation. A report
contains the exact issue question, proposed output descriptors, all candidate
readings and their origins, criticism history, rejected proposal history, actual
calls, fixed limits and the final Java/Python comparison path. Output descriptors
bind each executable candidate to the issue question; they prevent a narrow
predicate from being labelled as whole-law compliance by the report.

Generated Java source, JARs and build manifests sit beside the executed
counterexample scenarios. They implement the declared candidate formulas. The
existing draft host-package API carries source bytes and output descriptors;
its packet question must be checked when packaging an issue narrower than the
original packet scope. The bank's actual host API, fact meanings, evidence
requirements and release controls remain needed for institutional staging.

A run uses an existing authorized allowance. It never creates another grant or
refunds a failed reservation. Exact completed resume verifies source, method,
implementation, route, Java version, allowance history, manifests and receipts.
Interrupted dispatch requires explicit recovery. Operations on one run directory
are exclusive; runs sharing one allowance are scheduled serially. Source text is
quoted data, not executable instructions or permission to run commands.

The strongest alternative explanation for apparent agreement is correlated model
error combined with a fixed factual vocabulary. The weakest evidence concerns
whether the source and proposed facts capture every legally relevant distinction.
A matched formula or supporting criticism does not repair that uncertainty by
itself. The command records it for further investigation. It does not impose an
individual external legal opinion as a routine software prerequisite, and this
run has not measured savings in professional-review cost.
