The exact-rational extension parses a decimal percentage string, computes its
exact basis-point fraction n/d with d positive, and compares n against 1000d.
The unchanged whole-basis-point policy remains the comparator. At 9.999%,
n=9999 and d=10, so the comparison is false. Seven cases cover equality,
both sides very close to the boundary and objective-only/zero cases. The
operational Java input boundary still needs the same strict validation if it
accepts arbitrary external numerator/denominator fields; the current checked
adapter is Python. No negative-exposure domain policy is implied by the
arithmetic conversion.

## Repairs actually executed

The initial audit rejected a stale allowance, cross-packet batching and reuse of
historical CONTEXT labels that would have suppressed 48 restored rows. It also
repaired missing code bindings, nonresumable allowance handling, a note-only
repair path and unconditional completion despite pending work. The accepted
program retains the original allowance prefix, changes phase identity when code
changes, and writes next-phase and repair records between phases.

During execution, code review found the one-attempt provider initializer outside
the reader class. The earlier test's HTTP 503 text did not match the inherited
wrapper's retry conditions, so it did not expose the wiring error. The run was
interrupted, its code and partial regression were preserved, the initializer
was moved, and tests were extended to overload, stream-disconnection and deadline
errors. The repaired focused suite passed **57 tests**. Exact validated responses
were reused as retained evidence, without creating a new vote or refunding a
reservation.

manifests all acquired the final six-element predecessor list. Their immutable
journal records and saved phase results still had the correct prefixes. The
repair copies the list, checks each summary against its saved result, and
reconstructs only the summaries from the original journal. Both code versions
and the original summaries remain under `pre-summary-repair`; `summary-repair.json`
binds the exact changes. The focused round-15 tests passed 24 cases after this
repair. No source finding, model response or phase result was rewritten.

The first full regression after repair reached 558 completed tests and timed
out at the first API test in the sandbox. That exact API test passed in the

The first trusted suite passed 789 tests. A later full run of the summary repair

That final trusted run completed successfully in 648.81 seconds. It passed all
