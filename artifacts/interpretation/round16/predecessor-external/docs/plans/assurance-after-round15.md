# Successor from the round-15 evidence

This is the next specification, not a record of executed work. Verify the
round-15 delivery manifest and read its execution result first. The baseline is
140 accepted source comparisons, 91 pending gifts pairs, one unencoded restored
pair, eight retained parents, 330 PDF differences with unresolved materiality,
and a demonstrated exact-rational numerical route. The model allowance is
500/500; no new provider dispatch is authorized by this document.

The question is how to distinguish real interpretive failures from separately
scoped controls, preserve temporal and input meaning, and obtain useful evidence
about error. Passing more cases or obtaining fewer NOT_ESTABLISHED labels is
not a promotion criterion. The observed labels include unsupported relations
between a claim and a narrower question; treating them all as defects would be
wrong. The trusted delivery checks establish only the stated engineering results.

## Repairs, budgets and environment

N1–N4 can begin locally without new model calls. Reuse existing captured
responses as migration fixtures, never as fresh independent votes. Complete the
deterministic prerequisites before sizing live work. For 91 pending pairs, the
old 24-pair size would require at least four first passes, but round 15 exposed
repeated cross-field response errors. Prompt size, schema constraints and retry
requirements must be checked early; four calls cannot be promised to complete
the work. A future grant needs an explicit ceiling that includes failed calls
and a preserved predecessor allowance. Never edit or reset the exhausted grant.

Keep the no-hidden-transport-retry wrapper and direct tests of its installed
class. Stop live dispatch on the first transport failure; continue independent
local work. Every phase gets at most three attempts and an explicit time bound.
After each phase, rebuild its next-stage inputs from actual results and retain
rejected candidates. A failed interpretation is a promotion veto and repair
trigger; corrupted evidence or exhausted required resources is a continuation
veto for the dependent action.

Use trusted execution for the full local API regression: the sandboxed run
stalled while the same trusted API test passed. GPU devices remain intentionally
hidden. Hash the environment/tool versions, command and dirty-code content in
each manifest. Do not replace a full failed run with a selectively passing
subset.

## Review verdict

The successor corrects three assumptions the execution challenged: a
NOT_ESTABLISHED label is not always a rule defect; a compiling child may lack
historical or performance semantics; and a retrieved PDF can contain mutually
exclusive versions in one text stream. The rational Java boundary is also a
specific integration task rather than an implicit promise made by Python
tests. The plan is executable in this order once each phase's interface and
fixtures are frozen. It intentionally does not dispatch a second model family
or invent independent reference answers. Missing evidence blocks those claims,
not N1–N4. Production-bank integration remains deferred.
