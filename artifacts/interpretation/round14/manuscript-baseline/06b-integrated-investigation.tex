\section{From complementary checks to a working investigation}
\label{sec:integrated-investigation}

Return to the offer containing a fee waiver and a separate voucher. A programme
can implement its conditions exactly and still miss the voucher if the input
record describes only whether the offer contains a discount. In that situation,
adding another compiler leaves the missing distinction untouched. The necessary
repair is to reconsider what the facts describe. The proposed investigation
therefore treats the factual model as a revisable interpretation of the source.
One proposal may describe the whole offer; another may distinguish each benefit,
its recipient and its connection to a product. Both proposals retain their
source passages and classification assumptions. They cannot be treated as
equivalent merely because both use a variable named \texttt{discount}.

This change gives breadth-first investigation a substantive purpose. Before
ranking readings of the exception, separate readers propose the actors,
components and dates needed to express it. A challenger then asks which relevant
distinction all those proposals might have missed. Subsequent search investigates
cases that separate the proposals. For the combined offer, assessing the voucher
separately is such a case under the interpretation developed earlier in this
book. Whether a particular benefit is legally a gift remains a classification
question; a mathematical comparison cannot supply that classification.

The source itself must also remain open to challenge. Suppose the discount
exception appears in a footnote recovered by OCR but omitted by the embedded
PDF text. Comparing whole-page strings identifies a difference but does not
explain it. The investigation needs the footnote's page region, the text recovered
by each method and its attachment to the relevant paragraph. Additional work
then has a specific purpose: inspect that region, recover its wording, or locate
the corresponding official text. Ordinary line wrapping can be reconciled
without changing words. A missing negation or uncertain table header cannot.
Agreement among text parsers does not settle a disagreement with the rendered
page because the text parsers may share the same omission.

Each discovered problem consequently has a history. The record states which
source, factual model and proposed rule it affects, which action was taken,
and whether new evidence answered the question. A retry that produces the same
unsupported assertion adds no authority. The maximum number of actions is fixed
before execution and persists across interruptions. If the evidence is still
insufficient, the report retains the rival readings and the smallest unanswered
question that distinguishes them. Such a question can often be assessed more
economically than commissioning a new review of the entire circular.

Consider next an amendment to the provision defining the relevant distributor.
The wording of the gift paragraph might be unchanged, yet its applicable actors
could differ. The investigation must connect the proposed rule to the edition
of that definition and the relevant date. A changed dependency invalidates the
affected conclusion and its supporting execution checks. Historical replay
requires both the rule applicable to the conduct and the evidence available at
the historical cutoff. A later publication cannot silently become evidence that
was available earlier. Where the authority or temporal relationship is disputed,
the program reports that dispute instead of inventing a priority rule.

Once a factual model and executable interpretation are explicit, the execution
checks become precise. Python, generated Java and a separately compiled Catala
calculation can be run on the same cases. An independent solver can seek an
input that makes two formal proposals disagree. A discovered input is then
executed in the actual binaries, including their explanations and evidence
references. If a compiler mutation changes an inclusive threshold to a strict
threshold, the boundary case must detect the change. If two routes share the
same input validation or date handling, those shared operations still need
their own challenges. Multiple compilation paths do not make every layer
independent.

The distinction between these checks and a proof matters. A proof for a
specified language fragment would state that every valid input receives the
result prescribed by its formal semantics, under explicit runtime assumptions.
Finite conformance cases are evidence for that proposition, not its universal
derivation. A theorem about a mathematical evaluator requires an additional
connection to the emitted Java before it establishes a property of that Java.
Neither proposition, even when proved, establishes that a chosen English
interpretation included every legally relevant distinction.

A useful demonstration must therefore contain both successful decisions and
unresolved cases. The clear cases establish that the system can produce a
working Java package and apply its stated conditions. Deliberate omissions,
competing factual models and ambiguous authorities establish whether the
investigation exposes the situations in which its answer needs more evidence.
A system that refers every case to a reviewer has demonstrated caution but
has not demonstrated the intended reduction in manual interpretation work.

Reference cases must be prepared with the same distinction in mind. An official
example can provide direct evidence about the example it addresses. A constructed
case tests an explicitly stated interpretation. A case and rule written by the
same agent may repeat the same mistake. Their agreement remains useful for
checking execution, while independent source assessment is needed for a stronger
interpretation claim. The evaluation preserves these different origins rather
than combining them into one accuracy percentage. Related scenarios from one
circular also remain related observations; thousands of truth-table rows do not
become thousands of independently checked legal judgments.

The implementation target is one investigation joining these steps and retaining
their evidence. The phase plan fixes the supported scope, executes repairs after
failures, and refreshes the next phase when its assumptions change. Its first
demonstration concerns public circulars and declared control profiles. Measuring
reviewer savings requires actual review observations; estimating rare legal
errors requires a suitable independently supported corpus. Those evaluations
can follow a working demonstration, provided its report makes the remaining
questions visible.
