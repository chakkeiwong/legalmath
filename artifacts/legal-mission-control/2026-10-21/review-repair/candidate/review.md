# R2 correction and continuation within the adopted master

The live Gatecoin baseline reproduced two defects in the adopted R2 repair.
Completed responses rejected by reference-schema validation leave no decoded
`raw.json`, so 48 assignments from two groups received no repair. Copying a
large malformed response into a repair exceeded the unchanged 250,000-byte
input limit. Both are implementation failures, not legal impossibility.

The engineering question is whether every authenticated completed malformed
review can receive its already authorized single reassessment while preserving
valid siblings, the exact answer and sources, charged calls and owner attempts.
The comparator is the saved production failure and its actual sent schema,
receipt and ledger. Local pass requires real-receipt reachability, tamper
refusals, unchanged substantive context, measured capacity, one-repair accounting
and a restart that sends no previously settled request again. Legal acceptance
still requires every mandatory review and subsequent correction checks.

Receipt handling is restricted to a completed `ValidationError` reproduced
against the authenticated sent wire schema. Schema-valid reference expansion
failures, transport errors, capacity failures, refusals and uncertain dispatch
are not reclassified. The correction does not guess a malformed assignment map.
It requests one reassessment for each original assignment. Valid decoded siblings
retain their results. Full diagnostics are saved separately; the prompt receives
their evidence identity and a 512-character excerpt. The excerpt length is a
convenience choice, not a source compression policy. Complete answer and sources
remain in every request; actual packet measurement is its early check.

Handover is permitted only before the current owner's invalid-review pass starts.
Acquire the state, service and dispatch locks, verify the exact supervisor and
absence of provider children and RESERVED dispatches, then stop that supervisor
at this settled boundary. Retain its RUNNING reservation and attempt number for
the existing resume protocol. Never interrupt an active provider request.
If the boundary is not available, release locks and continue observing; uncertain
dispatch is a continuation veto, not permission to manufacture a completion.

Copy settled dispatch bytes and product identities into a continuation runtime
directory within this same repair package. Preserve original directories and
all sealed phase contracts. Rebuild new phase contracts under the new binding;
the ordinary dispatch identity check reuses the copied exact responses. This
avoids changing old phase bindings or running new code under an old binding.
Keep the old checkpoint references and source identities unchanged. No old
successful answer, completed failure or completed correction may be resampled.
The current Gatecoin reservation resumes as attempt 4; no attempt ceiling,
detour count, repair ceiling, service reservation, protected budget, model,
deadline or global call allowance changes.

Registration is an amendment inside `review_repair`, using the existing master
`gap-refresh`, `verify` and `live` command forms. Archive changed predecessor
sources and program bytes and validate them under their historical bindings.
Bind the correction's current sources, tests and actual diagnostic evidence
separately. Retain a write-ahead transaction for program/state/binding/mission.
The resumed worker bypasses transport requalification only for an authenticated
orphan reservation with a closed circuit; an open/uncertain circuit still needs
its existing recovery protocol.

Skeptical audit: PASS for this bounded correction, conditional on tests and the
settled boundary. The wrong baseline would be a synthetic non-reference provider;
the real malformed wire response is mandatory evidence. A format pass or local
capacity fit cannot promote legal acceptance. The main restart risks are changed
phase identities, duplicate dispatch and resetting a completed failure; preserving
old phases and copying only exact settled dispatches addresses those risks and
must be tested. No hypothesis about Sol reliability or the eventual legal answer
is inferred from this correction. Stop only for invalid authority, changed shared
evidence, unknown dispatch, depleted authorized budget/deadline, or a frontier
with no authorized ready work. Continue independent work after ordinary failure.

Run local checks with `.venv-context/bin/python`, CPU only, and retain commands,
source hashes, timing and results in this package. The earlier 160-test result
and four-route production replay remain immutable historical evidence. This
correction requires focused tests of the changed path and actual saved-packet
measurements; it does not repeat unrelated acquisition or answer generation.
