## Contract and skeptical audit

| Role | Predeclared criterion |
|---|---|
| Engineering pass | Completed review can explicitly report unavailable code or blocked premises; UNASSESSED remains incomplete; source/reading/backend mismatches are rejected; old evidence verifies as history. |
| Live diagnostic pass | Tiny route check returns schema-valid output; both perspectives validate the exact retained scope with all four dimensions assessed, including explicit unavailable outcomes where appropriate. |
| Legal closure | Exact original legal question plus established source, applicability, factual and normative premises and reviewed rivals. No anticipated closure from these changes. |
| Promotion veto | UNAVAILABLE treated as PRESERVES; blocked premise converted into support; dropped pair/reading; stale check attached to a new candidate; inconsistent dimension labels; changed source/question; unsupported answer ranking. |
| Continuation veto | Corrupted evidence, changed unreviewed method, exhausted original budget/window, service sentinel failure for dependent live work, or a journal with uncertain prior dispatch. Independent local verification continues. |
| Repair trigger | Reproducible contract/integration defect. Repair locally before dispatch. No automatic live repair loop in this program. |
| Explanatory only | Latency, request size, tool invocation count, response count, model agreement and retrieval order. |

Expected failures include unavailable executable profiles and unresolved source
premises. They should produce explicit assessed limitations, not a fabricated
legal answer. A timeout rejects that execution; it does not invalidate the legal
approach. No ranking, calibration, general English/case understanding, production
readiness or full live matrix completion is supported by this small diagnostic.

## Implementation and execution

1. **Preserve/trace.** Snapshot current source, tool backend/runner and completed
   results. Retain the complete original gap register; add every newly traced
   integration issue and exact remedy. Record transport event evidence without
   exposing authentication or unrelated session content.
2. **Assessment states.** Add UNAVAILABLE and BLOCKED correspondence outcomes
   with strict preconditions, followups and no executable quotation. Keep them
   unresolved in reconciliation. Record distinct assessed/comparison/unavailable/
   blocked counts; no conversion of historical UNASSESSED answers.
3. **Evidence attachment.** Version optional-tool reports, bind checks to source
   and candidate revisions, forbid backend binding overwrite, verify backend
   identity, and keep historical report replay available. Test stale candidate
   feedback and forged backend bindings. Request caches remain exact.
4. **Local verification.** Regression and adversarial controls; complete mixed
   executable/unformalized controlled workflow with actual installed tools;
   all 420 retained pairs inventoried and capacity computed, without scripted
   labels masquerading as live source judgments. Sequential commands preserve
   logs. Explicitly verify no unsupported reading disappears.
5. **Bounded live diagnostic.** Use at most one tiny schema-valid service call
   charged to product.baseline, then (only if it passes) two perspectives per
   arm on the retained two duty claims and a matched request-trigger candidate
   plus one retained unformalized reading. Four selected pairs; full denominator
   stays 420. Select the unformalized reading deterministically only when its
   already retained typed question has result_kind DUTY_TRIGGER; otherwise retain
   the original two pairs and record unavailable prerequisite. Both arms use
   identical sources/questions/candidates. Stop each arm on failure, never retry
   automatically. No quality ranking follows from the diagnostic.
6. **Results/reset.** Verify source/evidence identity, append-only consumption,
   and all original denominators. Record decisions, limitations, residual gap
   inventory and next evidence. End the program; no automatic extension.
