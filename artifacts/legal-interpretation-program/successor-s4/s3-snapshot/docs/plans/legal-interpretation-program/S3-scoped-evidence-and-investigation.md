## Question and evidence contract

Can recorded events and separately supplied legal premises reach conditional
standards through CompleteInvestigation while retaining their source, scope,
knowledge date, competing attachments, evidence identity and missing premises?
The exact comparator is S2's 14 conditional rules and S1's v2 integration.
This is deterministic engineering, with no stochastic ranking or legal labels.

The primary criterion is correct transport and recomputation on the actual
investigation route, including deliberate source, premise, attachment, identity,
time and receipt faults. Unit tests alone cannot satisfy it. Missing authority,
interpretation, factual classification or full-period coverage veto substantive
promotion but permit qualified computation. Corrupted baseline, lost obligations,
false provenance, invalid checking and unbounded execution veto continuation.
Concrete implementation counterexamples trigger repair; allow two causal repair
attempts per distinct cause before revising this plan. Counts and runtime explain
scope only. Success does not prove English fidelity, legal correctness, actual
client compliance, generalization, complete case treatment or release readiness.

## Interface and implementation decisions

1. Freeze all S2 source/test and driver bytes, its selected pointer, verification
   and original next plan. Later verification distinguishes historical integrity
   from execution of the current method; never rerun S2 with amended dependencies.
2. Introduce explicit `legalmath.semantic-investigation.v3` with a strict context
   envelope containing the unchanged v2 source context and typed standards input.
   v2 rejects the new envelope. Defaults remain opt-in. CompleteInvestigation
   accepts serialized standards input, binds it into its revision and action
   journal, and reconstructs the identical context in both verification routes.
3. Observations derive only fixed, narrow recorded-event predicates. The adapter
   cannot rename a ledger entry into access, acceptance, title or legal adequacy.
   A rule using a recorded predicate still requires a separate authority and
   inference premise. Supplied factual classifications are explicit declarations,
   never automatically extracted from event text. Evidence text is retained and
   its byte hash checked. Original events and rejected evidence remain visible.
4. Admission requires exact actor, provider, product, component, activity and
   jurisdiction, a known knowledge cutoff, event dates no later than that cutoff,
   and validity covering the entire assessment interval. Negative observations
   need a separately declared completeness premise. No retrospective cure follows
   from remediation, and different relationship participants remain different.
5. Attach standards to actual reading/question hashes through explicit proposed
   attachments. Bind the complete v3 context into each branch identity. Preserve
   unattached rules and unassigned branches explicitly; never infer equivalence
   from shared trigger formulas. Keep source-bound rule consequences separate from
   legacy Java Boolean outputs and argument membership.
6. Keep all 14 S2 rules and 46 obligations. Exercise paragraph 14 A/B/C and distinct
   paragraph 15/16 requests with source-informed deterministic challenges. Use an
   offline declared provider and retained SFC excerpts for an actual investigation,
   including serialized standards, exclusions, conflicts and missing premises.
   These responses are development inputs, not model or human quality evidence.
7. Execute affected regressions and independent whole-stage verification. Preserve
   an immutable attempt, run manifest, decision table and red-team note. Refresh S4
   from observed unsupported constructs and theorem/runtime correspondence needs.

Pre-mortem: everything could execute while a proposed legal reading is wrong.
Accordingly, no assertion of substantive correctness follows from deterministic
agreement. A failed event admission is expected candidate evidence, not a broken
research direction. An integrity mismatch is a real continuation veto until repaired.

Audit verdict: PASS_FOR_BOUNDED_IMPLEMENTATION. The original plan's two material
risks are resolved in this design: interval overlap is not full coverage, and S2
method-bound verification cannot be reused after integration changes. The actual
SFC route and full-stage replay answer the engineering question; synthetic behavior
does not act as a proxy for source interpretation. No live providers, network
retrieval, installations or GPU execution are needed.

## Commands and artifacts

Use fixed forms in the project directory:

```
python3 -m scripts.legal_interpretation_s3_prepare
.venv/bin/python -m pytest tests/interpretation/semantics/test_scoped_standards.py -q
python3 -m scripts.run_legal_interpretation_master resume
python3 -m scripts.run_legal_interpretation_master verify
```

The master runs the required affected suite once, then executes and independently
checks the dossier. Its attempt directory is
`artifacts/legal-interpretation-program/successor-s3/attempt-N/`.
The immutable result records actual commands, git commit and dirty baseline,
interpreter, toolchains, source hashes, CPU policy, elapsed time, retained inputs,
checks, limitations and the refreshed S4 plan. A failed attempt is never overwritten.
