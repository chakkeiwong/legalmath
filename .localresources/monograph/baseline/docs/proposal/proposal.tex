\section*{The proposed investment}
\addcontentsline{toc}{section}{The proposed investment}
Private-bank regulatory change repeatedly crosses a difficult boundary: a circular
describes what the institution should do, while software requires exact inputs,
conditions, dates and consequences. Much of the interpretation occurs in documents,
meetings and tickets that are only loosely connected to the eventual code. A small
change to an exception, client category or monitoring event can therefore survive
ordinary testing while changing the treatment of clients.

LegalMath would make that boundary a product. Its central deliverable is a
\emph{reviewable regulatory specification}: the relevant source passages, their
interpretation, typed rules, unresolved questions, examples, and the evidence
supporting execution. Compliance officers review the meaning in ordinary language
and worked cases; engineers implement or integrate the same versioned rules; tests
and formal checks report precisely which properties hold. A flowchart is one view
of this specification, alongside decision tables and event histories.

One complete example makes that proposition testable. The joint SFC--HKMA SPI
circular permits specified streamlining for certain clients and transactions.
A client at the wealth threshold can still fail because of conservative
objectives, an unselected product category, missing agreement or withdrawn
consent. The worked case follows a synthetic client through the circular and
both annexes, the interpretation and evidence record, a typed specification,
distinguishing tests, generated Java and a separate Java host call. It retains
offering documents, requested explanations and relevant warnings instead of
turning streamlining into a general permission to trade.

This proposal recommends a staged prototype centred on the SFC--HKMA sophisticated
professional investor (SPI) circular and its annexes, with separate amendment and
marketing cases. Start with reviewed rules, a small interpreter, deterministic
explanations and independent test scenarios. Add language-model drafting and
counterexample search once that baseline works. The bank's required output is
Java. A deterministic compiler produces source and a JAR from the adopted
specification; Python supports authoring and reference checks. The delivered
narrow demonstration implements exact money, explicit unknown/conflict results,
source-linked rule traces and consent replay. The larger workbench must add
review, the full language and event contracts, data normalization and controlled
release. Formal languages are explained from their basic ingredients before
the literature survey: expressions and types for decisions, exceptions for
qualified rules, and states and events for agreements.
Existing MathDevMCP, DynareMCP and ResearchAssistant components can support proof
evidence, investigative search and source management through narrow adapters.

The initial commercial decision is whether to fund a limited discovery and
prototype exercise.
The exercise should measure review effort, materially wrong conclusions, missed
obligations and amendment handling against the existing manual process. The
proposed schedule is twelve weeks with named compliance participation. Timing and
staffing are planning assumptions; no savings or accuracy result has yet been
measured. The study includes 38 downloaded paper editions representing 37 works,
all seven requested sources, foundational normative logic, and standards and
software documentation. The full implementation contract supplies 35 decision
cases plus negative, event and release scenarios. The separate Java demonstration
executes 32 SPI decision cases and eleven consent histories, compares the complete
results with a reference implementation, and detects three deliberately
introduced rule defects. These checks establish a working path to Java for the
stated subset. They do not establish autonomous legal translation, complete
regulatory coverage or bank production readiness. The prototype plan names the
remaining modules, interfaces and acceptance conditions, including a mandatory
Java backend.
